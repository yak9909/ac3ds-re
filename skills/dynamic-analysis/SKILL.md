# 実機での確認
理由と詳しい手順は [実機での解析の安全手順](../../docs/dynamic-analysis.md) を参照する。

- 実機の操作（Resume・メモリの書き換え・ブレークポイント）は、依頼文か利用者が許可した場合だけ行う。
- 証拠（画像・レジスタ・メモリのダンプ・ログ）は `_local/evidence/<Issue番号>/` に置き、記録には作業場からの相対パスと SHA256 を書く。

## 手順

1. 対象のプロセス・停止状態・PC/SP/LR/CPSR・ブレークポイントを確かめる。既に停止していれば、利用者に停止を頼み直さない。
2. 変える前の画面と、必要な値を保存する。
3. 再開する前に、停止のタイマーを登録する（既定 3000ms、上限 25000ms）。IDA の要求の中で sleep しない。
4. 自動で止まったら、別の呼び出しで停止状態を確かめてから、メモリを読み書きする。
5. 画像は Chokistream の Image Sequence（`Layout = Separate`。下画面のファイル名の綴りは `_bototm`）から取り、鮮度と SHA256 を確かめ、実際に画像を見る。
6. 画面とレジスタ・メモリの2つの経路を照合する。画像1枚だけで停止・クラッシュを断定しない。

## 用語（利用者の定義）

- **SIGSEGV**: CPU の例外で止まった。IDA に「got SIGSEGV signal」のダイアログが出る。
- **フリーズ**: 例外は無く、画面の更新が止まった。全スレッドの PC/LR/SP を並べ、待っている同期の相手を探す。

利用者の報告の言葉どおりに扱い、記録でも混ぜない。

## IDA への要求がタイムアウトしたら

再送や推測より先に、IDA のダイアログ（例外の通知）を確かめる。文面を記録してから閉じ、例外で止まった対象はそのまま再開しない（同じ命令で再び落ちる）。
