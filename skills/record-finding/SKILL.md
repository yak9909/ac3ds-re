# 記録の書き方

- 記録は `python tools/kb.py new --scope <acnl|hhd|3ds> --category <カテゴリ> --title "<題>"` で作る。作られたファイルの本文と、管理項目より上の項目を埋める。
- 1件には1つの結論を書く。別の結論は別の記録にする。
- `summary` は1〜3行。結論だけを書く（経過は書かない）。
- `addresses` は、結論の対象の関数・データの先頭アドレス（16進、`0x` 付き）。
- `tags` は `meta/tags.toml` にある物だけ。足りなければ報告で提案する。
- 既存の記録と違う結論なら、`supersedes` に古い記録の ID を書く。古い記録は書き換えない。

## 本文

- **結論**: 何が分かったか。確度の理由（独立した根拠の数、実測の有無）を1行で添える。
- **根拠**: 判定に必要な物に絞る（目安150行以内）。アドレス・命令・呼び出し元を具体的に書く。疑似C を貼るときは、根拠になる数行だけにする。
- **反証条件・未確認点**: どうなっていたら結論が誤りか。確かめていないこと。
- ファイルのパスは、作業場からの相対パス（`_local/evidence/...`）で書く。PC 固有のパス（ドライブ名・ユーザー名）は書かない。
