# 参考資料の使い方

資料の本体は `_local/refs/` に置く。所在、出所、マニフェストの照合値は `meta/references.toml` で引く。リポジトリにはチートのコード、ID 一覧、解析メモの本文を写さない。

`python tools/refindex.py` で `_local/refs/index/addresses.tsv` に番地候補の索引を作る（配置が違う場合は `--refs-root`・`--output-dir` を指定）。索引はコミットせず、`python tools/kb.py addr <番地>` で資料のキー・ファイル・行番号を引く（既定20件、残りは件数を表示。`--ref-limit` で変更）。
ビルドは台帳の任意の `build` またはパス中のビルドキーで明示でき、それ以外は不明とする。CHEATS は通常書き込み行（幅の指定を除いた番地）、CTRPF・TEXTS は `0x` に続く1〜8桁の番地候補を拾い、いずれも `0x00100000` 以上 `0x40000000` 未満に絞る（範囲内の定数は含む）。IDS の ID 表とバイナリは索引化しない。

## 読み方

- `CHEATS/` のテキストは Gateway 形式のチート。角括弧内はチート名で、先頭の色指定は表示用。通常の「8 桁の値が 2 つ」の行は、仮想アドレスと書き込む値を表す。値が ARM 命令ならコードの書き換えに当たる。`D*` などで始まる Gateway の制御コードはアドレスとして扱わない。`INDEX.md` はアドレスからチートを探す索引だが、制御コードは載せていない。
- CHEATS のアドレスは、本解析の対象と同じ仮想アドレス空間を前提としている。同じビルドなら IDA のアドレスと照合できる。ただし別の地域・版のアドレスをそのまま当てず、対象のコードで対応箇所を探す。
- `IDS/` は ID と観察された挙動の対応を探す手掛かり。ファイルによって 16 進・10 進の表記や文字コードが違い、カテゴリ名や説明も確定した仕様ではない。載っていない ID が存在しないとは言えない。コード中の ID 空間と同じかも、値を使う箇所で確認する。
- `CTRPF PROJECTS/` は先行するプラグイン実装、`TEXTS/` は構造・関数などの解析メモ。いずれも対象ビルドの一次証拠ではない。ソース中の名前や引数名、メモの主張をゲーム内の意味として採用する前に確認する。

## 解析での使い方

1. 調べるアドレスや挙動から、索引、チート、ID 一覧、先行コードを引き、調査する候補を得る。チート名は作者の主観的な説明で、効果の一部や意図しか示さない場合がある。1 つのチートの全行が同じ機能に必要・関連するとも限らない。
2. 候補のアドレスや値を一つずつ IDB の逆アセンブル、参照関係、データの使われ方などの一次証拠で確かめる。資料と独立に得た結論が一致する場合も裏付けの範囲を明示し、食い違う場合は原因を調べる。参考資料だけに依拠する結論は LOW とし、一次証拠による裏取りを経てから MEDIUM 以上を判断する。
3. 記録には `meta/references.toml` のキーと、参照したファイル・箇所を示す。資料の本文は長く引用しない。

この規則は `skills/use-references/SKILL.md` に従う。
