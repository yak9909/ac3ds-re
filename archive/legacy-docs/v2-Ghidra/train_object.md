# 村を通過する電車オブジェクト

## 結論

村で時折通過する電車は、単なる背景アニメーションではなく、`ModuleOutdoor.cro` 内の **`AcStrcTrain` オブジェクト**として扱われていると判断できる。

確度は **MEDIUM**。静的証拠は複数あるが、走行中の実機インスタンスはまだ観測していない。

## クラスとリソース

更新版 `ModuleOutdoor.cro` には以下が存在する。

- `AcStrcTrain::Allocator`
- RTTI `11AcStrcTrain`
- 継承 `AcStrcTrain -> UtlBase<AcStrc> -> AcStrc`
- `Strc/sobj/sobj_train/sobj_train.bcres`
- `Strc/sobj/sobj_train/Textures/%s/%s.bcres`

踏切は別に `AcStrcCrossing` と `sobj_crossing` 系リソースを持つ。

## 位置・移動状態

`AcStrcTrain` 固有処理から以下を確認した。

| this offset | 静的に確認した用途 | 解釈 |
|---|---|---|
| `+0x14` | `+0x40` を加算して毎更新変化。3成分ベクトルの先頭として渡される | 移動軸座標 |
| `+0x18` | `+0x14/+0x1C` と一緒にコピー | 位置ベクトル成分 |
| `+0x1C` | `+0x14/+0x18` と一緒にコピー | 位置ベクトル成分 |
| `+0x40` | 初期化時に進行方向別の符号を設定し、`+0x14` へ加算 | 移動量/速度相当 |
| `+0x360` | `+0x14` に加算して別コンポーネントへ渡す | 車体内オフセット相当（推測） |
| `+0x364` | 上記位置を受ける関連コンポーネント | 詳細未確定 |

更新処理の核心は `this+0x14 = this+0x14 + this+0x40`。別処理では `+0x14/+0x18/+0x1C` を3成分まとめて別ベクトルへ複製する。

したがって、「電車が座標等を持ったオブジェクトか」という問いには **はい** と答えられる。ただし現段階では各成分をX/Y/Zへ割り当てず、ワールド/ローカル座標の区別も保留する。

## 次の確認

実機で走行中に `AcStrcTrain` インスタンスを捕捉し、`+0x14/+0x18/+0x1C/+0x40` を時系列観測すれば軸・座標系・速度単位を確定できる。
