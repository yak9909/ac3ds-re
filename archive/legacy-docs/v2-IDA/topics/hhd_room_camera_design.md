# HHD式室内カメラの移植設計

IDA-gpt-6.1-sol-F014 / T001、2026-10-09。実装前の設計。確度MEDIUM（原ARM命令、RomFSデータ、原命令の部分実行）。実機は未確認。

## 目的と対象

日本語版無印ACNL＋更新で、家の十字キーによる段階操作をHHD v1.1 JPNの通常室内操作へ置換する。左右を押し続けて回転、上下を押し続けて距離と見下ろす角度を連続変更する。壁かけ/壁紙床のF013修正を同じ試験版に含める。

原バイナリSHA、独立6地点のIDB bytes、T=0は `work/evidence/hhd_room_camera/input_checks.json`。ロード範囲は各survey.json。番地は他ビルドへ流用しない。

## 調査結果

| 役割 | ACNL | HHD |
|---|---|---|
| 現在のCameraGame | [0x94A880] | [0x733578] |
| 通常入力 | 0x1A386C→0x68E15C→プレイヤー更新0x64C4A0 | 0x156C0C←0x4F390C←0x4D89D0 |
| 入力 | pressed、yaw 12段階/上下3段階 | held、yaw速度/zoom速度/zoom位置を毎回更新 |
| profile適用 | 0x1A3160 | 0x1549E4 |
| target→現在/eye | 0x1A5124→0x1A15B0 | 独立した同形のCameraGame |
| zoom補間 | profileを選択して遷移 | 0x153218→0x5F942Cで自然3次スプラインを作成 |

ACNL入力はmode0/9/25、Room_HasFlags(0x100)、camera+442の禁止と遷移後半のゲートを持つ。上位callerの状態/メニューのゲートも存在する。HHDの撮影0x1578BCは別操作で今回採用しない。

HHDの通常操作: 左(0x40000)優先−1/右(0x80000)+1、速度への接近は押下0.2/解放0.1。yaw加算は `trunc((velocity*3.0f)*182.044449f)`、u16巡回。下(0x20000)優先でzoom増加/上(0x10000)減少。加速0.2、停止0.0714285746（原word0x3D924925）、13フレームの予測制動に0.04/−0.035を使う。位置は[0,3]、区間の速度係数[0.07,0.06,0.08]。

HHD param.binの4点[3,4,5,37]を使い、yずれ/距離/polar角を補間する。4点の距離は[220,330,500,500]、角u16は[5097,6371,10922,1820]。Hornerの各乗算で角をs32切捨てする。係数生成の全命令と通常入力493フレームをARM1176で実行し `hhd_curve.json` / `hhd_native_frames.json` に保存。整数角の演算をfloatだけの補間へ変更しない。HHDの初期zoom位置1.0も使用する。

## 実装の構成

1. gohanにチェック項目「家のカメラをHHD式に」を追加、ON/OFFを既存効果登録へ接続。基点be72724から作業枝 `work/hhd-room-camera`。mainへ入れない。実装時に現行字形へ合わせた表記。
2. CTRPF MITMでACNL入力0x1A386CとApplyTarget 0x1A5124を接続。前者は家でnativeが許可する状態だけHHDのheld操作を実行し、元の段階操作を置換。家の判定はroom flagsの屋内8＋camera可0x100＋プレイヤー家0x80/NPC家0x40。外観番号を読まない。その他の場所/状態は元関数へ渡す。
3. ApplyTargetの前にカメラprofileだけを0x1A3160へ渡す。元ApplyTargetを実行して基準位置の追従・部屋範囲・遷移を保ち、その後、現在のoffset/polar/yaw/distanceを今回profileへ写す。元のS0補間戻り値をfloatで返す（gohanはAAPCS-VFP）。eye作成/壁透過はnativeがその後に行う。
4. mode0と模様替えmode25で適用。会話/入退室等の特殊modeは元処理、速度は止める。入力はゲームControllerのhold+0x110とnative入力禁止を使い、上位callerのゲートを保つ。gohanメニューを開いている間も停止。入力callbackが呼ばれないフレームは速度を持ち越さない。
5. ゲーム側状態はゲームスレッドだけで更新。カメラ/部屋/sceneの変化で初期化、yawは現在角から開始。ON/OFFは要求と世代番号のみをメニュー側から渡す。OFFはnativeの元yaw/vertical indexからprofileを再構成し、次の安全なApplyTargetで戻す。未使用の家/古いobjectへ書かない。
6. hooksはOFF時も元関数へ通す。外部変更を元bytes検査で検出して導入を止め、失敗した途中hookは解除。新規caveやゲームheapは使わず、私有状態と係数表はプラグイン内。屋外FieldCameraと同じApplyTargetの2語目を変更しない。

## 検証と反証条件

- 移植したC++制御の全frameを原HHD ARM実行結果へ照合。長押し、離した後、逆方向、左右/上下同時、両端、角の周回、3次補間の整数角を含める。
- ACNL原関数/フックのABI（R4–R11、SP、D8–D15、S0）、分岐/リテラル/コード定数境界、適用領域/既存hook重複、6地点原命令、TitleIDを確認。屋外/他室内/会話/メニュー/room変更/OFFで元経路を確認。
- ソース検査→指定ビルド→リンク後検査→hash/成果物保存→作業枝push。各変更DBへ全確定概念を反映しXML/bytesを検証して親Git保存。
- 実機では最小左右操作から、上下の奥行き、歩行追従、壁透過、通常↔模様替え、会話/持ち物/入退室、OFF、外観改造の普通の室内を確認。F013の壁かけ/壁紙/床も同版で確認する。
- 原HHDとの差、追従のずれ、演出上書き、家具リスト中の入力競合、OFF後に段階操作へ戻らない、他室内/屋外の変化があれば反証。エミュレーションを実機HIGHへ昇格しない。
