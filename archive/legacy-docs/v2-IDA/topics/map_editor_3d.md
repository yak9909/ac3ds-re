# マップエディターの上画面（カーソル・赤いハイライト・移動の複製）/ IDA-opus-5.5-D004

2026-09-27、IDA / opus-5.5。利用者の追加仕様（同日）:
タッチしたマスに青い UnitCursor、タッチした・範囲選択中のアイテムのモデルを赤く、移動中は元を残したまま複製を移動先に
白っぽく半透明で少し浮かせて出す（元の赤は戻す）、大きな範囲でも掴める（画面外は描かない・使い回す）。
**任意モデルの表示・色合成は公共事業エディター（BuildingPreview / BuildingHighlight）で実機済み**なので、それを流用する。

## 1. 使う事実（静的。根拠は FINDINGS IDA-opus-5.5-F055）

- 村のアイテムの実体 = `fgobj::ObjectBase`。`fgobj::Proc`（`*0x948E70`、屋外は `byte_948E5F`）+13732 から連結（次 = +8）。
  +40/+44 = マス、+100 = アイテム、+88 = インスタンスのホルダ（ノード = +92）。辿り方は `fgobj_DestroyObjectsAt 0x5A1A90` と同じ。
- 実体のモデルは `sub_58EEC0` → `ModelInstance_Create(obj+88, res, obj+32, obj+32, 0, …)`。一般のアイテムは bufferOption 0 → 材質の部分（M+48 色 / M+72 TEV / M+80 フラグメント）は資源と共有。
- 材質の写し `0x4ADD44(out, M, allocator, mask)`: M+8（資源の ResMaterial）から 728 B を写し、鍵は 0。mask の 0x780 のどれかで TEV 244 B も写す（+40 の参照表の相対ポインタは 0 にされる → 付け直す）。
- モデルの引き方（`sub_58FB40`）: 埋まっている → fg_crack_*、ID 158 → fg_hole_*、fgobj（≤0xFD）→ FieldObjDef +12 → 表 `*(proc+0x414)` + 22×n の +5 の名前 → `FindModel(proc+52)`、
  0x2000〜0x372A → ItemParam +11（特例 8/9）→ `sub_5350C0` の名前 → `FindModel(proc+0x13C)`、`(ID & 0x6000) == 0x4000` → fg_wrapping(_out)。

## 2. 設計

| 部品 | 中身 |
|---|---|
| カーソル（段階 A） | 既存 GridCursor。青（BuildingHighlight::kBlue・強さ 0xB0）。指が盤面に触れている間は触ったマス 1 つ、持ち上げ中は行き先のうち盤面の周り 1 マスまで（最大 64） |
| 上限（段階 A） | 持ち上げの数 64 → 2048。下画面のコマ・上画面のカーソル・複製は盤面の周りだけ作る |
| 赤（段階 B） | **2026-09-28 に作り替え（F058）**: 体を作らない。村の物体の描画関数の表 `off_948F90`（2 語）を包み、選んだマスの物体だけ材質を結んだ直後に TEV 段 5 へ赤を積む（ゲームのフェード `sub_58F0D0` と同じ組み立て関数）。描いたあとは 0x800 の物体と同じ手順でキャッシュを捨てる → 同じモデルのほかの物体に漏れず、ヒープも要らない。範囲を引いている途中も吸着した四角を赤くする。~~F056 の自前の体を 1.04 倍で重ねる方式~~・~~最初の実体の材質を書き換える方式~~ |
| 複製（段階 C） | 移動先が盤面の周りにある物だけ、アイテムの資源（村の季節資源。借りる）から `ModelInstanceCreate(…, 0x834, 1, 3)`。体は使い回す（同じ資源なら組み直さない）。材質は白を混ぜ、定数アルファで半透明、層 1。少し上げる |
| 片付け | 場面（`*0x948E70` とその +0x34）が変わったら何も呼ばずに描くのをやめ、ヒープごと返す（借りた資源は既に無いかもしれない）。エディターを止めたら元へ戻してからヒープを返す |
| 壊す前（F057） | **自前の体を壊す前に、写しの材質 +648（自前の TEV）を 0 に戻して TEV を返す**。ゲームの後片付けは写しの +648 → TEV +40 の表 → 参照を +12 = 0 にして解放する。表は元の季節資源の物なので、戻さずに壊すと元のモデルの LUT 参照が外れて落ちた（実機 3 回）。共通の規則は [gfx_model_lifecycle.md](gfx_model_lifecycle.md) |

## 3. 第 2 段: 体 1 つを N か所に描く（2026-09-28 実装 gohan 4fb9e33、実機未確認。根拠 F059）

いまはカーソル 1 個・複製 1 個に体 1 つ（6 KB 前後）を作るので、ヒープが数に比例して上限に当たる（F058: 親ヒープの空きは約 480 KB）。
村の物体は **1 つの体を行列だけ変えて何度も描いている**（`sub_59A918` → `sub_58F984` で体 +444 を書き、メッシュを直接描く）。同じ作法を自前で使う。

| 部品 | 中身 |
|---|---|
| 描画ノード | `g3d_FuncNode_Create 0x4EFFB4` を 1 個（旧 F-119 / F-120 で実機済み。340 B）。毎フレーム `Scene_SubmitNode` で出す |
| 体 | モデルの種類ごとに 1 つ（カーソルは UnitCursor 1 つ。向きが要るなら向きの数だけ）。材質アニメは体ごとに 1 回だけ進める |
| コールバック | 置く所ごとに体の行列を書き → `sub_58F984` 相当で +444 → メッシュごとに `sub_48D26C`。前後で `sub_4EF898(0x1FFF)` |
| ヒープ | モデルの種類数 × 1 体だけ。置く数（2048 まで）に依らない |
| 確かめること | コールバックの層（cb0 / cb1。加算合成のカーソルは半透明側か）、視点行列 `sub_711A8C(&unk_ABD380, 1024)` がこの時点で正しいか、体を描画リストへ出さないときの世界行列の更新 |
