# とびだせ どうぶつの森 (Animal Crossing: New Leaf) 解析

3DS 実機を Luma3DS の GDB スタブ経由で IDA Pro からデバッグして得た解析結果。
アドレスはすべて**実行時仮想アドレス**。`.code` のファイルオフセットは `仮想アドレス - 0x100000`。

## どこから読むか

| 目的 | ファイル |
|---|---|
| 解析の進め方・ルール | `CLAUDE.md` |
| 今どこまで進んでいるか | `RE/STATE.md` |
| 何が確定していて根拠は何か | `RE/FINDINGS.md` |
| 次に何を調べるか | `RE/TODO.md` |
| 関数の一覧と確度 | `RE/FUNCTIONS.md` |
| データ構造・テーブル定義 | `DOCS/structures.md` |
| 改造パッチと復元値 | `DOCS/patches.md` |
| スコップの速度アドレス | `DOCS/shovel_speed.md` |
| 先行情報（チートコード・ID 一覧）の扱い | `REFERENCES/README.md` |
| アドレスから既存チートを逆引き | `REFERENCES/CHEATS/INDEX.md` |

`NCCH/` は展開済み NCCH（`exefs/` `romfs/`）。
**現在置かれているダンプは別ゲーム（マリオカート7）** なので romfs は参照できない。

## 到達点

- スコップの各動作アニメの再生速度アドレスを全特定
- 岩・アイテム・木・低木・構造物・段差すべてで穴を掘れるパッチを確立（実機確認済み）
- 3x3 掘りはコードケーブまで実装したがクラッシュ。未解決

ゲームの同定根拠は `RE/FINDINGS.md` の F-01。

## 次にやること

`RE/TODO.md` を参照。最優先は **TODO-00: `0x598688` の 3x3 フックを外す**
（設置されたままだとクラッシュする）。

## 再開時に必要なこと

- IDB は接続のたびに破棄されるので、`ida_restore.py` を実行して復元する。
- メモリパッチもゲーム再起動で消えるので、`apply_patches.py` で再適用する。
- `acnl_gdb.i64` は当時のスナップショットだが逆アセンブルを含まないため、
  単体で開いてもコードは読めない。実用上は `ida_restore.py` の方が確実。
