# ゲーム側の入力を塞ぐ（自前メニューの暴発防止）

確定した知見。根拠は `RE/FINDINGS.md` F-350〜F-355、解析メモは
`scratchpad/MEMO_f350_input_block.md`、生成元は **`PATCHES/input_block_cave.py`**（正本）。

**実機で全項目確認済み**（デバッガ版ケーブ）。**SELECT/START の効き分けは 3gx でも確認済み**。

---

## 1. 仕様（利用者の要求そのもの）

| 対象 | 挙動 |
|---|---|
| スライドパッド | **常に許可**（メニューを開いていても移動できる） |
| SELECT | **常に不可**（自前メニューを開いていなくても） |
| START | **通常どおり効く**（メニューを開いている間だけ他ボタンと一緒に遮断） |
| その他のボタン | **自前メニューを開いている間だけ不可** |
| タッチパネル | **下画面ロック中だけ不可** |

下画面ロック中は**半透明の黒パネルを下画面全体に置く**（登場・退場フェードつき、色と時間は引数）。
キーボードやリストボックスが自前で背景を描くのはやめ、**ロックの ON/OFF に一本化**した。

★**プラグイン自身の入力は影響を受けない。** CTRPF の `Controller` は HID を直接読むので、
ゲームの sead 側を塞いでも自前メニューの操作とタッチは生きる。

## 2. どこで塞ぐか

### 2.1 sead の入力（ボタン・タッチ）

| | |
|---|---|
| 物理入力 | **`sead::CtrController`**（vtable `0x008FE6F8`）。ボタン 28 個 |
| ゲームが読む側 | **`sead::ControllerWrapper`**（vtable `0x008FF31C`）。ボタン 19 個 |

`ControllerWrapper::calc`（`0x005475D4`）は**元の `CtrController` から全部写す**ので、
**元を 1 個塞げばゲーム側は全部塞がる**。

`sead::Controller::calc`（`0x0053CDC4`）を使うのは `CtrController` だけ。その中の

```
0053CDE4  BLX  R1              ; 生読み（sub_540870）。+0x110 / +0x10 / +0x114 が更新される
0053CDF0  MOV  R0,R4
0053CDF4  BL   sub_542E88      ← ★ここ 1 語を差し替える（edge 計算の直前）
```

**「生読みの直後・edge 計算の直前」**なので、ここで hold を削れば
**trig / release / repeat も削った値から計算される**（幻の押下・離しが出ない）。

### 2.2 ★SELECT は「START への読み替え」の手前で消す（F-355）

**ゲームは SELECT を START に読み替えている。** だから sead 層では区別できない。

```
sub_483020:
    if (*a1 & 4) *a1 = (*a1 & ~0xC) | 8;   ; SELECT(bit2) -> START(bit3)
    *(a1+4) &= ~4;  *(a1+8) &= ~4;          ; trig / release からも bit2 を消す
```

呼び元は `sub_3533D0`（パッドを読む）の末尾:

```
003534DC  MOVEQ R0,R4          ; R4 = パッド構造体（+0 hold / +4 trig / +8 release）
003534E0  BLEQ  sub_483020     ← ★ここを差し替える。条件 EQ を保つこと
```

**この手前で bit2 だけを落とせば、SELECT だけ消えて START は残る。**

★CTRPF のフラグを見て弾く案は**却下**（CTRPF の処理は最後なので、
メニューを開く 1 フレームだけ SELECT が通ってしまう）。

## 3. ビット対応（`sub_540870` = 生読み から起こした）

3DS の生 HID ビット → sead の hold ビット:

| HID | ボタン | sead |
|---|---|---|
| bit0 | A | `0x00000001` |
| bit1 | B | `0x00000002` |
| bit2 | SELECT | `0x00000800`（★実測。libctru の並びと違う） |
| bit3 | START | `0x00001000`（推定・未実測） |
| bit4 | 十字右 | `0x00080000` |
| bit5 | 十字左 | `0x00040000` |
| bit6 | 十字上 | `0x00010000` |
| bit7 | 十字下 | `0x00020000` |
| bit8 | R | `0x00004000` |
| bit9 | L | `0x00002000` |
| bit10 | X | `0x00000008` |
| bit11 | Y | `0x00000010` |
| bit12 | ZL | `0x00000080` |
| bit28〜31 | **スライドパッド 右左上下** | **`0x00F00000`**（bit20〜23） |

★スライドパッドのアナログ値は別に `+0x11C` / `+0x120` に入るので、
ビットを残せば移動は完全に生きる。

### `sead::ControllerBase` の欄

| off | 意味 |
|---|---|
| `+0x04` / `+0x08` / `+0x0C` | trig / release / repeat |
| **`+0x10`** | タッチの旗。bit0 タッチ中 / bit1 押した瞬間 / bit2 離した瞬間 |
| `+0x14` `+0x18` | ポインタ座標 int |
| `+0x2C + 4i` | **ボタンごとの押し続けフレーム数**（★計測はこれを読むとタイミングに依存しない） |
| `+0xFC` | ボタン数（CtrController 28 / Wrapper 19） |
| `+0x100` `+0x104` | スティックのビット開始位置（どちらも -1 = 未使用） |
| **`+0x108`** | **タッチが使うビット番号**（実機は 15） |
| **`+0x110`** | **hold** |
| `+0x114` `+0x118` | ポインタ座標 float |
| **`+0x11C` `+0x120`** | **スライドパッドのアナログ X / Y** |

## 4. ケーブ 2 本（`PATCHES/input_block_cave.py` が正本）

| | フック | 素の語 | 置き場 | 語数 | 役割 |
|---|---|---|---|---|---|
| **A** | `0x0053CDF4` | `0xEB001823` | `0x00838020` | **27** | ボタン一括遮断 + タッチ遮断 |
| **B** | `0x003534E0` | `0x0B04BECE` | `0x008380A0` | **15** | SELECT を読み替えの手前で消す |

制御ブロック **`0x009B7010`**: `+0` ボタン遮断 / `+1` タッチ遮断 / `+2` SELECT 遮断（導入時 1）。

### ケーブ A の中身

```
  R3 = CTL
  LDRB R12,[R3,#1]          ; タッチ遮断の旗
  CMP  R12,#0
  BEQ  skip_tp
    LDR  R12,[R0,#0x10] ; BIC #1 ; STR       ← タッチ中フラグ
    LDR  R1,[R0,#0x108] ; R12 = 1 << R1
    LDR  R2,[R0,#0x110] ; BIC R2,R2,R12 ; STR ← ★hold の中のタッチビット
skip_tp:
  LDRB R12,[R3,#0]          ; ボタン遮断の旗
  CMP  R12,#0
  BEQ  skip_btn
    LDR  R12,[R0,#0x110] ; AND R12,R12,#KEEP ; STR
skip_btn:
  B    sub_542E88           ; 末尾ジャンプ（LR はそのまま = 0x53CDF8 へ戻る）
```

★**落とすのは「既知のボタン」だけ**（`BUTTONS = 0x000F789B` / `KEEP = 0xFFF08764`）。
`AND #0x00F00000`（スライドパッドだけ残す）と書くと**タッチのビットまで消える**（F-352）。

★タッチは **2 か所**にある。`+0x10` の旗だけ消しても
`+0x110` の中のビット（番号は `+0x108`）が残り、**左上に幻のタッチが出る**（F-354）。

### ケーブ B の中身

```
  LDRB R12,[R3,#2]          ; SELECT 遮断の旗（導入時 1 = 常時）
  CMP  R12,#0
  BEQ  skip
    LDR/BIC #4/STR を [R0]（hold）/[R0,#4]（trig）/[R0,#8]（release）に 3 回
skip:
  B    sub_483020           ; 読み替え本体へ
```

フック語は **`BLEQ`（条件 EQ）のまま**にすること（`0x0B1392EE`）。無条件 `BL` にすると壊れる。

### ★即値は手で書かない

`BIC R12,R12,#0x800` を手で `0xE3CCCC02` と書いて **`#0x200` になっていた**。
`input_block_cave.py` の **`enc_imm()`** が正本。objdump が捕まえた。

## 6. 検査

`python PATCHES/verify_plugin_port_v2.py` の**群 4** が見る（約 14 検査）:

- ケーブ語が生成元と 1 語ずつ一致するか
- フック語が正しいか / **B のフックが `BLEQ` のままか**
- `BIC #4` が 3 つあるか（hold / trig / release）
- ケーブ A に SELECT 固有の `BIC` が残っていないか
- ケーブ A と B が重ならないか
- `KEEP` マスクの性質（スライドパッドとタッチのビットを消していないか）
- 暗幕を描く場所が 1 か所か / ボタン遮断が `g_visible` に結びついているか

★**ケーブの逆アセンブル検証に idalib は使えない**（静的 IDB の segment は
`0x00838020` より手前で終わる）。**objdump** と、実機へ書いてから輪へ繋ぐ前の
**ida-pro-mcp での実バイト逆アセンブル**を使う。

## 7. `0x32C85A2D` について（利用者が手がかりとして渡した番地）

**`ButtonActionNodeEx[0] + 0xD9`**（配列の先頭 `0x32C85954` / 刻み `0x184` / この場面で 11 個）。
`sub_2E08F8` から「**この Button Action が結び付いている（有効）か**」の旗と確定。
0 にするとその操作が発火しない（X で持ち物が開かなくなる、という利用者の観測と一致）。

★**これでは全ボタンの無効化にはならない。** 覆うのは UI に登録された Button Action だけで、
移動・カメラ・当たり判定は別経路。個数と並びも場面で変わるので固定番地では潰せない。
**だから sead 層で塞ぐ方式（本文書）を採った。**
