## 結論

フィールドの魚・海中生物管理は、候補 ID `0x6A` を特殊乱数分岐で直接指定する生成経路を二つ持つ。各経路は通常抽選表からの候補選択も持ち、`0x6B` 以上を採用しない。ID `0x6A` は、同じ管理処理内で読み込まれる `JellyfishResource` および `Fish/fsh_kurage.bcres` から、クラゲの生成候補と判断した。

確度 MEDIUM。Ghidra で確認した独立した二つの出現経路（`0x0025337C` と `0x00255374`）が同じ ID `0x6A` を指定し、別経路のクラゲ専用リソース読込と対応する。実機での確証はない。

## 根拠

- Ghidra の対象は日本版 v1.5 `code.bin`。仮想ベース `0x00100000`、ARM:LE:32:v6。`exheader.bin` に従い `.text = 0x00100000–0x00838FFF`、`.rodata = 0x00839000–0x0093EFFF`、`.data = 0x0093F000–0x0097CFFF`、`.bss = 0x0097D000–0x00AF2F2B` とした。
- `0x00255374` の初期化状態では、`0x002554EC: ADR R0, 0x002557FC` により文字列 `JellyfishResource` を取得し、`0x0025550C: BL 0x0031785C` でリソースを登録する。続く `0x00255518: BL 0x002522A8` では、`0x00252380: LDR R0, [0x002523E8]` から `0x00846C04` の文字列 `Fish/fsh_kurage.bcres` が使用される。`0x00255628: BL 0x00254724` は、`0x00254734: LDR R0, [0x0025489C]` から `mJellyfish.mAlloc` を参照する。
- `0x0025337C` の周期的な候補生成では、`0x00253470–0x0025347C` の乱数値を `0x28` と比較し、`0x00253480: MOVCC R5, #0x6A` と `0x00253484: BCC 0x002534B8` で通常抽選を迂回する。通常抽選では `0x00253488: BL 0x00615628` の表を引き、`0x002534B0: CMP R5, #0x6B`、`0x002534B4: BCS 0x002534F8` で候補を絞る。採用時は `0x002534DC: BL 0x00254B20` に候補 ID を渡す。
- 別の初期化段階の生成経路 `0x00255374` では、`0x002558E4–0x002558F0` で乱数値を `0x28` と比較し、`0x002558F4: MOVCC R1, #0x6A`、`0x002558F8: BCC 0x0025592C` により直接候補を選ぶ。通常抽選は `0x00255900: BL 0x00615628` から取得し、`0x00255924: CMP R1, #0x6B`、`0x00255928: BCS 0x00255938` で選別する。採用時の `0x00255934: BL 0x00254B20` は上記の周期経路と共通。
- 別途 `0x00252B74` にも通常抽選 `0x0061519C` と `0x00252C44: CMP R4, #0x6B`、`0x00252C48: BCS 0x00252D10` があり、採用した候補 ID は `0x00252D0C: BL 0x00254428` に渡す。こちらには `0x6A` を直接指定する特殊分岐は見つからず、特殊候補は `0x4B`。
