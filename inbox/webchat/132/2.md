## 結論

Ghidra で確認した通常抽選用の静的テーブルでは、各4バイトエントリの種別 ID（先頭バイト）に `0x6A` はない。通常抽選を介さない直接指定の2か所（`0x00253480` と `0x002558F4`）では、いずれも `0x6A` を明示的に設定して生成へ渡す。

確度 MEDIUM。二つの独立した抽選関数 `0x0061519C` と `0x00615628` のテーブル参照・読み取り形式を Ghidra の逆アセンブルで照合し、それぞれの参照先の実データに `0x6A` がないことを Ghidra のメモリ読取りで確認した。実機での測定はない。

## 根拠

- `0x00252B74` は `0x00252C20: BL 0x0061519C` から候補を選び、`0x00252C40: LDRB R4, [R4]` で種別 ID を取得し、`0x00252C44: CMP R4, #0x6B` で上限を判定して `0x00252D0C: BL 0x00254428` へ渡す。
- `0x0025337C` と `0x00255374` の抽選経路は、`0x0025348C` および `0x00255900` から `0x00615628` を呼び、4バイトずつの候補テーブルの先頭バイトを種別 ID として取得する。通常抽選の上限は `0x002534B0` および `0x00255924` で `0x6B`。
- `0x0061519C` は条件に応じて `0x0085A204`、`0x0085B26C`、`0x0085D09C` を基準に、日付・場所等のインデックスから4バイトエントリの候補表を返す。
- `0x00615628` は条件に応じて `0x0085C22C` および `0x0085E53C` を基準に、同様の候補表を返す。
- Ghidra で `0x0085A204–0x0085F53C` を4バイト境界に沿って確認すると、エントリの先頭バイトが `0x6A` の箇所は **0件**。この範囲には `0x6B` の番兵エントリが存在する（`0x0085B2A4`、`0x0085C27C`、`0x0085D0E8` など）。
- 一方 `0x00253480: MOVCC R5, #0x6A` → `0x00253484: BCC 0x002534B8` と `0x002558F4: MOVCC R1, #0x6A` → `0x002558F8: BCC 0x0025592C` は、通常抽選を経由せずに同じ ID を選択する。
- この二つの出現経路は `0x002534DC`／`0x00255934` からいずれも `0x00254B20` を直接呼び、種類 ID は R1 で渡す。`0x00254B20` の `0x00254CCC: STRB R7, [R6,#0x3F8]` は汎用生成スロットへの種類 ID の保存であり、クラゲ専用関数とは断定できない。
