## 結論

`0x0025337C` 内では、直指定候補 `0x6A` を選んだ場合、レジスタ R5 に入っていた通常抽選の入力データへのポインタが ID `0x6A` に上書きされる。通常分岐 `0x00253488` へ落ちると、その R5 がポインタとして関数 `0x00615628` に渡り、ポインタ参照が壊れる。したがって、`0x00253484` の条件分岐を単純に無効化して通常抽選へ移すのは正しくない。

確度 MEDIUM。Ghidra で、独立した呼び出し元のレジスタ代入と呼び出し先のポインタ逆参照を命令レベルで確認した。実機での例外は未確認。

## 根拠

- `0x00253434: BL 0x002FB3A4`、`0x00253438: CPY R5,R0`: 通常抽選の入力ポインタを R5 に保持。
- `0x0025347C: CMP R0,#0x28`、`0x00253480: MOVCC R5,#0x6A`、`0x00253484: BCC 0x002534B8`: 直指定が選ばれた場合 R5 を種類 ID に変更し、通常抽選を飛び越す。
- `0x00253488: CPY R0,R5`、`0x0025348C: BL 0x00615628`: 通常抽選では R5 をポインタ引数として渡す。
- `0x0061562C: CPY R4,R0`、`0x00615658: LDRSB R0,[R4,#0x7]`: 通常抽選の参照先は R0 を実際にポインタとして使用する。R5 を `0x6A` にしたまま分岐を除去すると、低位の非正規アドレスを参照する。
- もう一つの直指定経路 `0x002558F4: MOVCC R1,#0x6A`、`0x002558F8: BCC 0x0025592C` は、通常経路の入力を R4 に保持しているため、同じレジスタ破損構造ではない。
