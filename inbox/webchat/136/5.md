## 結論

日本版 v1.5 の本体 `0x007CE420` は、開始セル・目標セルを受けて**最大8方向を展開するA*型の経路探索**を行う。隣接セルにはコールバックで移動コストと推定コストを与え、`累積コスト+推定コスト` の昇順に未探索候補を整列する。探索ノードは親ノードを記憶し、目標に到達すると親をたどって経路を復元する。

本体関数の戻り値は、開始・目標が探索範囲外なら `1`、候補が尽きれば `0`、目標到達なら `2`。成功時は経路の先頭ノードを探索文脈の `+0x20` に格納する。

ModuleOutdoor.cro の屋外住民の経路生成 `0x00B3E100`、`0x00B3E62C` は、ともにインポート中継 `0x00B01B00` を呼び、その参照先が本体 `0x007CE420` である。CRO の実行時ロード番地は未確定だが、CRO/CRS の再配置で関数の対応を確認した。

**確度 MEDIUM**。Ghidra で本体の経路探索・8近傍列挙・優先リスト操作を別関数として解析し、独立したCRO側の2呼出元とインポートの対応を静的照合した。実機未測定。

## 根拠

- Ghidra が復元した `0x007CE420` の範囲は `0x007CE420..0x007CE6F3`。冒頭は2座標の範囲判定。違反時は `0x007CE530 MOV r0,#1` から復帰。
- `0x007CE4B8 BL 0x007CECD4` は探索中のセル・候補リストを初期化し、`0x007CE51C BL 0x007CEA10` が開始ノードを未探索候補へ登録する。
- `0x007CE544..0x007CE55C` は未探索候補の先頭を取り出す。候補が空なら `0x007CE6EC MOV r0,#0`。目標に一致すれば `0x007CE57C..0x007CE594` で親ノード `+0xC` をたどり、`0x007CE598 MOV r0,#2`、`0x007CE59C STR r9,[r8,#0x20]` で成功結果を保存する。
- `0x007CE5B0 BL 0x007CE85C` は隣接セル取得。`0x007CE6B8 CMP r5,#8` まで方向値を増やす。`0x007CE85C` は方向0〜3を上下左右、4〜7を斜め4方向とし、ノードの方向許可ビットを検査する。
- `0x007CE5D4 BLX r3`（コールバック0）が移動コストを与え、`0x007CE600/604` が親と累積値を更新。`0x007CE61C BLX r3`（コールバック1）の値を加算してノード `+8` に格納する。更新済み候補は `0x007CE6AC BL 0x007CEA10` から再挿入する。
- 独立の `0x007CEA10` はノード `+8` のfloat値を比較し、次ポインタ `+0x10` で昇順連結リストを組む。`0x007CECD4` はノード状態と親・次ポインタを初期化する。
- ModuleOutdoor.cro は `0x00B3E244` と `0x00B3E810` から `BL 0x00B01B00`。本体への対応はGhidraスクリプトでCROの anonymous import 225 と import patch（ファイル `0x0A4210`、出力 segment0 offset `0x1B04`、ABS32）を解き、参照先 segment0 offset `0x6CE420` を static.crs の `.text` 基準 `0x00100000` に加えて `0x007CE420` と確認した。
- 住民側の `0x00B3E100` は探索結果 `2` を成功として扱い、結果ノードを住民実体 `+0x2CDC` の経路領域へ取り込む。`0x00B3E62C` も同じ `2` を成功と判定し、次ノードを取り出して移動要求につなぐ。
- 上のCRO便宜番地 `0x00Bxxxxx` はCROの先頭セグメントを `0x00B00000` に置いた解析座標で、実機のロード番地ではない。

## 反証条件・未確認点

- 探索コールバックの詳細な障害物・地形コスト、コストの具体的な重み、経路が再計算される全条件は未解明。
- `0x007CE420` は汎用グリッド探索関数であり、住民以外の呼出元もあり得る。住民専用関数という名称にはしない。
- 8方向すべてが常に通れるわけではなく、ノードの方向許可ビットとコールバック条件で制約される。
- 実機で経路や戻り値を測定していないため HIGH にはしない。
