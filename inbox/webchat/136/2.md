## 結論

ModuleOutdoor.cro で、屋外住民実体の **+0x2CDC** にある経路管理領域（以下 `p`）は、`p+0x1978` の非ゼロ/ゼロで2つの保存形式を使い分ける。

- `p+0x1978 == 0`: `p+4` に座標配列の先頭、`p+8` に未消費部分の終端を保持し、16-bit 単位で**終端側から取り出す**。座標を1つ取るたびに終端を2バイト戻す。
- `p+0x1978 != 0`: `p+0x94` のノードポインタから次の座標の下位2バイトを取り出し、ノードの `+0x10` を次ノードとして `p+0x94` に格納する。取得した座標の2バイトは `p+0x1958/+0x1959` にも保存する。
- `0x00B3F3E8` は双方の形式について残存経路の有無を判定する。非ゼロを返すのが「取り出せる次要素がない」場合。ノード形式では `p+0x94` と `p+0xC34` の両方が空のときだけ経路終了となる。
- `0x00B3E9D0` は次の16-bit座標を進めず参照し、ノード形式で現在のノードがなくキャッシュ値が一致しなければ経路要求用のインポート中継 `0x00B01B30` を呼ぶ。

実体への接続は、別の `0x00B6FA60` が `*(control+0x1960)+0x2CDC` を `0x00B3F3E8`、`0x00B3EC88` に渡すことから確認した。

**確度 MEDIUM**: Ghidra の独立した命令列・逆コンパイルで、経路終了判定・取得・先読みの各関数のデータ操作を相互照合し、さらに別の呼び出し元で住民実体との関係を検証した。実機観測はない。

## 根拠

以下の `0x00Bxxxxx` は ModuleOutdoor.cro の `.text` 先頭を `0x00B00000` に置いた便宜番地であり、実行時のロード先ではない。

1. `0x00B3F3E8` (`FUN_00b3f3e8`, Ghidra 関数体72バイト):
   - `B3F3E8 LDR r1,[0xB3F430]` でフラグの相対オフセット `0x1978` を読む。
   - `B3F3F8 LDR r1,[r0,#0x94]`、`B3F400 LDREQ r0,[r0,#0xC34]` はノード形式の残存判定。
   - `B3F410 LDRD r0,r1,[r0,#4]` → `B3F414 SUB r0,r1,r0` → `B3F418 MOVS r0,r0,ASR #1` は配列形式の要素数検査。空は `B3F428 MOV r0,#1`、非空は `B3F420 MOV r0,#0`。
2. `0x00B3EC88` (`FUN_00b3ec88`, Ghidra 関数体156バイト):
   - `B3EC88` のリテラル `[B3ED24]=0x1978` で形式を選ぶ。
   - ノード: `B3ECAC LDR r0,[r0,#0x94]`; `B3ECB4 LDRNE r2,[r0,#0x10]`; `B3ECB8 STRNE r2,[r1,#0x20]`（`r1=p+0x74`、つまり `p+0x94`）。`B3ECC4/B3ECC8` で座標2バイトを読み、`B3ECD8/B3ECDC` で `p+0x1958/+0x1959` に保存する。
   - 配列: `B3ECF4 ADD r1,r0,#4`; `B3ECF8 LDMIA r1,{r1,r2}`; `B3ED04 SUB r3,r3,#2`; `B3ED10 LDRH r1,[r1]`; `B3ED14 STR r2,[r0,#8]`。
3. `0x00B3E9D0` (`FUN_00b3e9d0`): 配列側 `B3EAAC..B3EAC0` は末尾の16-bit要素を参照するだけで `p+8` を減らさない。ノード側 `B3EA38..B3EA84` はキャッシュ条件に応じて `BL 0x00B01B30`、`B3EA88..B3EAA4` は現在ノードの16-bit座標を返す。
4. `0x00B6FA60`: `B6FA84` で `control+0x1960` から実体ポインタを読む。`B6FA88/B6FA90` は実体 +`0x2CDC` を計算する。`B6FB0C BL 0x00B3F3E8` の直後、経路が残ると `B6FB20 BL 0x00B3EC88` に進み、`B6FB24..B6FB2C` で得た16-bit値を2つの8-bit成分に分ける。

## 反証条件・未確認点

- 16-bitの2成分が村内のどの座標系に対応するか、A*探索で経路がどう生成されるか、経路の再計算先は未同定。これらを確定するには CRO のインポート再配置と探索呼出しを追う必要がある。
- `p+0x1978` は**経路管理領域を基準**とする相対位置であり、ふるまい制御構造体の同じオフセットとは異なる。
- オリジナルの CRO は実行時再配置される。インポートスタブの意味・実機での呼出順と戻り値は未確認。
