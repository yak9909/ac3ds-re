## 結論

ModuleOutdoor.cro の `0x00B66148` は、通常の目的更新経路で住民実体 +0x4651 の値を読み、直前の目的コードによって再抽選の分岐を変える。以下は、各分岐で引数 100 の抽選関数が返した値を `r` としたときの**分岐条件**である。

| 以前の目的コード | 新しい目的コードと条件 |
| --- | --- |
| 1 | この分岐では再抽選せず維持 |
| 2 | `r < 60` なら 0。そうでなければ特別行動候補選択（`0x00B403D4`）に成功すれば 5、失敗すれば 0 |
| 5 | `r < 5` かつ候補選択成功なら 5。そうでなければ `r < 75` なら 0、それ以外は 2 |
| それ以外 | `r < 20` かつ候補選択成功なら 5。そうでなければ `r < 70` なら 0、それ以外は 2 |

上記は目的コードの条件付き再抽選であり、コード 5 が屋外住民の「ふるまい番号 5」を意味するわけではない。別の前段分岐では日付・住民情報などに応じて目的コード 1・3・4 を直接設定する。

確度 MEDIUM。Ghidra が復元した `0x00B66148` の分岐命令に加え、独立した `0x00B403D4` の候補選択処理と `0x00B67670` の到着・次目的更新経路を確認した。実機測定はない。

## 根拠

- CRO 原本の `.text` はファイルオフセット `0x180`、サイズ `0x99E80`。Ghidra の独立解析ではこのバイト列を `0x00B00000` に配置した。以下の `0x00Bxxxxx` はこの**便宜番地**であり、実機のロード先番地ではない。
- `0x00B66158` は `MOV r11,#2`、`0x00B66160` は `MOV r9,#0`、`0x00B66164` は `MOV r10,#5`。これらが下記の `STRB` で実体 +0x4651 に設定される値となる。
- `0x00B6639C..B663C0` は実体 +0x4651 を取り出し、1 は保持、2 は `0x00B663F4`、5 は `0x00B66420`、残りは `0x00B663C4` へ分岐する。
- その他の分岐: `0x00B663C4 BL 0x00B01A90`（r0=100）→ `0x00B663C8 CMP r0,#0x14`。閾値未満で `0x00B663D8 BL 0x00B403D4`。候補成功は `0x00B66448 STRB r10,[r4]`、それ以外は `0x00B663E8 CMP r6,#0x46` により `0x00B66458 STRB r9,[r4]` または `0x00B66460 STRB r11,[r4]`。
- 以前のコード 2: `0x00B663F8 BL 0x00B01A90` → `0x00B663FC CMP r0,#0x3C` → 閾値以上で `0x00B6640C BL 0x00B403D4`。成功時だけ `0x00B66448`、その他は `0x00B66458`。
- 以前のコード 5: `0x00B66424 BL 0x00B01A90` → `0x00B66428 CMP r0,#5` → 閾値未満の場合だけ `0x00B66438 BL 0x00B403D4`。成功なら `0x00B66448`、それ以外は `0x00B66450 CMP r6,#0x4B` で 0 または 2。
- 独立した候補処理 `0x00B403D4` は対象コンテキスト +0x30 にある候補集合から最大 9 種を選び、コールバックの成功で 1、候補が尽きると 0 を返す。従って上記の特別行動への遷移は単なる乱数条件だけでは決まらない。
- 独立した到着処理 `0x00B67670` は `0x00B676F4` の現在位置→マス座標変換と、`0x00B67710/20` の目的マス（実体 +0x4652/+0x4653）照合を行う。条件処理を経て `0x00B67870 BL 0x00B66148` で目的を更新するため、再抽選が歩行先の更新経路で実行されることを確認できる。

## 反証条件・未確認点

- `0x00B01A90` の呼び先は CRO のインポート中継であり、原本の未再配置バイト列だけでは返値が 0〜99 の一様乱数か確定できない。従って閾値をそのまま発生確率（%）とは書かない。
- 候補選択 `0x00B403D4` の 9 個の実動作と、目的コード 0・2・5 が引き起こす経路探索の差は未検証。CRO の再配置情報と呼び出し先の照合が必要。
- 家から出る「ふるまい 5」への遷移元、A*・マクロ道路探索の全経路、実機での可視動作は未確認。
- `0x00B66148` の前段（日付や住民情報に応じた早期分岐）に入る場合は、この再抽選表が使われない。
