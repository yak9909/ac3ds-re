## 結論

ModuleOutdoor.cro の屋外住民ふるまい制御構造体（以下 `c`）では、現在のふるまい番号 `c+0x1975` と、次に適用するふるまい番号 `c+0x1976` を区別する。

`0x00B41330(c, mode)` は次状態候補の選択処理である。現在番号が `0x1A` なら次状態にも `0x1A` をそのまま格納する。それ以外では `c+0x1976` を 0 にして、**最大5件の判定コールバックを順に呼ぶ**。判定が非ゼロを返した時点で打ち切る。判定表は1件8バイトであり、処理先には直接関数ポインタとオブジェクトの仮想メソッドの両方が含まれる。

少なくとも `0x00B3DAA4`、`0x00B75764`、`0x00B6AE24` には、判定処理 `0x00B41330` を呼んだ直後に `c+0x1976` を読み、その値で `0x00B4109C(c, next_state)` を呼ぶ経路がある。

**確度 MEDIUM**: Ghidra で判定関数自体の分岐・読み書きを解析し、独立した3つの呼び出し元で次状態の使用と遷移を照合した。実機測定なし。

## 根拠

以下の `0x00Bxxxxx` は ModuleOutdoor.cro `.text` を `0x00B00000` に配置した便宜番地。CRO の実行時番地ではない。

- `0x00B41330`（Ghidra 関数体132バイト）:
  - `B41338/B4133C/B41344` で `c+0x1975` を読み、`B41348/B4134C` で `c+0x1976` を計算する。
  - `B41350 CMP r1,#0x1A` → `B41354 MOVEQ r1,#0x1A` → `B41358 STRBEQ r1,[r0]` は現在状態0x1Aの保持。
  - `B41364 MOV r1,#0` → `B4136C STRB r1,[r0]` が選択前の次状態0クリア。
  - `B41370 ADD r1,r7,r4,LSL #3` は8バイト幅の判定表を走査。`B41378 TST r0,#1` 以降は直接呼び出しか仮想呼び出しかを分岐。`B41398 BLX r2` が判定の実行。
  - `B4139C CMP r0,#0` → `B413A0 BNE B413B0` は成功時停止、`B413A4/B413A8/B413AC` は添字を増やし5件まで反復。
- `0x00B3DAA4`: `B3DB70 MOV r1,#0` → `B3DB78 BL 0x00B41330` → `B3DB7C/B3DB84` で相対 `0x1976` の1バイトを取得 → `B3DB88 BL 0x00B4109C`。
- `0x00B75764`: `B7576C MOV r1,#0` → `B75770 BL 0x00B41330` → `B75774/B7577C` で相対 `0x1976` をロード → `B75784 B 0x00B4109C`。
- `0x00B6AE24`: 住民実体 `+0x554` のバイトが非ゼロのときだけ `B6AEC4 BL 0x00B41330` → `B6AEC8/B6AED0` で相対 `0x1976` をロード → `B6AED8 B 0x00B4109C`。この経路に到達する前に `B6AEA8..B6AEB8` は実体 `+0x4678` に `0x18` を格納する。
- `0x00B4109C`: `c+0x1975` に渡された状態番号を書き込む実際の状態切替関数である（既存 ACNL-F0464 に対応）。`0x00B41330` の `+0x1976` はその事前の選択欄に相当する。
- 上の4呼出元で用いるオフセットのリテラルは原本で `[B3DBB0]=[B75788]=[B6AEE0]=0x1976`。

## 反証条件・未確認点

- 5件の判定表のアドレスは `B41360 LDR r7,[0x00B413B4]` が参照するが、**未再配置の CRO 原本では当該4バイトは 0**。したがって再配置後のテーブル位置と各コールバックの実番地・具体的な優先順位は未特定。
- 「家から出る」ふるまい番号5を、どの判定コールバックがどの条件で `c+0x1976` に書くかは未確認。今回の根拠だけで自動外出の条件・時刻を断定しない。
- 実機ではこの構造体の更新と他の行動要求が同一フレームで競合する可能性がある。実機の状態番号の観測が必要。
