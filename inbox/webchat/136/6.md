## 結論

屋外住民の経路生成には、**4方向グリッドで先に経路候補を選ぶ段階**と、**8方向グリッドで実際の移動経路を決める段階**がある。

- 本体 `0x0029C344` は開始・目標の座標を広域用の座標へ変換し、`0x007CDC48` で上下左右の4方向グリッドを探索する。成功（戻り値 `2`）の場合、その経路の先頭ノードを探索文脈 `+0x18EC` に保持する。
- 本体 `0x0029BE38` は経路文脈 `+0x18EC` に候補が無い（または次ノードが無い）と、直接 `0x007CE420` で8近傍の目的地探索を行う。候補があれば、広域経路が示す方向に局所探索範囲・目標条件を調整して `0x007CE190` で8近傍を探索する。
- `0x007CE190` は `0x007CE420` と同じく8方向の候補展開・評価値順のリストを使うが、目的到達条件をコールバックの**3番目のメソッド**に委ねる（`0x007CE420` は指定目標セルとの一致を直接判定）。
- ModuleOutdoor.cro `0x00B3E100` は、対象マスが現在の経路領域に含まれない場合に、`0x00B01B28`（広域候補設定）と `0x00B01B30`（局所探索）を呼ぶ。参照先は順に本体 `0x0029C344` と `0x0029BE38` である。

この4方向グリッドの論理単位が村内の「エーカー」「道路」のどちらを表すかは未確認であり、グリッドの呼び名を公式の地理区分と同一視しない。

**確度 MEDIUM**。Ghidra で本体の4方向/8方向探索、探索結果の保存、別関数内の候補有無による分岐を独立に確認し、CRO側の呼出元・CRO/CRS再配置と照合した。実機未確認。

## 根拠

- `0x0029C344`: `0x0029C428 BL 0x007CDC48` → `0x0029C42C CMP r0,#2`。成功時のみ `0x0029C438 LDR r0,[r4,#0xBC0]` → `0x0029C444 STR r0,[r4,#0]`。ここで `r4` は `0x0029C43C..0x0029C440` により文脈 +`0x18EC` へ調整される。
- `0x007CDC48`: Ghidra の関数範囲 `0x007CDC48..0x007CDEDB`。展開ループ末尾 `0x007CDEA0 CMP r5,#4`。呼び出す隣接方向取得関数 `0x007CDA5C` と、優先リスト操作 `0x007CDBF8` を併用する。候補枯渇0、境界外1、到達2を区別する。
- `0x0029BE38`: 冒頭で `context+0x18EC` のノードと次ポインタを調べる。無い場合は `0x0029BF94 BL 0x007CE420`、`0x0029BF98 CMP r0,#2`。候補がある場合は経路の方向から局所範囲と目標位置条件を構築し、`0x0029C260 BL 0x007CE190`、`0x0029C264 CMP r0,#2` へ進む。
- `0x007CE190`: 関数範囲 `0x007CE190..0x007CE41B`。`0x007CE2D8 BL 0x007CE85C` で隣接方向取得、`0x007CE3DC CMP r5,#8` まで反復。`(**callback[2])` の非ゼロで終了経路へ入り、親ノードをたどって戻り値 `2` を返す。`0x007CE420` は隣接方向取得を共有するが目標ノードの一致を直接検査する。
- ModuleOutdoor.cro の `0x00B3E3F8 BL 0x00B01B28`、`0x00B3E448 BL 0x00B01B30` は同じ関数 `0x00B3E100` の中にあり、前段の座標範囲不成立から到達する。
- Ghidra スクリプトでCROのインポートパッチと anonymous import を結合。中継 `0x00B01B28` のパッチは `0x0A4510` → 静的 segment0 offset `0x19C344` → `0x0029C344`。中継 `0x00B01B30` は `0x0A44EC` → offset `0x19BE38` → `0x0029BE38`。static.crs の segment0 基準は `0x00100000`。
- CRO の `0x00Bxxxxx` は `ModuleOutdoor.cro` の先頭セグメントを `0x00B00000` に置いた解析上の番地。ロード後の実行番地は未確定。
