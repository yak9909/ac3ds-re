## 結論

再解析で確認。基底 Layout の正射影は生成時の幅 `+0x28`、高さ `+0x2C` から作り、`+0x34` の16語として保持する。本記録の画素換算式で使う W,H は、送出する保存行列を作ったときの寸法を指す。root Pane の寸法でも、画面別の固定倍率でもない。記録済み列が非空なら、その Layout の行列を再生直前に Drawer 経由で送る。

確度 MEDIUM：矩形・行列の生成命令、独立した再生側、ペイン幾何・変換とタッチ座標変換が整合する。実機は操作していない。既存名・コメントは証拠として数えず、命令とデータを再読した。

基底の正射影、追加の view/立体視等の変位がゼロである場合、変換後の UI 点 (X,Y) に対する左上原点の画面境界座標は、viewport を Vw×Vh として次の通り（画素中心の丸め規則ではない）。W,H は現在の寸法欄ではなく、送出する保存行列を作ったときの寸法である。現在の `+0x28/+0x2C` を使う場合は、保存行列と一致していることを条件とする。

```
px = Vw/2 + X*Vw/W
py = Vh/2 - Y*Vh/H
```

| viewport | 保存行列生成時の W×H | 中央 | UI 1 単位の倍率 (横,縦) |
|---|---|---|---|
| 上 400×240 | 400×240 | (200,120) | (1,1) |
| 下 320×240 | 320×240 | (160,120) | (1,1) |
| 下 320×240 | 400×240 | (160,120) | (0.8,1) |

以下のペイン寸法・中央位置の換算も同じ W,H を使う。ペインのローカル幅 w=`+0x48`、高さ h=`+0x4C` は、それだけでは画素寸法ではない。回転・傾斜が無く、親を含む有効 scale が sx,sy なら、画素寸法は `abs(w*sx)*Vw/W`, `abs(h*sy)*Vh/H`。回転等があれば四頂点を行列で変換する必要がある。中央アンカーなら、ローカル四隅は `(±w/2, ±h/2)`。親・view が単位行列かつ scale=1 の場合、画面上の左上 (px0,py0) と画素寸法 (pw,ph) をペイン中央へ換算すると次の式になる。

```
w = pw*W/Vw; h = ph*H/Vh
X = (px0 + pw/2 - Vw/2)*W/Vw
Y = (Vh/2 - py0 - ph/2)*H/Vh
```

画面幅の400/320の取り違えによる40画素差も、1対1の条件下での半幅差であって、任意の投影・親変換に共通ではない。
