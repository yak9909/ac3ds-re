## 結論

再解析で確認。基底 Layout は `+0x11D != 0` のときだけ Pane 木を専用リストへ再記録し、範囲を保存して要求をゼロにする。再生は要求を検査せず、保存長 `+0x108 > 0` の場合に保存範囲を使う。記録要求ゼロのまま再生することは静的契約として成立する。

確度 MEDIUM：要求の生産側、記録側の分岐・消去・範囲確定、独立した再生側の命令が一致。今回の実機操作はない。

## 根拠

一次証拠：`_local/evidence/24/ida-primary.txt`、`ida-followup.txt`、`ida-calls.txt`、`ida-final.txt`。既存 [ACNL-F0435] のキャッシュ説明とも整合するが、判定は下記の命令による。

- `0x900608` の Layout vtable 実データでは `+8=0x5682DC`、`+0x0C=0x568030`、`+0x10=0x5685A4`、`+0x14=0x5686D4`。`0x566EA4..0x566EC8` は head を `list+4` から読み、next `node+8` を辿り、各 node の vslot `+0x14` を呼ぶ。再生巡回は [ACNL-F0693]。
- `0x5686E0..0x568700` は要求検査より先に `+0x11F==0` なら投影生成の vslot `+0x18` を呼ぶ。「要求ゼロなら関数全体が無処理」ではない。
- `0x568704..0x56870C` は `LDRB [Layout+0x11D]; CMP #0; BEQ return`。非ゼロなら `0x568718` で元の選択 ID を取得し、`0x56871C/24` で `+0x100` の ID を選ぶ。
- `0x568730` → `0x7B01CC` は選択 manager の offset・提出済み位置・GX件数等をリセットし、cursor=base、end=base+capacity とする。続く `0x56873C` → `0x7B05B0` は保存開始位置とGX開始件数を控える。追記型に蓄積し続ける記録ではない。
- `0x568758` は Drawer の begin slot に1を渡し、`0x56876C` で Pane 木を記録する。`0x4D7184` は global cursor を読み、`0x4D7190..0x4D71B0` は root と表示ビットを検査して再帰走査し、`0x4D71C8` は返された最終 cursor を global に保存する。木の走査内ではローカル cursor が進む。
- `0x568770` は raw word `0xE320F000` の NOP。木の走査から戻った後であり、`R4=Layout`。ただし Drawer end (`0x568788`, 引数1) と Commit (`0x56879C`) より前なので、ここでの書込長は最終記録長ではない。
- `0x56878C..0x56879C` は `+0x104/+0x108/+0x10C/+0x110` に開始位置・バイト長・GX開始位置・GX件数を保存。`0x5687A8` は元 ID を再選択し、`0x5687AC/B0` は要求を0にする。
- 要求の生産例 `vc_ACSYSTEM_DATA2(0x568030)` は Pane アニメ評価・行列計算の処理を経て `0x568068 MOV R6,#1`、`0x5682B8 STRB R6,[R4,#0x11D]` を実行する。可視変化の有無を比較してから要求を立てる仕組みとは限らない。
- 独立した再生側 `0x56835C..0x568364` は保存長の符号付き `<=0` なら記録範囲再生を省略。正なら `0x5683C8..0x5683E4` で保存 ID と範囲等を `0x7B0A28` に渡す。シザー命令は長さ検査より先に出る [ACNL-F0697]。
- `0x133A64..0x133A6C` は引数を読まず `*(0x96FC38)` を返し、`0x4D7164..0x4D716C` は global cursor を返す。F0228 のこの小関数の説明は確認。
