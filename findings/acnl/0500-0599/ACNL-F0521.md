## IDA-opus-5.5-F010: モデル単位の色ハイライトは「TEV の空き最終段で定数色と混ぜる」でできる（2026-09-23、**HIGH（静的＋実機で表示確認）**。材質 1 つで確認）

解析ソフト: IDA / 解析モデル: opus-5.5。利用者の依頼「建物を含めた任意の 3D モデルで、そのモデルだけ全体の RGBA を操作できるか。
将来、選択中の建物を薄い青でハイライト（環境光の影響を受けない）」。実機は読み取りのみ（`work/evidence/models3d/tint_probe_20260923.json`）。

### 1. 汎用の材質書き出し `0x49C08C`（MaterialActivator vtable slot 3）

材質（`nw::gfx::Material`、以下 M）は部分ごとの ResMaterial ポインタ M+40〜M+80（`a3[10]`〜`a3[20]`）を持ち、各部分の
「前回と同じなら省く」鍵（ResMaterial +672〜+720）と比べて GPU コマンドを書き出す。

- **色**: `a3[12]`（M+48）の +36 からの u32 配列。添字 44〜48 = 光源系（Emission/Ambient/Diffuse/Specular0/1 と推定）、**49〜54 = Constant0〜5**
- **TEV 6 段**: `a3[18]`（M+72）の +648 の相対ポインタ先（**フラグメントシェーダ部 244 B**）。+220 から 24 B（バッファ設定）、
  続けて **1 段 28 B × 6**: `[選択番号, 入力元, ヘッダ 0x804F00Cx, オペランド, 合成式, 定数色, 倍率]`。
  選択番号 1〜5 → Constant1〜5、6〜10 → 添字 44〜48、その他 → Constant0 を**定数色の欄へ埋めてから** 24 B をそのまま流す
  （ヘッダの書き込み先 0xC0/0xC8/0xD0/0xD8/0xF0/0xF8 = PICA の TEV 段 0〜5）
- **フラグメントの設定（ブレンド等）**: `a3[20]`（M+80）の +280〜（IDA-gpt-6-astra-F002 が使った部分）

### 2. 材質の複製 `0x4ADD44(out, M, allocator, mask)`

728 B の ResMaterial 本体（色・フラグメントの設定を含む）は常に複製し、**鍵 +672〜+720 は 0**（＝毎回書き出す）。mask で追加複製:
`0x1` テクスチャマッパー表、`0x20` +157〜159、`0x40` +160、**`0x780` のどれか = +162 のフラグメントシェーダ部 244 B（TEV）**、`0x100` はその参照表も。

### 3. 実機（読み取り）: 建物 fobj_lamp_jpn(0xC3)

- 実体 +0x90 = `nw::gfx::Model`、Model +0x164 = 材質の配列（この建物は 2 個）、Model +0x1EC = `nw::gfx::MaterialActivator`、
  **vtable slot 3 = 0x49C08C（汎用）**。木（F002）で必要だった書き出し関数の付け替えは建物では要らない
- **色の部分 M+48（= M+80）はインスタンスごとに別**（同じ 0xC3 の 4 棟で 4 つ）。本体だけの複製（+648 の TEV 相対ポインタは 0）で、鍵 +692 = 0。
  ゲーム自身がインスタンスごとに作っている
- **TEV の部分 M+72 は同じ種類で共有**（4 棟とも 0x301CA374、鍵 +712 = 0xB8B030A7）
- TEV: 段 0 = 入力 0x0E300E01・合成 0x10002、段 1〜3 は使用中、**段 4・5 = 入力 0x0E1F0E1F・合成 0（前段をそのまま通すだけ）**
- 色: 添字 44〜48 = 0, 0xFFFFFF, 0xFFFFFFFF, 0xB6B5B5, 0xB6B8B7、Constant0〜5 = 0xFF000000

### 4. ハイライトの手順（案。未適用）

1. 対象モデルの各材質で `0x4ADD44(mask 0x80)` → TEV を含むインスタンス専用の ResMaterial
2. 複製の**空いている最終段（段 5）**を: 入力 = [定数, 前段, 定数]、RGB オペランド = [色, 色, **アルファ**]、RGB 合成 = Interpolate、
   アルファ = 前段のまま、選択番号 = 5（Constant5）
3. その材質の色の部分（M+48、既にインスタンス専用）の Constant5 = 薄い青 RGB ＋ アルファ = 混ぜる強さ
4. M+72 を複製へ。戻すときは M+72 を元へ（複製はすぐ解放しない。F002 と同じく GPU の参照終了は未確認）

TEV の最終段はフラグメントライティング・環境光・テクスチャの**後**なので、明るさに関係なく同じ割合で青が混ざる。アルファは前段のままなので
切り抜き（アルファテスト）は保たれる。フォグはこの後に掛かる。

未確認・反証条件: (a) 実機で青く見えるか（未適用）、(b) 段 5 が空いていない材質（その場合は別の手）、(c) PICA の Interpolate の入力順と
オペランドの値（citro3d/libctru の定義と照合してから書く）、(d) 影・アウトライン等の別パスで元の材質が使われるか、
(e) モデルビューア（F035）の自前モデルは Activator が別の可能性。

### 5. 実機で試した結果（2026-09-23、利用者の許可あり）

道具 `tools/models3d/tint_probe.py`（MODE = apply / color / restore）。対象は上画面右の fobj_lamp_jpn（0xC3、(85, 53)、実体 0x331273D0）。
関数は呼ばず、TEV の写しを `.text` 末尾の空き 0x838740 に置き、その棟の**色の部分（M+48、インスタンス専用）の未使用の +648** を写しへの
相対ポインタにして、材質 M+72 を色の部分へ向けた（汎用書き出しが M+72 から読むのは +648 と鍵 +712 だけ）。書いた値:
段 5 = [選択 5, 入力 0x0E1F0EFE, 0x804F00F8, オペランド 0x200, 合成 0x4, (定数色), 0]、Constant5 = 0xB0FFB060。

- **材質 0（柱と頭）: 薄い青になった**。夜の暗い灰色が明るい水色に変わり、環境の暗さに引きずられない（`applied_b0.png`）
- **強さ 0x50 に下げると青みが弱くなる**（`applied_50.png`）。Constant5 のアルファが混ぜる割合として効く
- **材質 1（灯り）は段 5 が使用中**（入力 0x033F0EFD・Interpolate・定数色 0xFF001D43）で飛ばした → 全材質で最終段が空いているとは限らない
- **restore で元の見た目に戻る**（`restored.png`）。M+72・+648・Constant5・空きを読み戻しで確認
- 画像: `work/evidence/screens/tint_20260923/{before,applied_b0,applied_50,restored}.png`、元値 `work/evidence/models3d/tint_probe_state.json`

残り: 段 5 が使用中の材質の扱い（別の空き段を探す／段 5 の後に足せないので段 5 の出力へ混ぜ込む形に書き換える等）、
常用には `.text` の空きではなくヒープ上の写し（`gfx_ResMaterial_CopyForInstance` mask 0x80 など）、GPU が古い写しを参照し終える時期、
影などの別パス、モデルビューアの自前モデル。
