## IDA-unknown-F027: 頂点バッファの番地は VA→GPU 変換を通り、対応外の領域では黙って 0 になる（2026-09-18、HIGH、静的）

IDA-unknown-F026 で「頂点属性コマンド列は sub_7E5710 が組み立てる」と分かったので中身を読んだ。

**(1) 番地の出どころ**。sub_7E5710 は `v13 = sub_143B54(頂点バッファの VA)` を **`*(mesh+52)` に保存し、同時に `buf[8] = v13 >> 3` として PICA の頂点バッファ基底に書く**（>>3 は PICA の番地規約）。各属性ストリームのオフセットも `sub_143B54(...) - v13` として同じ基底からの差分で出す。

**(2) sub_143B54 は sub_140C3C への thunk で、これは VA → GPU（物理）番地の変換**。経路は (a) sub_1431BC (b) VA ∈ [0x1F000000, 0x1F600000) または 0x1F600000 なら `VA - 0x07000000`（VRAM） (c) sub_143158 / sub_143170 (d) 登録済みの線形領域 `[sub_143238(), +sub_143220())` に入っていれば、基底が 0x30000000 未満なら `VA + 0x0C000000`、そうでなければ `VA - 0x10000000`。**どれにも当てはまらなければ 0 を返す。例外も警告も出ない。**

**(3) したがって想定される失敗の形**: 自前で用意したヒープが登録済みの線形領域の外にあると、`sub_143B54` が 0 を返し、**頂点バッファ基底が 0、属性オフセットも全部 0** になる。sub_7E5710 は戻り値を検査しないので、**コマンド列は正常な形で生成され、メッシュも可視、マテリアルも正常なのに、GPU は物理番地 0 から頂点を読む**。クラッシュもエラーもなく、ただ何も出ない。これは実機で観測した症状（描画経路のふるいを全部通るのに画素が 1 つも出ない。IDA-unknown-F024 の実機節）と完全に一致する。

**★2026-09-18 訂正（IDA-unknown-F028）: この項の欄の同定は誤りで、仮説は実機で棄却された。** `mesh+52` は番地ではなく `sub_4A8B44` が書く定数 0x000F02C0（PICA ヘッダ）。頂点バッファの束縛は属性コマンド列の `ATTRIBBUFFERS_LOC`＋`ATTRIBBUFFER0_OFFSET` で表され、実機では正しい番地を指していた。以下は当時の記述のまま残す。

**(4) 検証できる 1 点**: 自前インスタンスの **`mesh+52`（0x34）が 0 かどうか**。0 なら原因はこれで確定。非 0 なら本仮説は棄却で、次は `desc[usage+76]` の属性番号対応（sub_7E5710 は sub_4A8B44 と違い `>= 0` の除外判定を持たない）を疑う。

**(5) 注意**: テクスチャが正常だったことは反証にならない。実機で読んだテクスチャ番地 0x041F9F40<<3 = 0x20FCFA00 は VA 0x30FCFA00 − 0x10000000 に相当し、上の (d) の分岐が成立したことを示す。つまり**少なくともテクスチャが置かれた番地は線形領域内**だった。頂点バッファが同じ領域に載っているかは別に確かめる必要がある。

反証条件: mesh+52 が非 0 である、sub_143B54 の戻り値をどこかで検査している経路がある、または頂点データが mesh+52 以外の欄から供給される。根拠 IDB コメント（0x7E5710 / 0x140C40）。
