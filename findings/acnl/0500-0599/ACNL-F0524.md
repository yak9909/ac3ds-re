## IDA-opus-5.5-F007: その場で作った建物は資源の枠を部屋が片付くまで返さない。尽きると読み込みスレッドが落ちる（2026-09-23、MEDIUM（静的＋実機のクラッシュダンプ））

解析ソフト: IDA / 解析モデル: opus-5.5。番人方式（F006 §4 旧版）の実機確認（利用者）:「枠を越えても置けるが、
置きすぎるとクラッシュ」。ダンプ `work/evidence/crash/crash_20260923_publicworks_guard.dmp`（解析 `.txt`）。

### 1. ダンプ

data abort、pc `0x56A0EC`（`ldr r3, [r0]`、r0 = 0）、lr `0x5699A0`。スタックにプラグインの番地は無い。
`0x56A0EC` は読み込み要求（r4 = `0x3313726C`）の **+0xCC（確保に使うアロケータ）が null** のまま、
`vtable+0x18` で 0x2EE0（12,000）B を確保しようとした所。呼び出しの連鎖は `sub_569EFC` ← **ファイル読み込みスレッド**
`sub_5664EC`（要求の列 `0xADF7D4`）。

### 2. 建物の資源の借り方（ModuleOutdoor `0xB49620`、実体の vtable slot 55 `0xB27CFC` から 2 回 = モデルとテクスチャ）

r5 = BsStrcMgr の **ResourceMgr（管理役 +0xF24、村では `BsStrcMgr_InitHeaps` が 1,423,360 B のヒープと 0x40 個 × 284 B の枠を作る）**。

1. 読み込み済み一覧（RM+0x470C = 管理役 +22064）に同じ名前があれば使い回す
2. 読み込み中一覧（RM+0x4724）に同じ名前があれば、その枠で読み込みを進める
3. 無ければ**空き一覧の先頭（RM+0x4718 = 管理役 +0x563C）を null を確かめずに取る**（`0xB49844` / `0xB49850`）

枠は部屋を片付けるとき（`BsStrcMgr_Teardown`）まで返らない。ゲームの読み直しは毎回枠を作り直すので、素のゲームで
部屋の中の建物の種類が増えることはなく、この経路は起きない。gohan がその場で種類の違う建物を置く・動かすを
繰り返すと空きが尽き、壊れた読み込み要求ができて落ちた、と判断した（空き一覧が尽きた瞬間は実機で見ていない）。

### 3. gohan の対策（実機未確認）

- **その場で作るのは公共事業（profile 0x80 = AcStrcFieldObj）だけ**。romfs で fobj は 1 種類最大 3 ファイル・77,712 B。
  役場・店・家は 1 種類で数十〜数百ファイル・数 MB（sobj 最大 780,816 B、dobj 2,321,480 B、hobj 6,407,268 B）あり、
  何本読むかも確かめていないので、ゲームの部屋の読み直しに任せる
- 作る前に **空き一覧が 3 個以上** かつ **ResourceMgr のヒープの空き（`HeapFreeSize 0x74D744(*(mgr+0xF28))`）が 0x30000 以上** を確かめる。
  足りなければ部屋の読み直し（ゲーム自身が枠を作り直す）
- 検査 89 件 PASS（F007 分: 空き一覧の位置 = CRO のリテラル 0x4718 + 0xF24、次のノード `[r4, #8]`、null 検査が無いこと、
  `InitHeaps` が +0xF24 と RM+0x4714 を作ること、HeapFreeSize、romfs の最大ファイル数と大きさ、profile 0x80 の名前）。
  成果物の逆アセンブルで `cmp #0x80`、空き数 3、`[mgr+0xF28]`、`cmp #0x30000` を確認

反証条件: 公共事業を何十回置き替えても落ちない前にしきい値で読み直しへ切り替わること、が実機で確かめられない
（しきい値の手前で落ちる）なら、空き一覧以外の資源（アニメ・読み込み中の枠）も数える必要がある。
