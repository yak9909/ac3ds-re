## F-317: ★取り外しでコマンドリストを削除しておらず nngx ヒープが漏れる — HIGH

### 症状

`detach` → `Free` → フック復帰 → ゼロ埋め、で
**nw::lyt は完全復帰する（1,331,224 B）のに、nngx は戻らない。**

| | nngx の空き |
|---|---|
| 再起動直後 | 1,220,172 |
| 1 回目の組み込み後 | 1,087,992（**−132,180**） |
| 2 回目の組み込み後 | 955,800（**−132,192**） |

**1 回の組み込みごとに 132,180 B（= `2 x (0x10000 + 28x16)` ＋ヘッダ）が返らない。**
`LIST_SIZE 0x10000` なら **ON/OFF を 9 回で nngx を使い切る。**

### 原因

A1/A2 のケーブは `node+0x100` が 0 のとき
`GenCmdlists` → `CmdlistStorage` で**コマンドリストを作る**が、
**取り外しでそれを削除していない。**
`.bss` をゼロにすると `node+0x100`（list id）も消えるので、
**次に組み込むとまた新しいリストを作る**＝毎回漏れる。

nw::lyt の借用は `Allocator::Free` で返しているので戻る。
**片方だけ返していた。**

### 直し方

`nngxDeleteCmdlists` 相当が `sub_127D98(件数, &id の配列)` にある
（分類 0x10000 / 261 の器へ `off_96EAA8` で返し、管理表から外す）。

取り外しの手順に**リストの削除を足す**:

```
1. detach（root Pane = 0、記録要求を立てる）
2. 記録長 +0x108 が上下とも 0 になるのを待つ
3. ★sub_127D98(1, &node+0x100) を上下それぞれで呼ぶ   ← 追加
   （ゲームのスレッドから。確保・解放と同じくケーブ経由）
4. nw::lyt の借用を Free
5. フックを素へ戻す -> 100ms 待つ -> .bss とケーブをゼロ埋め
```

★**3 を 5 より先にやること。** `.bss` を消すと list id が失われて削除できなくなる。

### 教訓

**「借りたものを返す」検査を、確保した資源の種類ごとに持つ。**
nw::lyt だけ見て「完全復帰した」と満足していた。
**取り外しの検査は、触った全部のヒープの空きが元に戻ることを見る。**

### 状態

- 実機は素に戻してある（フック 4 本すべて素、`.bss` とケーブはゼロ）
- **nngx は 955,800 B（本来 1,220,172）。再起動すれば戻る**
- 仕様書 v2 §5.3 に手順を追記した
