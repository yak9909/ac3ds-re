## F-340 — 色替え・書体替えの費用を分解し、記録量の式を完成させた（2026-09-07・実機）

**confidence: HIGH**（実機 15 点で誤差 0。うち 2 点は**式を作ったあとに予言してから測った**）
根拠: memory 値（`batch+0x1C` と ノード `+0x108`）/ assembly（`0x004D4EAC` / `0x004D6570`）
正本: `PATCHES/batch_cost_model.py`（単体実行で自己検査が走る）
詳細: `scratchpad/MEMO_f340_color_cost.md`

### 式

```
batch+0x1C（語） = 74 + 12n + 28*f
                  + [色の連 k>=2 なら] 40 + 16*(k-1) + 20*(f-1)
記録長 = align16( 4*語数 + 192*本数 + 204*Picture 枚数 )      … F-338 のまま
```

| 何を変えるか | 費用 |
|---|---|
| 字 1 つ | 12 語 = 48 B |
| 追加の吐き出し 1 回 | 28 語 = 112 B |
| 色の連 1 本（2 本目以降） | **16 語 = 64 B** |
| 単色でなくなること（一度きり） | **40 語 = 160 B** |
| 2 回目以降の吐き出し（多色のとき） | **+20 語 = 80 B**（block2 が復活する） |
| **書体を変えること** | **0 語**（同じアトラスなら群も切れない） |

**色替えの費用は変わり目の位置に依存しない**（32 字・色 2 本を 16/16 と 8/24 で測って同値 542）。

### 吐き出しの回数 f（★F-339 の「+20 のずれ」の正体）

計数器は F-337 / F-338 の逆アセンブルどおりだが、**境界の向きは実機で決めた**。

```
吐き出しから 17 字目を積むとき  … 切れる（16 字ごと）
吐き出しから 7 本目の色の連    … 切れる（色の連 6 本ごと。ctx+0x27 の上限 24）
ctx+0x24（字ごと +1 / 上限 25）… 16 字より緩いので一度も効かない
ちょうど末尾で切れる場合は数えない（1 回目の吐き出しは 74 に入っている）
```

F-339 の「34 字・3 色が式より 20 語多い」は誤差ではなく、
**34 字だと追加の吐き出しが 2 回あり、2 回目で block2（20 語）が復活する**ため。
32 字（追加 1 回）では出ない。34 字で再現し、56 字（追加 3 回）で `20*(f-1)` を検定した。

### ★あふれたときの守り（静的解析。実機では試していない）

| 場所 | 守り |
|---|---|
| `EmitGlyphQuad 0x004D4F6C` | `if (batch+0x00 容量 > batch+0x04 件数)` のときだけ記録を書く。**超えた字は静かに捨てる**（落ちない・壊れない）。カーソルは進む |
| `BuildCommandStream 0x004D659C` | `n = min(batch+0x04, batch+0x06)`。**`+0x06` を書けば語数の上限を外から縛れる** |
| コマンド語の器 `+0x20 = (78n+57)&~3` | 最悪（1 字ごとに色替え）でも使用率 73%（n=2）、実用域は約 47%。**あふれない** |

### 設計に効くこと

1. **色は高い、書体はただ。** 同じ色をまとめれば 1 本 64 B 浮く。
   ただし**描画順が変わる**ので、重なりのある配置で並べ替えてはいけない。
2. **色の連が 6 本を超えると吐き出しが 1 回増える**（+28 語）。1 吐き出しに色は 6 本まで。
3. 書体は自由に混ぜてよい。

### ★踏んだ落とし穴

1. **表と文字列の領域が重なっていた。**
   `O_TABLE +0x320` / `O_STR +0x400` で、F-339 は 3 件（0x60）だから当たらず、
   **8 件（0x100）にした瞬間に文字列の先頭 32 B を潰した**。画面には出ていたので気づきにくい。
   → `textwriter_multi.check_regions()` を書き build から必ず通す。`O_STR` は `+0x520` へ。
   **「前は動いた」は根拠にならない。件数で伸びる領域は毎回測る。**
2. `CTL_DIRTY` を立て忘れ、前の条件の値を読んで同じ数字を 2 回見た。
   ケーブは dirty のときだけ組み直して旗を落とす。**条件を変えたら毎回立てる。**
3. **★`export_gui_v2` を IDA の中で `import` するとデバッガ API が壊れる。**
   `load()`/`load_module()` が `sys.modules["ida_bytes"]` 等を空モジュールに差し替え、
   同ファイルは末尾で `main()` を呼ぶので**取り込んだだけで走る**。
   以後 `ida_bytes.get_bytes` も `ida_dbg.write_dbg_memory` も消える（黙って消える）。
   同じ細工は 8 本（`compare_q_baseline` / `dump_q_ref` / `export_gui` / `export_gui_v2` /
   `preview_layout` / `verify_literals` / `verify_plugin_port` / `verify_plugin_port_v2`）。
   → 9 箇所すべて**「本物（`__file__` を持つ）があるなら差し替えない」**へ直した。
