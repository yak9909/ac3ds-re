## F-290 (HIGH・実機) — CAVE_Q を `Picture_DrawToCommandList` 呼びへ置き換えた。**座標系は手書き経路と同一**

2026-09-04 深夜〜2026-09-05。設計は `scratchpad/DESIGN_caveq_picture.md`、
経過は `scratchpad/MEMO_caveq_port.md`、状況復元は `scratchpad/MEMO_f290_state_recovery.md`。

### 何をしたか

`build_q` の**手書きスプライトループを、1 枚ごとの
`BL 0x73CB58 nwlyt_Picture_DrawToCommandList(picture, cursor, 0, drawctx)` に置き換えた**
（`Q_PICTURE_CALL = True`）。再利用する Picture 雛形を `.bss` の `PIC = 0x009B6000`（`0x400`）に置き、
**1 個を使い回して行列・幅・高さ・UV・色だけ差し替える**。

- `0x73CB58` は入口で `MOV R4,R0 / MOV R5,R3 / LDR R2,[R0,#0x13C]` なので **a3(R2) はデッド**。`R2=0` でよい
- 戻り値 R0 = 進んだカーソル。これを R5 へ受けて繋ぐ
- **フックは増えない**（CAVE_Q から直接 BL するだけ。`0x73CB58` は素のまま）
- マテリアル消失ガードを入れてある（`LOG+0x08` が発火回数。**実測 0 回 / 記録 4823 回中**）

### ★座標系を実測で確定（このセッション）

下画面の表に 4 本の帯（X=-150/-50/+50/+150、H=60/120/180/240、W=40）を置いて画面を実測。

| 表 | 画面 |
|---|---|
| X=-150 / -50 / +50 / +150 | 中心 x = 10 / 110 / 210 / 310 |
| H=60 / 120 / 180 / 240（Y=0） | 高さ 60 / 120 / 180 / 240、いずれも中心 y=120 |

→ **`screen_x = X + 画面幅/2`、`screen_y = 画面高/2 - Y`、1 単位 = 1px、幅・高さ 1:1。**

**手書き経路（F-278）とまったく同じ。**
したがって**表の 20 語書式・`preview_layout.py`・`verify_plugin_port.py` はそのまま通用する**。
アンカー（表 `[6][7]`）は `Pane_GetAnchorOffset` が幅・高さから決めるため読まれないが、
位置合わせに影響しないことを実測で確認した。

  クラッシュなし・ガード沈黙・連写差分 0%

### ★未解決 H-1 — チャンク 0 の残像（原因特定）

`TOP_CHUNK=0` なのに上画面へ 160x240 の白い矩形が残り、上ノードの記録長は `0x180` のまま。

**原因**: `build_q` の `gotscreen` 直後で
`CUR_TAB==0` または `CUR_CHUNK==0` なら **`SelectList`/`Clear`/`StartSave` より前に `skip` へ飛ぶ**。
記録サイクルを行わないのでノードの `+0x108` が前フレームのまま残り、**前の絵が replay され続ける**。

F-282 でプラグイン側に見つけた「不備 2」と同じ構造（あちらは空でもダミー 1 チャンクを出して回避）。

**直し方**: チャンク 0 の判定を **StartSave のあと**へ移し、空の記録を Commit する。
★F-256 の「そのパスでゲームが 1 度も描いていなければ描かない」ガードは**残すこと**
（消すと上画面が真っ白のままフリーズした実績がある）。

### 手順上の教訓

デバッガのメモリ読みは**古い値を返すことがある**。
`PACKED_BOT` を読んで Picture 由来の値が見え「色配列が潰されている」と早合点したが、
`invalidate_dbgmem_contents` を挟んで読み直したら正常だった。
**異常を見つけたら、結論を出す前に必ず読み直す。**

### F-290 追記 — ★H-1（チャンク 0 の残像）を直した。**監査器が別ファイルを見ていた**

**H-1 の修正**: `build_q` の「表が無い／チャンク 0 なら何もしない」判定を、
**記録を始める前 → `StartSave` / `DrawBegin1` のあと**へ移し、`skip` ではなく `endrec` へ飛ばす。
`endrec` は DrawEnd1 → Commit → SelectList 復帰まで行うので、**空の記録が Commit され前の絵が消える**。
既存の早期離脱 3 つ（drawctx 未記録／カーソル 0／残量不足）と同じ出口なので新たな危険は無い。
語数は 205 語のまま。

**実機 A/B**（下画面 y=120 の白画素）

| 段 | 操作 | 画面 | 記録長 |
|---|---|---|---|
| A | 表 4 本・BOT_CHUNK=1 | 帯 4 本 | `0x2A0` |
| B | **BOT_CHUNK=0** | **完全に消えた** | **`0x0`** |
| C | BOT_CHUNK=1 に戻す | A と 1 文字も違わない | `0x2A0` |

記録長が追随しているので「replay されない」のではなく**空の記録が Commit されている**。

### ★★手順上の重大な欠陥（このとき発見）— 監査器が旧ファイルを見ていた

`PATCHES/audit_node_cave.py` の**既定の対象が旧 `cave_node_draw.py`** だった。
引数なしで走らせると **現行のケーブを 1 語も監査していないのに「総異常 0 件」**と出る。
**F-286 / F-287 で「監査 OK」と報告したものはこの誤りを含んでいた可能性が高い。**

直した: 既定を `cave_node_record.py` へ変更し、許容する外部飛び先に `PIC_FN`(`0x73CB58`) を追加。
正しい対象で回すと CAVE_Q 205 語・全ケーブ異常 0・重なり無し・リテラル異常 0 で通る。

**教訓: 検査器には「何を検査したか」を出力させ、対象を毎回確認する。
「異常 0 件」は正しい対象を見ていて初めて意味がある。**
