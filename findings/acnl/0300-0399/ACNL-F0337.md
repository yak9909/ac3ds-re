## F-311 追記 2: 文字が乱れた原因は「中央整列での半画素」（2026-09-06）— HIGH

### 症状

メニューは出たが文字が乱れた。実機の画素を読むと

```
  8 ..#...#.#.....##..#.#...........##.##.#.....#...#.#...#....
  9 ..#...#.#.....#.#.#.#...........#.#.#.####..###.#.#...#....
 10 ..#####.#.....#..##.#...........#...#.##....#...#.#...#....
 11 ..#...#.#.....#...#.#...........#...#.#.....#..##.#...#....
 12 ..#...#.#.....#...#.#...........#...#.#.....#...#.#...#....
 13 ..#...#..####.#...#.#####.......#...#.#####.#...#..####....
```

`ACNL MENU` が **`HLNL MENU`** に見えた（`WALK SPEED` → `WHLK SPEEU`）。
`A`→`H` / `C`→`L` / `O`→`U` / `D`→`U` は全部
**「字形の 0 行目が欠けている」**という 1 つの症状。

字形は 7 行だが、出ているのは **行 1〜6 の 6 行 + 下に余白 1 行**。
つまり文字の上端が `y + 0.5` に来ていて、最近傍サンプリングが 1 テクセル下へ丸めた。

### 原因

`+0xFC` は**組み合わせた選択子**だった（`nwlyt_TextBox_ConfigureTextWriter 0x4BADA0`）:

```
水平 = textbox[0xFC] % 3    0=左 / 1=中央(0x10)  / 2=右(0x20)
垂直 = textbox[0xFC] / 3    0=上 / 1=中央(0x100) / 2=下(0x200)
```

`4` は **水平中央 + 垂直中央**。`nwfont_TextWriter_ApplyAlignment 0x7E7968` は中央のとき

```
文字の上端 = ペイン中心Y - 文字高/2
```

とする。ペイン中心は `cy = 画面高/2 - (y + ペイン高/2)` なので、
**ペイン高 == 文字高 でないと中心が半画素になる。**

こちらはペイン高に**セル高 7** を入れていた。ずれが 0.5 だったので
`|7 - 文字高| / 2 = 0.5` → **文字高 = 8 = 行送り（FINF+0x01）**と逆算できる。

★横は `幅 = 文字数 x 送り` が測定幅と一致していたので元から整数だった
（実機でも字形は 5 列すべて出ていた）。**半画素は縦だけで起きていた。**

### 直し

`FillSlot()` のペイン高を `kFontCellH` から **`kFontLinefeed`** へ。

### 再発防止

- 仕様書 §3.1 に**「中央整列ではペインの寸法と文字の寸法を一致させる」**を追記。
  必須記述の検査（`verify_spec_v2.py` 群 8）にも入れた（22 項目）
- `verify_plugin_port_v2.py` 群 8 に
  **「`FillSlot()` のペイン高が `kFontLinefeed` であること」**と
  **「`kAlignTB` の `%3` / `/3` を展開して表示する」**検査を追加
