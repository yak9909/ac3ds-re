## F-315: F-312〜F-314 を実機で検証。**結論はすべて正しかった** — HIGH

### A. `LIST_SIZE = 0x10000` は確保できる（2 回とも成功）

自前ノードのコマンドリストが両画面とも作れた。

```
上ノード list=42 / 下ノード list=43   投影済=1
```

### B. `LIST_SIZE` が **nngx ヒープからだけ**減ることを実機で確認（F-314 の裏取り）

| | 前 | 後 | 差 |
|---|---|---|---|
| nw::lyt 空き | 1,331,224 | 1,331,224 | **±0** |
| nngx 空き | 1,220,172 | 1,087,992 | **−132,180** |

予想 `2 x (0x10000 + 28x16) = 131,968` + ブロックヘッダ ≒ 一致。
**2 つは別のヒープ**という F-314 の結論が実機で裏付けられた。

### C. `0x50000` の借用も問題なし

```
借用 0x32EB0F60 / 0x50000
nw::lyt 空き 1,331,224 -> 1,003,524（差 327,700 = 0x50004 + ヘッダ 16）
ブロックヘッダ +0x0C = 0x50004   ← size + align（F-164 のとおり）
```

### D. **CMAP 方式 2 と CWDH が実機で完全に動いた**

「チートメニュー」の 7 字について、ゲームが計算した UV から字形番号を逆算し、
`font_ui_map.py` の期待値と突き合わせた。

| 字 | コード | 期待 | 実機 |
|---|---|---|---|
| チ | U+30C1 | 180 | 180 |
| ー | U+30FC | 246 | 246 |
| ト | U+30C8 | 183 | 183 |
| メ | U+30E1 | 197 | 197 |
| ニ | U+30CB | 185 | 185 |
| ュ | U+30E5 | 217 | 217 |
| ー | U+30FC | 246 | 246 |

**7/7 一致。** 幅（CWDH）も送りも期待どおり（幅 7 または 6、送り 8）。
**256x128 のシート**（従来 128x128）も扱えた。

### E. 1 文字あたりのコマンド語数の式が実機と ±2 語で一致

| 文字数 | 実機の語数 | F-313 の式 | 差 |
|---|---|---|---|
| 7 | 158 | 156 | +2 |
| 10 | 194 | 192 | +2 |
| 14 | 242 | 240 | +2 |

**一律 +2 語**（マテリアル選択の 2 語ぶん式が足りていなかった）。
式を `... + 2` に直せば完全一致する。下画面の記録長は 3,552 B。

### F. 取り外しも正常

`detach` → 記録長 0 → `Free` → フック復帰 → ゼロ埋め で
nw::lyt の空きが **1,331,224 B に完全復帰**した。
