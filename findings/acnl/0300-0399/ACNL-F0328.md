## F-304 (HIGH・実機) — ★`FINF+0x07` は**文字ストリーム読み取り器の選択**。1 以外だと PC=0 で落ちる

自前フォント資源（F-303）で実機が 2 回落ちた。**原因は 2 つあり、片方は解析結果、片方は私の操作ミス。**

### A. 1 回目 — `FINF+0x07` の意味を取り違えた（本物の知見）

```
sub_743A90(out, font):
    result = (font->vtable[0x48])(font)      ; slot18 = 0x743888 = *(u8*)(FINF + 0x07)
    if (result == 1) { out[1] = 0x004D7680; }   ; UTF-16 の読み取り器
    else             { out[1] = 0; }            ; ★関数ポインタが 0 のまま
```

呼び出し側（`DrawString 0x7E7FA4` と測定側 `0x7E7B78`）は
`out[1]` をそのまま `BLX` する。**0 なら PC=0。**

`0x004D7680` の実体:
```
LDR R1,[R0] / LDRH R2,[R1],#2 / STR R1,[R0] / MOV R0,R2 / BX LR   ; u16 を 1 個読んで進める
0x004D7694 は同じものの u8 版
```

**`FINF+0x07` は「行送り」ではない。必ず `1`。**
★実機のゲームフォントも `FINF+0x07 = 0x01` だった（F-299 で読んでいたのに取り違えた）。

判定は **PC=0 / LR=0x007E7B7C / R3=文字数** で付いた。

### B. 2 回目 — ★私の暗算ミス。**復帰させようとして壊した**

`sub_743A90` の逆コンパイル結果 `v3 = 5076608` を**暗算で `0x4D7BC0`** と読み、
そこへ `PC` を送って復帰させようとした。**正しくは `0x004D7680`**（差 1344 バイト）。

`0x004D7BC0` は `sub_4D7750`（nw::font のシェーダ初期化）の**文字列プールの中**
（`"dmp_TexEnv[3].scaleRgb"` 付近）。CPU が**文字列 552 バイトを命令として実行**し、
`sub_4D7750` の末尾 `0x4D7DE8 LDR R0,[R4]` でデータアボートした。

**途中の `STR` 相当が任意の番地へ書いた可能性があるので、プロセスの状態は信用できない。
この場合は復帰させず再起動する。**

> ★教訓（CLAUDE.md の既存ルールの再確認）:
> **10 進で出た値を暗算で 16 進にしない。必ずスクリプトで変換する。**
> とくに **`PC` を書き換える前**は、飛び先が本当に関数の先頭かを
> 逆アセンブラで確かめること。1 命令の取り違えでは済まず、
> **文字列を実行してメモリを壊す**。

### C. 復帰の可否の判定

| 状況 | 復帰 |
|---|---|
| 原因のデータを直せば命令が成功する（F-303 の null vtable） | **不可**だった（レジスタに古い値が残る） |
| レジスタを直す / `PC` を関数の後始末へ送る | **不可**だった |
| **正しい飛び先へ `PC` を送る** | 理屈では可。ただし**飛び先を必ず逆アセンブラで確認**してから |
| **暴走して任意番地へ書いた後** | **復帰させない。再起動する** |

判定材料は `LOG+0xE8`（毎フレーム増える計数器）。増えなければ止まっている。

### D. 反映

`PATCHES/own_font.py`:
- `FINF+0x07 = 1` に修正し、**書き込み後に読み戻して 1 でなければ中止**する
- 事前検査を追加（既定 TagProcessor `*(0x0097C0B4)` が 0 なら
  `sub_79B70C` と同じ値 `0x008FCA24` を入れ、ガード `0x0097C0B0` を 1 にする）
- `check_regions()`（F-303）と合わせ、**書き込む前に落ちる**構えにした
