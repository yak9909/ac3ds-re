## F-305 (HIGH・実機) — ★★★自前フォントで実機に描けた。`nw::font` の構造を**全欄**確定

F-303 / F-304 の 2 度のクラッシュを受けて、**推測を一切残さず**構造を確定してから適用した。
実機で「OWN FONT 0123 ABC」を**自前の 5x7 ビットマップフォント**で描画。
**コードケーブは 1 語も足していない。データだけ。**

### A. `ResFont` vtable 26 スロットの全数解析

**推測した欄は 1 つも無い。** 全スロットを 1 本ずつ逆アセンブルして読む欄を確定した。

### B. ★F-304 の真因を機械で確定 — 読み取り器は**表**から来る

```
0x743AAC  LDR  R1,[R1,#0x48]          ; slot18 = *(u8*)(FINF+0x07)
0x743AB0  BLX  R1
0x743AB4  CMP  R0,#1
0x743AB8  LDREQ  R0,=0x008AD9E8
0x743ABC  LDRDEQ R4,R5,[R0,#0x18]     ; ★表 0x008ADA00 から 2 語
0x743AC4  STRD  R4,R5,[R6,#4]
```

`0x008ADA00 = 0x004D7680`（関数）/ `0x008ADA04 = 0`（調整値）。
`0x004D7680` の実体は `LDR R1,[R0] / LDRH R2,[R1],#2 / STR R1,[R0] / MOV R0,R2 / BX LR`
＝ **UTF-16 を 1 文字読んで進める**。

**slot18 が 1 でなければ `R4=R5=0` のまま出力され、呼び出し側が `BLX 0` する。**
F-304 の `PC=0` はこれ。★即値ではなく**表**なので、逆アセンブルしないと分からない。

### C. CWDH を省く条件（実機で有効）

`slot15 0x7436F0` と `GetGlyph 0x7438B4` は、`FINF+0x0C`（CWDH）が **0 なら
`FINF+4` の 3 バイト**（left / glyphWidth / advance）を使う。
CWDH ノードの並びは `+0 begin(u16) / +2 end(u16) / +4 next / +8 から 3 バイト刻み`。

→ **固定幅フォントなら CWDH を作らなくてよい。**

### D. 自前フォントの設計（`PATCHES/own_font_data.py` が唯一の生成元）

| | 値 | 根拠 |
|---|---|---|
| シート | 128x128 LA4、8x8 モートン | — |
| セル | `cellW = cellH = 7`、刻み 8、16x16 = 256 マス | `U=(cellW+1)*列+1` に合わせる |
| 字形 | 5x7 を `(8*列+1, 8*行+1)` に置く | GetGlyph の 1 画素余白 |
| `FINF[0x15]` = 5 / `FINF[0x14]` = 7 | 要求 (5k, 7k) で**倍率がちょうど k** | slot2 / slot3 |
| `FINF[0x16]` = `TGLP[0x02]` = 7 | ApplyAlignment の `+ascent` と DrawString の `−baseline` が**相殺** | 0x7E7968 / 0x7E83E4 |
| `FINF[0x07]` = **1** | 読み取り器 | slot18 |
| `FINF[0x01]` = 8 | 行送り | slot9 |
| CMAP | 方式 0、`0x20`-`0x7E` → index `0`-`94` | 0x743768 |
| 記述子 `+0x04` | **ResFont 自身**（slot25 が `ResFont+0x10` を返す） | 0x4D6920 |

★ゲームのフォントも `FINF[0x16] == baseline`（18/18）で、これは任意の設計ではなく流儀。

   **総異常 0 件**

4. `own_font.py` の `check_regions()`（F-303）で領域の重なりを総当たり検査
5. 書き込み後に `FINF[0x07] == 1` と `FINF[0x16] == TGLP[0x02]` を**読み戻して**確認
