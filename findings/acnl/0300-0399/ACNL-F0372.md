## F-346（2026-09-07）: ★アトラス以外をプラグインの `.bss` へ移した（借用 442,368 -> 36,864 B）

**confidence: HIGH**（検証器 8 群 異常 0 件 / ビルド成功 / **実機で確認済み**）
★2026-09-07 実機確認: 描画は正常、**手紙も開ける**（利用者「手紙が開けました」）。
  F-345 で挙げた 3 つの未確認事項はすべて解消:
  (1) `.bss` 304,312 B の 3gx は読み込める
  (2) ゲームの描画スレッドはプラグインの `.bss` を問題なく読める
  (3) 手紙で落ちない
根拠: F-345 の「GPU が読むのはアトラスの画素だけ」

### 何を変えたか

`Sources/GuiV2.cpp`

| | 前 | 後 |
|---|---|---|
| 置き場 | 全部が借りた nw::lyt ヒープ | **アトラスだけ借用。ほかは `g_mem`（プラグインの `.bss`）** |
| `g_base` | 借りたヒープの先頭 | **`(u32)g_mem`** |
| `g_gpuBase`（新設） | — | 借りたヒープの先頭（アトラス専用） |
| `kPlugBytes`（新設） | — | `0x40000`（262,144 B）。`g_mem` の大きさ |
| `kBorrowBytes` | 0x50000（327,680 B） | **0x9000（36,864 B）** |
| `Layout()` | 1 本の連続領域 | **2 本に分離**。プラグイン側は `kPlugBytes` に、アトラスは借用に収まるか各々検査 |

`Install()` は `g_mem` を毎回ゼロ埋めしてから組み立てる。
アトラスだけ借りたヒープへ `memcpy` + `svcFlushProcessDataCache`（GPU は D-cache を見ない）。

### 収支

| 構成 | 借用 | 手紙の場面の空き | 手紙（262,528 B）のあと |
|---|---|---|---|
| F-325〜F-343 | 442,368 B | 47,636 B | **−214,892 B** |
| F-344 | 327,680 B | 162,324 B | **−100,204 B** |
| **F-346** | **36,864 B** | **453,140 B** | **+190,612 B** |

プラグイン側の配置 222,784 B（`kPlugBytes` の 84%）。
`.bss` は 42,080 -> 304,312 B、3gx 全体で 943,304 B。

### 検証器（群 4）に足した検査

- プラグイン側の配置が `kPlugBytes` に収まるか
- 借用にアトラス + 0x80 が収まるか
- `g_gpuBase + g_offAtlas` がソースにあるか（アトラスだけ借用起点）
- `g_base = (u32)g_mem` があるか（ほかはプラグイン側）

   （同一プロセスなので読めるはずだが、キャッシュの一貫性は実機で見るしかない。
