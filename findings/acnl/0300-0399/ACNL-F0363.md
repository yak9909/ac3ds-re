### 設計への含意

- 共有バッチなら位置は writer のカーソルで決まるので、
  **整列もアンカーも 0 にできる。F-322 の `/2` が経路から完全に消える**
  （★縦は `DrawString` が字ごとに `-行送り * 倍率Y` をかけているので、その分を勘定に入れる）
- 溢れの安全弁は自前で持つ（ゲームは黙って捨てる）
- アトラスを **2 枚に分けたときだけ**群が分かれ、描画順が「アトラスごと」になる

### ★★F-315 の実測値を静的模型から厳密に再構成できた（最強の裏取り）

F-315 の測定点は下画面の **7 / 10 / 14 字**。`48 x 字数` を引いた残りが**3 点とも 296 B ちょうど**。

```
吐き出し 1 回の固定費 = 16 + 16 + (16*4+16) + 16 + 64 = 192 B
提出の前置き 0x60                                    =  96 B
F-315 が式に足した「一律 +2 語」（マテリアル選択）      =   8 B
                                              合計 = 296 B  ★完全一致
```

独立に求めた 3 つの数が 296 に収束する。**偶然では合わない。**
F-315 の測定点はすべて 16 字以下なので、「16 字ごとに吐き出す」という予測と矛盾しない。

### ★実機で白黒がつく予測

色を変えない 1 本の文字列について `記録（ペイン除く）= 296 + 48n + 192 * (ceil(n/16) - 1)`。

| 字数 | 予測 |
|---|---|
| 16 | 1,064 B |
| **17** | **1,304 B**（★192 B 跳ねる） |
| 33 | 2,264 B（★また跳ねる） |

**16 字と 17 字を測るだけで吐き出しの模型が正しいか分かる。** 実機ゲートの測定に入れる。
