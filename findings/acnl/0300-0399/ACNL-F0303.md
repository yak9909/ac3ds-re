## F-278: 座標系を上下とも静的に確定した。**1 単位 = 1px、原点は画面中央**。`c4` は恒久的にゼロ — `HIGH`（静的、実機実測と一致）

### 1. 投影 uniform の `c4` は何か → **常にゼロ。我々に影響しない**

`nwlyt_Drawer_EmitProjectionUniform` が吐く 24 語を機械的に展開した。

```
0x28 値（uniform index）/ 0x2C ヘッダ 0x000F02C0
0x30 param0            / 0x34 ヘッダ 0x013F02C1（extra 19 → パラメータ計 20 語 = 5 個の vec4）
0x38..0x80  param1..19
0x84        8 バイト境界の詰め物（毎回 0 にされる）
```

| パラメータ | 実アドレス | 中身 |
|---|---|---|
| `c0`〜`c3`（16 語） | `0x30` と `0x38`〜`0x70` | 投影行列（`sub_148D30(a1+13, …)` が `0x34`〜`0x70` へ写し、`0x30` へ先頭語を移す） |
| **`c4`（4 語）** | **`0x74` / `0x78` / `0x7C` / `0x80`** | **`sub_4D5D1C` が LayoutMgr 初期化時に 0 を書く（`*(a1+116/120/124/128) = 0`）** |

行列のコピーは `0x34`〜`0x70` しか触らないので、**`c4` は初期化以降ずっと `(0,0,0,0)`**。
自前ノードの描画には一切影響しない。F-260 の未検証項目が 1 つ解消した。

### 2. ビューポートのレジスタが確定した

`LayoutMgr_SetDisplaySize` が出すヘッダ `0x803F0041` を復号すると

```
reg 0x041 / mask 0xF / extra 3 / consecutive
→ reg 0x041, 0x042, 0x043, 0x044 を連続で書く
   0x041 = h * 0.5      0x042 = 2.0 / h
   0x043 = w * 0.5      0x044 = 2.0 / w
```

`h` が「幅」側、`w` が「高さ」側に入る。**3DS のフレームバッファは 90 度回転していて、
物理幅 = 240、物理高さ = 400（上）/ 320（下）**なので、これで正しい。

同様に `Layout_ReplayRecordedList` の scissor ヘッダ `0x802F0065` は
`reg 0x065 / 0x066 / 0x067`（SCISSORTEST の mode / pos / dim）の連続書き込みだった。
F-262 の読みと一致する。

### 3. 座標系の完全な導出

投影行列（F-265 / F-266、回転後）は

```
NDC.x = (2/H) * y        NDC.y = -(2/W) * x
```

ビューポートは NDC ±1 を物理フレームバッファの ±半分へ写す。

| 画面 | W | H | 物理 FB | x=±W/2 | y=±H/2 | 1 単位 |
|---|---|---|---|---|---|---|
| 上 | 400 | 240 | 240 x 400 | ±200 px（画面横の端） | ±120 px（画面縦の端） | **1.0000 px** |
| 下 | 320 | 240 | 240 x 320 | ±160 px（画面横の端） | ±120 px（画面縦の端） | **1.0000 px** |

**F-208 の実機実測「下画面は x=±160 / y=±120 が画面端、等方 1 単位 = 1px、原点は中央」と
静的な導出が完全に一致した。** 上画面も同じ式から `x = ±200` が端になる。

したがって「上画面のレイアウト矩形を 400 幅としてよいか」という保留は解消した。
**我々が `+0x28` に入れた値が、そのままそのパスのビューポートと一致するので
1 単位 = 1px になる。** 400 は各パスの `SetDisplaySize(400,240)` と同じ値である。

### 4. スプライト表は上下とも画面に収まる

```
文字 11 個 / 間隔 24 単位 → x = -120 .. +120（グリフの半分を足して端は 132）
  上画面 使える範囲 ±200 → 収まる
  下画面 使える範囲 ±160 → 収まる
```

上画面用（`TOP_SPRITES`、y = -80）・下画面用（`SPRITES`、y = +72）とも問題ない。

### 5. F-124 の実機捕獲列と、今回復号した即値が全部一致した

| 即値 | 復号 | 捕獲列での役割 |
|---|---|---|
| `0x000F02B1` | reg `0x2B1` | `VSH_BOOLUNIFORM`（UV を使うか。`drawctx+1692` から） |
| `0x000F0227` | reg `0x227` | `INDEXBUFFER_CONFIG` |
| `0x000F0228` | reg `0x228` | `NUMVERTICES` |
| `0x000F02C0` | reg `0x2C0` | `VSH_FLOATUNIFORM_CONFIG` |
| `0x00BF02C1` | reg `0x2C1` extra 11 | `VSH_FLOATUNIFORM_DATA`（3x4 行列 12 語） |
| `0x0008025E` | reg `0x25E` mask 8 | `Commit` の 16 バイト境界合わせ（無害） |

**静的に復号した即値と、実機から捕獲したコマンド列が全項目で一致する。**
