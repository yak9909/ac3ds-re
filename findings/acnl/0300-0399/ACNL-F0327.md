## F-303 (HIGH・実機) — ★借りた nw::lyt ヒープは **GPU 可視**。自前フォント資源の設計を確定（描画は未達）

### A. ★★借りた `nw::lyt` ヒープは GPU から見える

これまでアトラスは `g_GfxAllocator`（`*(0x0094CA30)`）から `0x4000` 借りていた（F-166 / F-221）。
**そのヒープは 1 回漏らすと次の確保が 0 を返す**ことを今回実測した
（`cave_gfxalloc_probe.py` を install → resume → **読む前に uninstall** して番地を失い、
次の確保が `0` になった）。

そこで `alloc_lyt_heap.py` が借りる 128KB（`0x32EB0F60`）へアトラスを置き、
**実績のある Picture 経路で判定**した。

| | |
|---|---|
| アトラスの置き場 | ヒープ `+0x14020`（VA `0x32EC4F80`。**0x80 境界に乗せる**） |
| 結果 | **メニュー 184 枚が正常に描画された**（画面キャプチャで確認） |

→ **アトラス専用の確保はもう要らない。`g_GfxAllocator` の 0x4000 上限に縛られない。**
道具: `PATCHES/upload_atlas_heap.py`、`build_pane_tree.py` の `ATLAS_OFF`。

★VA は `0x80` 境界に揃えること（旧経路は align `0x80` で確保していた）。
ヒープ先頭が `0x...F60` なのでオフセット側でずらす。

### B. 倍率の決まり方（`RecomputeScale 0x4D51B0`）

```
0x4D51C8  LDR R1,[R0]        ; font の vtable
0x4D51CC  LDR R1,[R1,#8]     ; slot 2
0x4D51D0  BLX R1             ; = FINF[0x15]
0x4D51E4  LDR R1,[R1,#0xC]   ; slot 3
0x4D51EC  BLX R1             ; = FINF[0x14]
0x4D51F4  writer+0x24 (scaleX) = 要求幅 / FINF[0x15]
0x4D5200  writer+0x28 (scaleY) = 要求高 / FINF[0x14]
```

要求サイズは **`TextBox+0xE4`(幅) / `+0xE8`(高さ)**。
`ConfigureTextWriter` が `0x4BADA0 VLDM R2,{S0-S1}`（R2 = TextBox+0xE4）で渡す。

★実機のゲームフォントで検算: FINF[0x15]=18 / FINF[0x14]=24、要求 16.2 x 21.6
→ **倍率は縦横とも 0.9** できれいに揃う。

→ **`FINF[0x15] = glyphWidth`、`FINF[0x14] = cellH`** にしておけば、
要求サイズ `(glyphWidth*k, cellH*k)` で**倍率がちょうど k**（整数倍。F-281）。

### C. Y の決まり方

```
ApplyAlignment 0x7E7968:  writer.Y = y + slot4() * scaleY      ; slot4 = FINF[0x16]
DrawString     0x7E83E4:  描画Y   = writer.Y - slot19() * scaleY ; slot19 = TGLP[0x02]
→ 実効 Y = y + (FINF[0x16] - TGLP[0x02]) * scaleY
```

**`FINF[0x16] = TGLP[0x02]` にすると相殺し、y 引数がそのまま字の位置になる。**
★実機のゲームフォントも `FINF[0x16] = 18` / `baseline = 18` で**一致していた**。
つまりこれは任意の設計ではなく、**このライブラリの流儀**。

### D. 自前アトラスの作り方（`PATCHES/make_font_nwfont.py`）

既存の `make_font_atlas.py` は**自前スプライト表用**で、字形をセルの `(x+1, y+0)` に置く。
`nw::font` は `U = (cellW+1)*列 + 1` / `V = (cellH+1)*行 + 1` で参照するので
**上にも 1 画素の余白が要る**。基準版を壊さないよう生成物は全部別名にした。

| | |
|---|---|
| シート | 128x128 LA4（8x8 モートン、1 バイト/画素）= `0x4000` |
| セル | `cellW = cellH = 7`、刻み 8、16 列 x 16 行 = 256 マス |
| 字形 | 5x7 を `(8*列+1, 8*行+1)` に置く。`glyphWidth = 5`、`advance = 6` |
| 対応 | ASCII `0x20`-`0x7E` を **CMAP 方式 0** で index `0`-`94` へ（コード順に並べる） |

検証 4 本（このファイル単体で完結）: 詰め直し照合 / UV がシートに収まるか /
方式 0 の写像 / 余白が消えているか — **全部 OK**。字形あり 61・空セル 34。

### E. ★★事故 — バッチがフォント資源を上書きしてゲームが止まった

最初に置き場を **文字列 `0x10280` / バッチ `0x10300` / ResFont `0x11800`…** と並べた。
**バッチは文字数で伸びる**（`sub_4D5480`）。17 文字で `0x18B0` バイトなので
`0x10300 + 0x18B0 = 0x11BB0` となり、**`0x11800` のフォント資源を丸ごと踏んだ**。
書き込み順もバッチが後だったため、ゼロで塗り潰した。

結果:

```
0x4D51C8  LDR R1,[R0]      ; R1 = *(ResFont) = 0
0x4D51CC  LDR R1,[R1,#8]   ; ★番地 8 でデータアボート
```

**復旧できなかった。**

- メモリを正しい値へ直しても、**アボートした命令はレジスタに残った 0 を再実行し続ける**
- `R1` に正しい vtable を書いても進まない
- `PC` を関数の後始末（`0x4D5204 VPOP`）へ進めても進まない
- `LOG+0xE8`（毎フレーム増える計数器）が **12314 のまま**で止まっていることを確認

→ `DOCS/crash_recovery.md` §3-2 の「復旧できないとき = 再起動」に該当。

### F. 再発防止

`own_font.py` に **`check_regions()`** を入れた。
全領域を `(名前, 開始, 大きさ)` で並べ、**総当たりで重なりと領域超過を検査**し、
1 件でも当たれば**書き込まない**。バッチの大きさは文字数から計算して渡す。

配置も「小さい固定物を先、伸びるバッチを最後」に変えた:

```
0x10000 TextBox / 0x10200 Material / 0x10280 文字列
0x10380 ResFont / 0x103A0 FINF / 0x103C0 TGLP / 0x103E0 CMAP / 0x10400 記述子
0x10800 バッチ（伸びる。旧アトラス 0x14020 の手前まで = 最大 39 文字）
0x14020 旧アトラス / 0x18020 自前アトラス
```

> ★教訓: **大きさが入力で変わる領域を、固定オフセットの一覧に目視で並べない。**
> F-287（リングが自前 TEV を潰した）と同じ型の事故。**機械検査を必ず付ける。**
