## F-280: ★★★★★メニューを実際に描けるところまで実装した（フォント・レイアウト API・領域拡張） — `HIGH`（静的のみ・未適用）

これまで描いていた「ACNL GUI OK」は**デモ**であって、メニューには足りなかった。
理由と対策を順に潰した。

### 1. 既存のアトラスは 9 文字しか入っていなかった

`PATCHES/font_atlas_64x64_la4.bin`（実機のバッファから吸い出したもの）を
8x8 のマスに割って非ゼロ画素を数えたところ:

```
     0    1    2    3    4    5    6    7
0   18   13   18   12   17   16   18   14     ← A C N L G U I O
1   14    0    0    0    0    0    0    0     ← K
...
7    0    0    0    0    0    0    0   64     ← 塗り潰し
```

**「ACNL GUI OK」を出すためだけの 9 文字＋塗り潰し。** これでは何も書けない。

### 2. `PATCHES/make_font_atlas.py` — 128x128 の ASCII アトラスを作る

- 5x7 の字形を 61 文字ぶん定義（空白・A-Z・0-9・`.,:;!?-+*/=<>()[]#%&_|^@`）
- 8x8 のマスに左 1 画素の余白を入れて配置。16x16 = 256 マス
- **マス (15,15) は塗り潰し**（枠・カーソル用）
- 3DS のテクスチャ形式に合わせ、**8x8 タイルのモートン順**で LA4 に詰める

出力:

| ファイル | 中身 |
|---|---|
| `PATCHES/font_atlas_128x128_la4.bin` | 16384 バイト |
| `PATCHES/font_charmap.py` | 文字 → (列, 行) |
| `Plugin/.../includes/GuiFontAtlas128.h` | プラグイン用。バイト列と `kGuiCharmap` |

**検証**: 書き出したバイト列を読み直してビットマップへ戻し、
元の字形と 1 画素ずつ突き合わせた。**不一致 0 件**（未使用マスがゼロであることも確認）。

### 3. 描画レイアウト API（`cave_node_record.py`）

```python
uv_cell(c, r)                    -> (u0, v0, u1, v1)   u0=c/16, v0=1-r/16 …
rect_sprite(cx, cy, w, h)                              塗り潰しの矩形 1 枚
text_sprites(s, cx, cy, gw, gh, adv)                   中央揃え
text_sprites_left(s, x_left, cy, gw, gh, adv)          左揃え
pack_groups([(色, スプライト列), ...]) -> (一覧, チャンクごとの色)
```

**★色はチャンク（7 枚）単位でしか変えられない**（`build_q` の `COLOR_IDX`）。
`pack_groups` は各色グループを 7 の倍数まで大きさ 0 のダミーで埋めて、
**チャンク境界と色の切れ目を必ず一致させる**。

### 5. `.bss` を広げた（根拠つき）

従来の表は下 `0x600` バイト（19 枚ぶん）しかなく、メニューには**まったく足りない**。

**使ってよい根拠を 3 つ突き合わせた。**

1. 実機ダンプ `code_runtime.bin` の `0x9B0000`-`0x9B8000` は**全部ゼロ**
2. ダンプ全域を 4 バイト整列で走査し、この範囲を指す語を探すと 4 件だけ当たるが、
   いずれも**連続した数値表の一部**（誤検出）だった

   ```
   0x841F44: 0x0099310F / 0x009A310F / 0x009B310F / 0x009C3610
   0x8A9C00: 0x005D0800 / 0x001D0800 / 0x009B0900 / 0x00530714
   ```

   隣の要素が `.bss` の外なので、ポインタ配列ではない
3. `0x9B0D00`-`0x9B5E00` は現行設計が既に使っていて**実機で確認済み**（F-255 / F-256）

**★ただし `0x9B0900` を指す語があるので `0x9B0D00` より下は使わない。**

```
0x9B0D00  LOG         0x100
0x9B0E00  COLORS_BOT  0x400   16 チャンク x 0x40
0x9B1200  COLORS_TOP  0x400   16 チャンク x 0x40
0x9B1600  （予備 0xA00）
0x9B2000  TABLE       0x2000  102 枚（1 枚 20 語 = 0x50 バイト）
0x9B4000  TABLE_TOP   0x1000  51 枚
0x9B5000  （予備 0x100）
0x9B5100  NODE_TOP / VTBL / NODE_BOT / MATBUF / RING / MATCMD（従来どおり）
```

### 6. 導入前の検査を追加した（`_check_layout`）

**黙って隣（ノードや vtable）を踏み潰すのが最悪**なので、必ず例外にする。

- 表が容量に収まるか（下 7280/8192、上 2240/4096）
- 色の本数がチャンク数と一致するか（下 13、上 4。上限 16）
- `CHUNK` と `CHUNK_HINT` が一致するか
- **`.bss` の全 11 領域どうしの重なり**
- `0x9B0D00` より下を使っていないか

`MODE = "install"` の先頭で必ず走る。

### 7. テクスチャを 128x128 へ

```
TEX_W = TEX_H = 128        TEX_BYTES = 0x4000（16384）
reg 0x082 TEXUNIT0_DIM  = 0x00800080   (128<<16)|128
reg 0x08E TEXUNIT0_TYPE = 9            LA4
```

確保済みバッファは `0x4000` なので**ちょうど収まる**（`TEX_VA + オフセット` を
使う箇所は無い。`OWN_BUFFERS`（F-263）と `LIST_BUF_*`（F-261）は既に廃止済み）。

`SOLID_UV` も 8x8 グリッド時代の `(0.875, 0.125, 1.0, 0.0)` のままだと
128x128 では 2x2 マス（うち 3 マスは空）を指すので、`(0.9375, 0.0625, 1.0, 0.0)` に統一した。

### 8. `PATCHES/preview_layout.py` — 実機なしで見た目を確かめる

F-278 で確定した写像（原点=画面中央、1 単位 = 1px）と、生成したアトラスの字形を使って、
スプライト表を**画面のピクセル座標へ落として ASCII で描く**。

等倍で出すと文字が読める。実際に確認した結果:

```
タイトル     ACNL MENU
1 行目       WALK SPEED
2 行目       MOVE ANYWHERE
```

**外接矩形**（ダミーを除く）:

```
下画面 x -150..150（端 ±160）/ y -100..100（端 ±120）  収まる
上画面 x -131..131（端 ±200）/ y -101..-91（端 ±120）  収まる
```
