## F-312: Simulator の 2 フォントを `nw::font` へ載せた（日本語 275 字を含む）— HIGH

### A. 何を作ったか

`PATCHES/make_font_ui.py`。Simulator が使う 2 フォントを**1 枚のシートに同居**させ、
`nw::font::ResFont` を 2 つ作れる形にした。

| | |
|---|---|
| 美咲ゴシック第2 8px | **362 字（うち日本語 275 字）**。可変幅（送り 4〜8） |
| PixelMplus10 数字 8px | 27 字（`0-9 A-F a-f x X . -` 等）。5x8 固定 |
| シート | **256x128 LA4（32,768 B）**。8x8 タイルのモートン順 |
| セル | 幅 7 / 高さ 8。刻みは `cellW+1 = 8` と `cellH+1 = 9` |
| 格子 | 32 列 x 14 行 = 448 セル（使うのは 390） |
| 字形番号 | 通し。美咲 `0..361` / PixelMplus `362..388` / **塗り潰し `389`** |

★字形の出どころは**プラグインが既に持っている 1bit の表**
（`MisakiGothic2nd8.cpp` / `PixelMplus10Numeric8.cpp`。Simulator の抽出ツールが公式 BDF から作ったもの）。
**新たに字形を起こしていない。**

### B. 静的解析で確定した 2 つの機構（どちらも初使用）

#### CMAP 方式 2 — ソート済み対の二分探索（`MapCharToGlyph 0x743768`）

```
+0x00 u16 begin / +0x02 u16 end / +0x04 u16 方式 / +0x08 u32 次
方式 0: 字形 = *(u16*)(node+0x0C) + code - begin
方式 1: 字形 = ((u16*)(node+0x0C))[code - begin]            … 表引き
方式 2: +0x0C = 件数、+0x0E から (code, 字形) の対。**二分探索**
```

**日本語のようにコードが散らばる場合は方式 2 の 1 ノードで足りる。**
方式 0 のノードを連ねる必要は無い。

#### CWDH — 字形番号で引く可変幅（`GetGlyph 0x7438B4` / `slot15 0x7436F0`）

```
+0x00 u16 begin（★コードではなく字形番号）/ +0x02 u16 end / +0x04 u32 次
+0x08 から 1 件 3 バイト: left / glyphWidth / advance
    entry = node + 3*(字形番号 - begin) + 8
```

**1 ノードで字形番号 0..389 を覆えば全部の可変幅が入る**（1,178 バイト）。

★`left` は使わず **0 固定**にし、`offsetX` はセル内の画素位置へ焼き込んだ。
`glyphWidth = offsetX + width` にすれば、`left` が効く実装でも効かない実装でも同じ絵になる。
`offsetY` も同じくセル内へ焼き込んである。

### C. 検証（6 本。すべてオフラインで 0 件）

| | |
|---|---|
| 1 | 詰めたバイト列を読み直して画素へ戻し、元の 1bit 表と 1 画素ずつ比較 |
| 2 | 全字形の `U + glyphWidth <= 幅` / `V + cellH <= 高さ` |
| 3 | 字形の画素が元表と一致 |
| 4 | セルの余白（0 行目・0 列目）が全部消えている |
| 5 | **CMAP 方式 2 の二分探索をゲームと同じ手順で写経**し、全 389 字で一致 |
| 6 | 塗り潰しのセルの内側が全部点灯 |

目視でも `チートメニュー` / `変更を適用しますか？` / `プレイヤー` が正しく出た。

### D. ★ここで分かった容量の壁（次の設計を決める）

Simulator の UI をそのまま TextBox で組むと**破綻する**。

| | |
|---|---|
| 上画面に同時に出る文字 | 10 行 x 約 24 字 + 見出し・脚注 約 40 字 + 説明パネル 約 180 字 ≒ **460 字** |
| TextBox を 1 文字列 1 個で持つ | スロット容量の合計が必要。上 24 枠 x 32 字 + 下 8 枠 x 44 字 = **476,160 B** |
| **記録コマンドリスト** | 460 字 x 83 B ＝ **38,180 B** > `LIST_SIZE 0x8000` の 8 割 = 26,214 B |

→ **2 つとも変える必要がある。**

1. 文字は**基準仕様 v2 §3.2 の TextWriter 直呼び**（F-306。実機成功済み）へ。
   F-308 のとおり **1 本のバッチに複数の文字列を積める**。
   スロットごとの容量ではなく**同時表示の総字数**だけを確保すればよい。
2. **`LIST_SIZE` を上げる**。仕様書 §4.7 の「文字を増やす前に `LIST_SIZE` を増やす」に従う。

★当初ここに「上げられるかは実機で測る」と書いたが、**それは誤り**だった。
  **F-313 で静的に決着した。実測は要らなかった。**
