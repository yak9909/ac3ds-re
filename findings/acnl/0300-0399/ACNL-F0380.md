## F-354（2026-09-07）: ★タッチは 2 か所にある — hold の中のビットも消す（実機確認済み）

**confidence: HIGH（実機で確認。利用者「誤反応が消え、ロック中は完全に無反応、
ロックしていない時は正常です」）**

### 症状

下画面ロック中に**特定の位置を触ると、画面左上が反応する**（持ち物ボタンにフォーカス）。

### 実機の計測（ロック中・触ったまま Suspend）

```
装置 0x32943FEC:  +5588 X=87 / +5590 Y=122 / +5592 タッチ中=1
CtrController:    +0x10  = 0x00000000     ← 旗は消せている
                  +0x110 = 0x00008000     ← ★タッチのビット（番号 15）が残っている
                  +0x14/+0x18 位置 = 87,122
Wrapper:          +0x10 = 0 / +0x110 = 0 / +0x108 = -1
                  +0x14/+0x18 位置 = 111,119   ← 更新されず**古い値**
```

### 原因

**タッチは 2 か所に書かれる。`sub_542D78` が両方を書く。**

| | 場所 |
|---|---|
| (1) タッチ中の旗 | `+0x10` bit0 |
| (2) hold の中の 1 ビット | `+0x110` の `1 << *(int*)(this + 0x108)`（この機体では **15**） |

F-352 で「落とすビットを列挙する」方式（`KEEP = ~BUTTONS`）へ変えたとき、
**タッチのビット 15 を「残す」側に入れてしまった**。
その結果ロック中も (2) が立ちっぱなしで、
それを見た経路が「押されている」と判断。位置は別経路の**古い値**を使うので、
実際に触った場所とは無関係な所（左上）が反応した。

### 直し

ケーブに (2) の消去を追加。**ビット番号は決め打ちせず `+0x108` から読んで
`1 << n` を作って落とす**（負なら何もしない）。18 語 -> 28 語。

```
LDR  R12,[R0,#0x108]     タッチのビット番号
CMP  R12,#0
BLT  no_tp               負なら hold にビットを持たない
PUSH {R4}
MOV  R4,#1
LSL  R4,R4,R12           R4 = 1 << 番号
LDR  R12,[R0,#0x110]
BIC  R12,R12,R4
STR  R12,[R0,#0x110]
POP  {R4}
```

### ★教訓

- **1 つの入力が複数の場所に書かれることがある。**
  「旗を消したから遮断できた」と思い込まず、**その入力を書く関数を全部読む**。
  `sub_542D78` を最初に読んでいれば 1 回で気づけた。
- **「残すものを選ぶ」も「落とすものを列挙する」も、知らない項目で事故る。**
  F-351 は前者で、F-354 は後者で踏んだ。**書き手（`sub_542D78`）から列挙するのが正しい。**
- 症状の「左上が反応」は、**押下の判定と位置の取得が別経路**だったため。
  片方だけ塞ぐと、もう片方の古い値が使われる。

### 実機で確認できたこと

1. 左上の誤反応が消えた
2. ロック中はタッチが完全に無反応
3. ロックしていないときは正常
