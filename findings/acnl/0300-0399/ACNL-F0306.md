### ノイズの原因 — 非整数倍の拡大

元アトラスは 8px。それを 14px（1.75 倍）で描いていた。
最近傍サンプリングなので **元 1 画素が出力 1px と 2px に割れる**。

```
8 -> 14 (1.75倍)  元画素ごとの出力画素数 = [2,1,2,2,2,1,2,2]   ★不均一
8 -> 10 (1.25倍)  = [1,1,2,1,1,1,2,1]                          ★不均一（上画面）
8 -> 16 (2.00倍)  = [2,2,2,2,2,2,2,2]                           均一
8 -> 24 (3.00倍)  = 全部 3                                      均一
```

F-208 で一度踏んだ「一部の線が 1px、一部が 2px」と同じ症状である。

### 直したもの

- 文字を **16px（8px のちょうど 2 倍）固定**に（`MENU_GLYPH`）
- 上画面は 1 行だと `29 文字 x 送り 14 + 16 = 408px` で 400px を超えるので **2 行**に分割
  （`SELECT = MENU` / `SELECT+UP = LEGACY`）
- 送りは整数倍でなくてよい（位置がずれるだけで拡大率には関係しない）。`MENU_ADV = 12`

**★教訓: 拡大率は必ず元テクセルの整数倍にすること。送りは自由でよい。**

### 検証（適用前）

`preview_layout.py` と同じ写像で、文字だけを描いて**横方向のラン長**を数えた。

```
幅  2 px : 1074 本    幅 4 px : 58 本    幅 6 px : 12 本
幅  8 px :   76 本    幅10 px :106 本
→ 奇数幅のラン = 0 本
```

**すべて偶数＝線幅が完全に均一。** 2 倍固定が効いていることの機械的な証拠。

監査 0 件・リテラル検査 0 件・アトラス画素照合 0 件・配置検査 OK。

### 適用の仕方 — `PATCHES/update_tables.py` を追加した

見た目だけを変えるときに**ケーブもフックも vtable も触らない**ための道具。
`.bss` のスプライト表・色配列・`LOG` のポインタだけを書き換える。
登録ケーブが毎フレーム `+0x11D` を立てるので、次のフレームで自動的に記録し直される。

実機での結果:

```
下表 1820 語 -> 009B2000  不一致 0
上表  560 語 -> 009B4000  不一致 0
表[16] 幅=41800000 高=41800000     ← 16.0（2 倍化が反映）
```

### 補足 — 記録リストの余裕

下画面は 91 枚で **11536 / 16384 バイト**（`LIST_SIZE = 0x4000`）を使う。
1 枚あたり約 127 バイト。表の容量は 102 枚なので、
**満杯にすると約 13000 バイト**になり、まだ収まるが余裕は少ない。
**枚数を増やすときは `LIST_SIZE` も上げること。**
