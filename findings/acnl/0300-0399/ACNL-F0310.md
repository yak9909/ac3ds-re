## F-286 — F-283 / F-285 を捨てて **F-282（実機で描画に成功した版）へ巻き戻した** — `HIGH`（静的検証済み・実機未確認）

実機で描画に成功した CTRPF プラグインの最後の版は **F-282**（利用者報告
「3gx はゲーム上で問題なく動作しました」）。F-283 は真っ黒→クラッシュ（F-284）、
F-285（別エージェントの修正）は「文字が全部板」「全体が明滅」。そこで F-282 へ戻した。

**巻き戻す前のものは `BACKUP/f283_f285_20260904/` に保存**（`f285_broken.3gx` も含む）。

### 判明したこと

**`cave_node_record.py` のメニュー内容は F-283 でも F-282 のままだった。**
F-283 で変えたのは**容量と `.bss` 配置と `LIST_SIZE` だけ**で、
UI の作り込みは全部 C++ 側にあった。だから巻き戻しは 13 定数の差し戻しで済んだ。

| 定数 | F-283 | → F-282 |
|---|---|---|
| `COLORS_TOP` / `COLORS_MAX` | 0x9B1E00 / 64 | **0x9B1400 / 24** |
| `TABLE` / `TABLE_BYTES` | 0x9B2E00 / 0x1400 | **0x9B1A00 / 0x0C00（38 枚）** |
| `TABLE_TOP` / `TABLE_TOP_BYTES` | 0x9B4200 / 0x9000 | **0x9B2600 / 0x2A00（134 枚）** |
| `NODE_TOP`/`VTBL`/`NODE_BOT` | 0x9BD200/D400/D500 | **0x9B5100/5300/5400** |
| `MATBUF`/`RING`/`MATCMD` | 0x9BD700/D800/D900 | **0x9B5600/5700/5800** |
| `LIST_SIZE` | 0x10000 | **0x8000** |

### 併せて直したもの（描画に影響しない安全側）

1. **`export_gui.py` が `kGuiSolidCol`/`kGuiSolidRow` を出すのをやめた。**
   F-282 は `GuiFontAtlas128.h` を include するので、そちらの `unsigned char` 版と
   **型違いの二重定義**になる。F-283 でアトラスの include を外したときに足したもの。
2. **`export_gui.py` に `kGuiLogFrames = 0xE8` を追加。**
   CAVE_F（`DrawCtx_FlushBatch` フック）が数える「ゲームが描いた回数」で、
   **フックが生きている間だけ増える**。
3. **`OwnGui.cpp` の取り外し順序を直した。**
   別エージェント版は `LOG+0x00`（カウンタではない）を読み、しかも
   **フックを外したあとに**増加を待っていた。外したら誰も数えないので永久に進まない。
   → **フックを外す前に** `LOG+0xE8` の増加を確認し、増えなければ
   （Pause 中の疑い）**ケーブを消さない**。外したあとは 100ms 待ってからゼロ埋め。
   `Enable()` の二重実行ガードと「`InstallHooks()` 失敗時にケーブを消さない」
   （F-284 対策）はそのまま残した。

### 実機へ入れるときの注意

**先に F-285 の版を外し、本体を再起動してから入れること。**
古いフックが `.text` に残ったままだと `InstallHooks()` が「素ではない」で弾く。

詳細は `scratchpad/MEMO_f286_rollback.md`。
