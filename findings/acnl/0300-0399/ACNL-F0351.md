利用者の指示で段 6・段 7 を進めた。アニメーションは利用者が実機で確認済み
（問題なし。`HANDOFF_CHEATMENU.md` と `BASELINE/gui_v2_ok_f322/README.md` に記録）。

### 入れたもの（Simulator の写し）

- 上画面リストボックス / 下画面リストボックス（8 行・見出し・スクロール・
  スライドイン。汎用 + ホットキー項目用）。メニューを閉じているときも
  ホットキー発動で上画面に開く。
- ホットキー設定（Y で下画面に入力待ちを開く）・発動（閉じているときに
  一致したら実行）。行に H 印、説明パネルに `HOTKEY:xxx`。
- 通知（上画面右下・キュー・押し上げ・出入りスライド）。X 適用・
  ダイアログ確定・ホットキー発動・セーブ実行で積む。
- `ACT_SAVE` / 上画面リスト / 下画面リストのアクションを配線
  （従来は何も起きなかった）。

### 意図した差（Simulator と違うところ）

1. **通知は同時 2 件まで**（Simulator は 7）。矩形・文字・記録・借用の
   予算のため。3 件目以降は一番古いものを押し出す（queue は保つ）。
2. **入力待ちの A/B/X は記録しない**（A=決定 / B=取消 / X=無効）。
   Simulator はマウスで押すが 3DS は十字キー操作のため手段を残す。
   A/B/X 単体や含む組み合わせは設定できない。
3. **value/slider のホットキー発動は +1 して即適用**（無通知）。
   下画面の数値 UI を移植しないため。
4. 文字キーボード系アクションのホットキー発動は何もしない（同上）。
5. 入力待ち・リストの角は四角い（丸角プリミティブが無い）。
6. はみ出す行は描かない（従来通りの切り抜き無し方針）。

### 予算の変更

- 文字スロット: 上 50 本 -> 65 本 / 下 2 本 -> 11 本。
  項目名・下帯は 24 字枠 -> 16 字枠へ移した（Trim が画素幅で切る前提）。
  ASCII ばかりの長い名前だけ溢れる（壊れない）。
- Picture: 画面あたり 36 枚 -> 56 枚（128 枚 -> 112 枚）。
- 借用 0x60000 -> **0x6C000**（配置 438,784 B）。
  最悪時の空き 738,876 B（F-310）に照らすとゲームへ約 296KB 残る。
  300KB の目安をわずかに割るので、**場面転換の soak で見ること**。
- 上画面 `LIST_SIZE` 0x18000 -> **0x20000**（記録の最悪値 82,488 B が
  上限 78,643 B を超えるため。`export_gui_v2.py` を直して再 export）。
  下は据え置き（23,064 B <= 26,214 B）。nngx の空きは十分（F-318）。
- ケーブの中身は不変（LIST_SIZE は実行時に焼き直す値）。
  `audit_node_cave.py` の対象外。`verify_plugin_port_v2.py` 8 群 0 件、
  `verify_spec_v2.py` 8 群 0 件、`gohan.3gx` 再ビルド済み。
