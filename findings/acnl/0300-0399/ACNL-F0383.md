## F-357（2026-09-08）: ★FPS だけ上げてゲーム速度を据え置くことはできない（実機計測つき）

confidence: **HIGH**（静的にループ構造を確定 + 実機で周期を計測）

利用者の問い「ゲームの進行スピードを変えずに FPS のみ制限をとっぱらう事が可能か」への回答。
詳細は `scratchpad/MEMO_f357_fps_vs_speed.md`。

**結論: この設計では不可能。FPS とゲーム進行は同じ 1 個のつまみ。**

### 1. メインループが 1:1（`sub_54C818` -> `Framework_MainLoop`）

```
+0xA0 = VBlankCount() ; +0xB0 = tick ; +0xB8 = tick
loop:  vtbl[0x64](this)   ; スロット 25 = sub_54C424 = 1 フレーム分
       B loop
```

`sub_54C424` の中は **Calc(スロット27 `0x5498B4`) -> Draw(スロット26 `0x549944`) ->
リスト入替(スロット30 `0x54C5D8`) -> フレーム周期の記録 -> 待ち＋提示(スロット31 `0x54C684`)**。
**1 反復 = Calc 1 回 = 提示 1 回**で、論理と描画を別レートで回す仕組みが無い。

### 2. フレームワークは経過時間をゲームへ渡していない

Calc の入口は `sub_54B79C` -> `sub_543BD0` -> `MethodTree_WalkAndInvoke(node)` で**引数はノードだけ**。
フレーム所要時間 `+0xA8` の読み手は **スロット 19 `0x005497D4` = `getFPS()`** だけ
（`(float)qword_96F3F0 / (float)this+0xA8` を `FDIVS`）。表示用であって論理には効かない。

### 3. 実機計測（`tickFreq = 268,111,856 Hz` / 1 VBlank = 16.715 ms）

フレームワークオブジェクト = `0x32939880`（この boot）。

| 設定 | 周期 | fps | 待ち+提示 |
|---|---|---|---|
| `+0x70 = 2`（素） | 33.837 / 33.652 / 33.789 ms | 29.55 / 29.72 / 29.60 | 17.42 / 17.78 / 17.62 ms |
| `+0x70 = 2`（戻したあと） | 33.751 ms | 29.63 | — |
| **`+0x70 = 1`（1.5 秒だけの実験）** | **17.770 ms** | **56.28** | **1.743 ms** |

- **`this+0x70 = 2` を実機で確定**（F-356 の宿題を解消）。2 VBlank 待ち = 30fps。
- **周期の比 33.751 / 17.770 = 1.899 倍**。論理:提示が 1:1 なので**進行も 1.9 倍速**。
- `calc+draw` の実作業 = **14.935 / 15.634 ms（平均 15.28 ms）= 1 VBlank 予算の 91.4%**。
  だから `+0x70=1` でも 60fps に届かず **56.3fps** で頭打ちだった。
- ★この 15.28 ms は**いま映っている 1 場面のもの**。場面をまたぐ一般化はしていない。

### 4. 測り方（コード注入なし）

`sub_54C424` が毎フレーム `+0xB0` に、`Framework_WaitAndPresentFrame` が末尾で `+0xB8` に
`svcGetSystemTick` を刻む。停止した瞬間の前後関係で読み分ける:

| 条件 | 意味 |
|---|---|
| `+0xB8 > +0xB0` | 同一フレームの **待ち+提示** = `+0xB8 − +0xB0` |
| `+0xB8 < +0xB0` | 待ちの最中に止まった。**calc+draw** = `+0xB0 − +0xB8` |

`+0xA8` は常にフレーム周期（待ち込み）。
★**止めたまま置くと `+0xA8` に停止時間が混ざる**（`svcGetSystemTick` は止まらない）。
必ず「走らせる -> 時間切れで止める -> 読む」を 1 往復にすること。

### 5. 案の評価

| 案 | 判定 |
|---|---|
| `+0x70 = 1` | 60fps を狙えるが**進行も 2 倍**。この場面では実測 56.3fps 止まり |
| `0x0054C6E8` を `MVN` に（F-356） | 待ちが全部消える。**同じく進行も速くなる** |
| ループをフックして Calc を 2 回に 1 回 | 提示は増えるが**同じ絵の 2 度出し**。30fps と区別できない。**無意味** |
| ゲーム側の毎フレーム増分を全部半分に | 数千か所 + romfs のアニメ資源も 30fps 前提。**非現実的** |
| フレーム間補間 | エンジンに仕組みが無い。**不可** |

★**逆（遅くする）は綺麗にできる。** `+0x70` は整数の VBlank 数なので
3 = 20fps / 4 = 15fps と、**1/N のスローがデータ 1 語で作れる**（コード改変なし）。

### 6. 実機の後始末

`+0x70` は 2 に戻し、`0x0054C6E8` が `E59400A0`（素）であること、bp が 0 個であることを確認済み。
