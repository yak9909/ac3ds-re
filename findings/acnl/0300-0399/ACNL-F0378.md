## F-352（2026-09-07）: ★実機報告 2 件 — タッチのビットを消していた（修正）／ SELECT は未解決

利用者の報告:
1. 「メニューを開いてる間**常に下画面が無効**になります」
2. 「**SELECT が無効になっていません**。メニューを閉じたときのボタン復帰に巻き込まれている？」

### 1. タッチが死ぬ — ★こちらのマスクの誤り（原因確定・修正済み）

**タッチは `+0x10` の旗だけでなく、`+0x110`（hold）のビットにも入る。**

```c
// sub_542D78（タッチを書き込む）
v7 = *(_DWORD *)(result + 264);          // = +0x108。タッチのビット番号
if ( v7 >= 0 ) {
    if ((a2 & a3) == 0) *(+272) &= ~(1 << v7);   // 触っていない
    else                *(+272) |=  (1 << v7);   // ★触っている
}
```

F-350 のケーブは `AND R12,R12,#0xF00000`（スライドパッドだけ残す）だったので、
**ボタン遮断が立つと同時にタッチのビットまで消えていた**。
症状「メニューを開いている間ずっと下画面が無効」はこれで完全に説明できる
（暗幕は出ないので、暗くはならず反応だけ死ぬ）。

**修正**: 「残すものを AND で選ぶ」のをやめ、**既知のボタンのビットだけを落とす**。

```
BUTTONS = A|B|X|Y|ZL|START|SELECT|L|R|十字4 = 0x000F789B
KEEP    = ~BUTTONS                            = 0xFFF08764   ← これを AND する
```

これならタッチのビットにも、スライドパッドにも、未知のビットにも触らない。

★**教訓: 「残すものを選ぶ」マスクは、知らないビットを巻き込む。**
  「落とすものを列挙する」ほうが安全。

### 2. SELECT — ★未解決

ケーブは旗に関係なく `BIC R12,R12,#0x1000` を毎フレーム実行しており、
`sub_540870` の対応表では **HID bit2（SELECT）-> sead 0x1000** で間違いない。
また 1 の症状はケーブが確実に動いていることを示している
（ボタン遮断の旗が立ったときだけタッチが死んだのだから）。

にもかかわらずゲームに届いているなら、**ゲームは SELECT を
この `sead::CtrController` 以外の経路から読んでいる**ことになる。

**未確認。実機で測る必要がある**:
- SELECT を押しっぱなしにして `CtrController(+0x110)` と `Wrapper(+0x110)` を読む
- 落ちていれば別経路。落ちていなければケーブが効いていない

`input_block_cave.py` / `GuiCavesV2.h` / 検証器を修正して再ビルド済み。
