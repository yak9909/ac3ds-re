## F-297 (HIGH・実機) — ★下画面のペインツリーを組んだ。**上下 2 画面が独立した輪で同時に描かれる**

F-295 の時点では下画面のノード（`0x9B5400`）は用意だけされていて
root Pane の子リストが空だった。ここへ 2 本目の輪を組んだ。

### 分かったこと — 投影行列は **Layout ノードの +0x28/+0x2C** で決まる

`ssys::ma::lyt::Layout::SetupProjectionMatrix`（`0x567BC0`、vtable +0x18）は
`sub_73BAC0(&rect, layout+0x10)` で矩形を取る。その中身は

```
0x73BAC4  v2 = *(float*)(a2 + 24)      ; = *(float*)(layout + 0x28)  画面幅
0x73BACC  v3 = *(float*)(a2 + 28)      ; = *(float*)(layout + 0x2C)  画面高
          l = -W/2, t = +H/2, r = +W/2, b = -H/2
```

つまり **root Pane の大きさではなく Layout ノードの +0x28/+0x2C** が
正射影の範囲を決める。`layout+0x121 == 1` なら透視射影になるが、
自前ノードは 0 なので正射影。

実機の自前ノードは既に **TOP = 400.0 x 240.0 / BOT = 320.0 x 240.0** で、
`+0x0C` 優先度 `0xFF`、`+0x100` リスト id 44 / 45、
`+0x134` display は TOP `0x410` / BOT `0x401` と揃っていた。
**下画面が出ていなかったのは root の子リストが空だっただけ**で、
ノード側の設定はすべて正しかった。

### 組み方

`build_pane_tree.py` の Picture 配置ループを 2 画面ぶんに一般化した。

- Picture 群は**ヒープに連続で並べる**（上画面ぶん → 下画面ぶん）
- **輪は root ごとに独立**。各 Picture の `+0x04`（次）は自分の root の番兵
  `root+0x14` を指し、`+0x08`（前）は同じ輪の一つ前を指す
- 中央原点への写像 `to_center` に**その画面の幅・高さ**を渡す
  （上 400、下 320）。ここを取り違えると横に 40px ずれる
- Material と texMap は**上下で共有**してよい（描画中は読むだけ）

### 容量 — 64KB では足りず 128KB へ広げた

| | 枚数 |
|---|---|
| 上画面（メニュー） | 74 |
| 下画面（説明＋ホットキー） | 110 |
| 合計 | **184** |

`0x10000` の上限は 185 枚で、余りが 1 枚しかなかった。
**F-296 の解放機構を実際に使って** detach → free → `SIZE = 0x20000` で確保し直した。
128KB なら 371 枚。**借り直しは実機で問題なく通り、同じ番地が返ってきた。**

### 下画面は上画面より不透明にする

全面を覆うので、上画面と同じ α `0xC7` だと
「PRESS A BUTTON」や著作権表示が透けて読みづらかった（実機で確認）。
`COL_BOT_PANEL = 0xF20D100C`（α `0xF2`）にして解消。

### 実機での結果

- 記録長 上 `0x38D0` / **下 `0x5580`**、投影済みフラグは上下とも 1
- 輪を歩いた子の数は 上 74 / 下 110 で**置いた枚数と一致**
- Resume を 5 秒挟んだ独立キャプチャ 2 枚の画素差は
  **全体 0.1% / 説明文の帯 0.0%**（残る 0.1% は α 5% ぶんの背景の透け）

### ★連写では明滅を測れない（測定手法の訂正）

`grab_screen.ps1 -Shots 8` は下画面で「差 0%」を返したが、
**動きのある上画面を対照に撮っても 0%** だった。
連写中は Chokistream のウィンドウが再描画されないので、
**連写の差分は明滅の証拠にならない。**
明滅を見るときは **Resume を挟んだ独立キャプチャ同士**を比べること。
