## F-31 【完成】隣マス掘りが中心マスと完全同期 — `HIGH`

3 箇所のフックで、穴・抉れ・土しぶきのすべてが中心マスと同じタイミングで出る。
実機で確認済み。

| 領域 | 範囲 | 命令 | 用途 | フック | 元の値 |
|---|---|---|---|---|---|
| A | `0x66336C`-`0x6633CB` | 24 | 穴（アクター+マップ） | `0x5A09EC` | `EBFFE245` |
| B | `0x6632F0`-`0x66332B` | 15 | 地面抉れ | `0x65BD58` / `0x65BDEC` | `EB004E09` / `EB004DE4` |
| C | `0x663298`-`0x6632B7` | 8 | 土しぶき | `0x65BD2C` | `EB041950` |

いずれも `0x663294` のパッチ（無条件 B）で死んだ `Shovel_DecideState` 内の領域。

### 到達までに潰した誤りの記録

| 版 | フック | 誤り |
|---|---|---|
| v1 | `0x598688` | R0-R3 を復元せずテールジャンプ → クラッシュ (F-16) |
| v2 | `0x598688` | PUSH 後に BL するとスタック引数がずれる (F-20) |
| v3 | `0x598688` | 中心の対象アイテムを隣に渡し `Item_SameId` で不成立 (F-22) |
| v4 | `0x598688` | 判定は通るが反映側が 1 マスしか見ない (F-24, F-25) |
| v5 | `0x59E9CC` | レコードを積んでも同上 |
| v6-v8 | `0x59E9CC` | 穴は出るがタイミングが「刺す」と同時 |
| v10 | `0x65BD84` | まだ早い（抉れパーティクルの直後より前） |
| v11 | `0x5A09EC` | アクターのみでは**穴が見えない** |
| **v12** | `0x5A09EC` | **アクター生成 + マップへ 158 の両方が必要**。完成 |

**要点**:
- **穴の見た目・実体はマップデータの 158**。アクターは動き・付随効果を担う
- **タイミングを合わせるには、中心マスが処理している当人をフックする**。
  手前の段階（アクション決定・レコード登録）ではどうしてもずれる
- 戻り値 `R0` は呼び出し元が `EOR R5,R0,#1` で使うので必ず復元する
