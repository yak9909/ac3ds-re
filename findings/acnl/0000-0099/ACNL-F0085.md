## F-47 `0x596890` の実態 — 踏みつけ処理 `FieldObj_TrampleAt` — `HIGH`

`REFERENCES/CHEATS/outdoor.txt` の「歩いた場所の物を消す」が書き換えるアドレス。

**`0x596890` の素の値は `EBF5990F` = `BL Item_GetCategory`。**
`FieldObj_TrampleAt` (`0x59683C` - `0x5969D8`) の中にある。

### 関数の役割

**プレイヤーが通ったマスの植物を踏み荒らす処理。** 呼び出し元は `0x64D068`（`sub_64CFA4` 内）の **1 箇所だけ**
（プレイヤー更新の中。引数 `a4`/`a5` は `VCMPE.F32` の結果から作られる真偽値＝速度判定）。

```
FieldObj_TrampleAt(X, Y, a3, a4, a5)

 1. unk_2F75E4(4, unk_2F75CC()) と a3 & a5 のゲート
 2. Field_GetItemAtXY(mapmgr, X, Y, 0) → 無ければ return
 3. Item_GetCategory() == 29 なら return          ← ★0x596890 はこの BL
 4. unk_59BD54(X, Y)                              （副作用のみ。戻り値は捨てている）
 5. v15 = (unk_76DE88(*0x9566E8) == 1)
 6. Item_IsFlowerCategory(cat) でも cat == 19 でもなければ return
 7. a3 & a4 & ~v15 が 0 なら return
 8. R4 = (Math_RandFloat(100.0) <= 12.5f)         ← ★12.5% の抽選
 9. FieldObj_PlayPlantEffect(item, X, Y, R4)      （音とパーティクル）
10. R4 == 0 なら return                            ← 87.5% はここで終わり
11. ネットワーク中なら sub_623F80(71, 4, &rec, 8) で送信
12. Field_SetItemAt(X, Y, 0, pNo, &g_EmptyItem)   ← ★マスを空にする
13. Field_MarkDirty(X, Y, 1)
```

### 12.5% の抽選

```
005968E8  MOV   R4, #0
005968EC  VLDR  S0, =100.0
005968F0  BL    Math_RandFloat        ; S0 = rand01() * 100.0
005968F4  LDR   R1, =0x41480000       ; 12.5f
005968F8  VMOV  R0, S0
00596900  CMP   R0, R1
00596904  MOVLE R4, #1
```

`CMP` は float のビットパターンを符号付き整数として比べているが、
**非負 float では IEEE754 のビット列が大小関係を保つので正しい。**

`Math_RandFloat` (`0x565030`) は `0x96F400` を状態とする乱数で 0..1 を作り引数を掛ける。
直後の `0x565054` が `(rand01 - 0.5) * 2.0 * max` という対称版になっているのが
「0..1 を返す」ことの裏付け。呼び出し元 **87 箇所**の汎用ヘルパ。

### 対象になるオブジェクト

`Item_IsFlowerCategory` (`0x2FCE5C`) は
カテゴリ **{11,12,13,14,15,16,17,20,27,28}** で真。**19 は含まない**ので
呼び出し側が `|| cat == 19` を足している。呼び出し元は 9 箇所。

定義テーブル（実機実読）から該当 ID を引くと **連続した 1 ブロック**になる:

| cat | 件数 | ID |
|---|---|---|
| 11 | 7 | `0x9F`-`0xA5` (159-165) |
| 12 | 6 | `0xA6`-`0xAB` (166-171) |
| 13 | 6 | `0xAC`-`0xB1` (172-177) |
| 14 | 8 | `0xB2`-`0xB9` (178-185) |
| 15 | 1 | `0xBA` (186) |
| 16 | 3 | `0xBB`-`0xBD` (187-189) |
| 27 | 6 | `0xBE`-`0xC3` (190-195) |
| 28 | 4 | `0xC4`-`0xC7` (196-199) |
| 17 | 1 | `0xC8` (200) |
| 20 | 2 | `0xCA`-`0xCB` (202-203) |
| 19 | 42 | `0xCE`-`0xF7` (206-247) |

**`0xB2` は cat 14。** ユーザーが「植えられた赤いバラ」と呼んでいたものと一致する。
つまり **花などの地面植物**が対象。

`FieldObj_PlayPlantEffect` (`0x1703A8`) 側も
`Item_GetId(item) - 159 < 89` で **ID 159-247** に限定していて、上の範囲と正確に一致する。
`g_PlantEffectTable` (`0x859254`) は u16 × 89 × 2（前半＝壊れない時、後半＝壊れた時）で、
並びがカテゴリの区切りと一致する（先頭 7 個、次 6 個、次 6 個…）。

### チートが何をしているか

| 書き込む値 | 意味 |
|---|---|
| `EA00001D` | `B loc_59690C` — **手順 3〜8 を全部飛ばす** |
| `E3A0001D` | `MOV R0, #0x1D` — 直後の `CMP R0,#0x1D` が成立して `BEQ loc_5969D0` |

**ON (`EA00001D`)**: カテゴリ判定も、速度判定も、12.5% の抽選も無視する。
`R4` は `a3` のまま（非ゼロ）なので `CMP R4,#0` を必ず通過し、削除まで進む。
→ **通ったマスの物が種類・確率を問わず必ず消える。**

**OFF (`E3A0001D`) は復元ではない。** `0x596890` の素の値は `EBF5990F` であって
`E3A0001D` ではない。この値を書くと関数が即 return するので、
**踏みつけ処理そのものが死ぬ**（花を踏んでも荒れなくなる）。
元に戻すにはゲーム再起動か `EBF5990F` の書き戻しが要る。

### ON にしたときの副作用

`0x59690C` へ飛ぶと `MOV R2, R6`(Y) と `MOV R3, R4` を通らないので、
`FieldObj_PlayPlantEffect(item, X, R2, R3)` の **第 3・第 4 引数が不定**になる
（直前の `Field_GetItemAtXY` が `PUSH {R4-R11,LR}` する実関数なので R2/R3 は破壊される）。
削除自体は `R5`/`R6` を使うので正しい座標で行われるが、
**音とパーティクルは意図しない座標・種別で出る可能性がある。**

### 「A ボタン押している間置く」(同ファイル) について

同じ関数を使い、`0x5969E4`（`Field_SetItemAt` に渡すアイテムポインタのリテラル、
素の値は `0x00955FF4` = `g_EmptyItem`）を差し替えて「消す」代わりに「置く」に変える発想。

```
00596890 E3A0001D   常時: 踏みつけ処理を無効化
00596870 E1A00000   A中: 初期ゲートの BEQ を NOP
00596890 1A000015   A中: BNE loc_5968EC（カテゴリ判定を飛ばして抽選へ）
005968D0 E1A00000   A中: NOP
005968D8 E1A00000   A中: NOP（cat 19 判定を潰す）
00596920 E1A00000   A中: 抽選に外れても続行
00955FF4 000000C8   A中: g_EmptyItem をアイテムID 200 に
```

**ただし `005969E4` を書き換える 2 行（`0A000039` / `00A00000`）は `00955FF4` を
書き換える行と矛盾する。** ポインタを `0x00A00000` に向けるなら `g_EmptyItem` の値は
使われないし、`0x0A000039` は未マップ領域を指す。
少なくとも一方は不要か誤り。**未検証。**
CLAUDE.md の「1 チートに含まれるアドレス行がすべて必要・関連しているとは限らない」に該当する。

### 補足 — 呼び出し元の数え方

当初 `code_runtime.bin` を Python で走査して ARM の `BL` だけを数えたが、
**Thumb からの呼び出しを取りこぼしていた**（`Item_IsFlowerCategory` を 7 件と誤った。正しくは 9 件。
`0x10494C` と `0x2FB0B6` が Thumb 側）。

**静的 IDB (idalib) の `xrefs_to` を使うこと。** ARM/Thumb 両方と data 参照を拾う。
自前のブルートスキャンは、そのエンコードしか見ていないことを忘れると静かに間違える。
