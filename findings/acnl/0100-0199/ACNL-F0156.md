## F-118: ★★注入した描画が画面に出ることを視覚的に確認。影は「アルファのみ」

> **【後日訂正】本項 §3 の「重ねがけが濃くならないのは深度テストで落ちるから」という
> 仮説は F-120 で否定された。** 深度テストは最初から無効（`0x107 = 0x00000F40`）で、
> 合成は SRC_ALPHA / ONE_MINUS_SRC_ALPHA。理由は未解決（TODO-83）。

confidence: **HIGH**（実機。ユーザーの目視 + メモリ実測）

TODO-75 / TODO-79 の締め。**「積んだコマンドが本当に絵になるのか」**を確定させた。

### 1. コールバックは空振りしていない

`GpuCmd_Advance` の直前（`0x28E964`）に bp を置き、引数 `R0` = 積んだ総バイト数を読んだ。

```
R0 = 21360 バイト (0x5370)
   固定分 = 4128（既製ブロック）+ 456（頂点属性リセット）= 4584
   差分   = 16776 バイト ← ★影本体の描画コマンド
```

**`BsShadowViewMgr_BuildShadowCmds` は毎フレーム 16KB 以上の描画コマンドを積んでいる。**
`vc_POINT1`(`0x948DE8`) も非 0（`0x3309BE14`）で、早期 return していない。

### 2. ★視覚的な確認 — アルファは効く、RGB は効かない

`BsShadowViewMgr` の色フィールドを書き換えて実機で目視。

| 書き換え | 結果 |
|---|---|
| `*(mgr+176)` アルファ基準値 `120` → `255` | **影が明らかに濃くなった** |
| `*(mgr+38..40)` RGB `00 00 26` → `FF 00 00` | **色は変わらなかった** |

**★これで「このコールバックが積んだコマンドは確実に画面に出ている」が確定した。**
自前描画も同じ経路で見える。

一方、**TexEnv0 の定数色は RGB が使われていない。**
combiner がアルファだけを参照する構成になっていると考えられる（`MEDIUM`）。
F-114 で「色は TexEnv0 の定数色に入る」と書いたが、
**実際に絵を左右しているのはアルファだけ**だった。

### 3. ★重ねがけしても濃くならない理由（`MEDIUM`）

`SUBMITS = 8`（同じノードを 8 回登録）を実機で試した。

| 指標 | 結果 |
|---|---|
| `ctx[2]` の要素数 | **8**（`0x30896220` ×8）— 登録は成立 |
| 見た目 | **変化なし** |
| 速度 | **変化なし**（ユーザー目視） |

**同じ深度に同じ形を描くので、2 回目以降が深度テストで落ちていると考えるのが自然。**
早期 Z 棄却なら重くならないこととも整合する。

**★重要な含意:** 自前描画を「既存ノードの真似で同じ場所に重ねる」形にしても見えない。
**別の位置・別の深度に描く必要がある。**

### 4. 取り下げる観測

F-117 の直後に「`SUBMITS=8` でフレームが遅くなった」（ベースラインは 5 秒で
`0x1B72E4` に到達、8 回では 8 秒で未到達）と書いたが、
**ユーザーの目視では速度変化なし。**
bp 到達時間はフレーム内のどこで再開したかに依存するため、単発観測では判断できない。
**この「遅くなった」は取り下げる**（CLAUDE.md「一度の観測を一般化しない」）。

### 5. 復元

書き換えたのは 4 バイトのみで、元の値（`+38..40 = 00 00 26`、`+176 = 120`）へ復元済み。
パッチも uninstall 済み（フック `0xE92D4010`、ケーブ全ゼロ、bp 0 件）。

### 6. 次への含意

| 分かったこと | TODO-81 への影響 |
|---|---|
| コマンドは画面に出る | 自前コールバックは**見える** |
| 同じ深度に重ねると落ちる | **深度を変えるか、深度テストを切る**必要がある |
| 影は 16KB/フレーム積んでいる | 自前分の予算は十分ある（空き約 850KB） |
