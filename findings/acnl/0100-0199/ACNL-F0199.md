## F-173: 発行点への注入は成功したが GPU が固まった。捕獲した列は自己完結していない — `HIGH`（実機、フリーズ）

適用: `PATCHES/cave_replay_draw.py`

### 1. やったこと

F-172 で特定した発行点へ、実際にコマンドを注入した。

1. **捕獲**: `0x4B7DCC` で `[R9-64, R0)` を 1 回だけ `.bss` へ写した。
   **504 バイト（126 ワード）取れた。** 構造も確認済み:
   - `[0]=0x80000020` `[1]=0x000F02C0` `[3]=0x00BF02C1` → 状態プリフィックス（3x4 行列）
   - 行列の平行移動は X=`-177.0`、Y=`-89.36`
   - `[16]=0x80000023` `[17]=0x000F02C0` `[19]=0x00FF02C1` → TextBatch ヘッダ
2. **再生**: `GpuCmd_SplitAndSubmit`(`0x1280CC`) の入口で
   `g_GpuCmdPtr` へ 504 バイトを書き、`g_GpuCmdPtr` を進めた。
   境界検査（`g_GpuCmdPtr + len <= g_GpuCmdEnd`）付き。

### 2. 結果 — 描画スレッドが固まった

- **音は鳴り続ける**（オーディオスレッドは生きている）
- **画面が更新されない。入力も効かない**（描画/メインスレッドが停止）
- `PC = 0x00463E24`（ケーブ外。無限ループではない）
- **`g_GpuCmdPtr` が前回値から 1 バイトも進んでいない**
- `mgr` の `len == submitted`、キュー件数 12 で据え置き

**フックを外して再開しても復帰しなかった。**
原因を取り除いても解けない = **GPU / GX キュー側が固まっている。**
3DS の再起動が必要だった。

### 3. 原因の見立て（未確定）

**捕獲した列は自己完結していない。**

batch はブレンド・TexEnv・テクスチャを自分で持つが、
**頂点属性の配列設定（regs `0x200`-`0x226`）は入っていない**（F-167 で確認済み）。

`reg 0x227 INDEXBUFFER_CONFIG` は列に入っており、その値はオフセット 0。
だが**オフセットの基準は `reg 0x200` VTX_ATTR_ARRAYS_BASE_ADDR** で、
それは我々の列に無い。

`GpuCmd_SplitAndSubmit` の時点でどの基準が設定されているかは不定なので、
**GPU が無効なインデックス／頂点を読みに行って停止した**と考えられる。

F-167 で「グリフに頂点データは無い」と分かっていたが、
それは**位置と UV が定数から来る**という意味であって、
**`DRAWELEMENTS` 自体はインデックスバッファと頂点配列を使っている。**
1 グリフ 6 頂点という数もそれを示している。**ここを取り違えていた。**

### 4. 次にやること

**頂点配列の設定を含めて捕獲する。**

`mgr[1]`（リスト先頭）と `mgr[3]`（現在長）が読めるので、
**1 フレーム分のコマンドリストを丸ごと吸い出して
regs `0x200`-`0x226` がどこで設定されているかを探せる。**
実測では base=`0x3229D0C0`、len=`0x1CF50`（118,608 バイト）。

見つかったら、その設定を自前の列の先頭に足す。

### 5. 教訓

**「自己完結している」と判断する前に、
その描画が依存する状態を全部列挙すること。**
今回は batch にブレンドやテクスチャが入っていたので自己完結と思い込んだが、
**入っていないもの（頂点配列）を数え上げていなかった。**

失敗の代償が「絵が出ない」ではなく **「GPU が固まって再起動」**だったので、
この種の確認は事前にやる価値がある。
