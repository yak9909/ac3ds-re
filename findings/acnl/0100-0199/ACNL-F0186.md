## F-160: テキスト描画の座標系を確定。F-158 の「1.25 = 400/320」は誤り — `HIGH`（実機で基準行列を採取＋3 枚の配置と照合）

### 1. 対象自身の基準行列（`T_nam_00` の live 実測）

`0x4B7DCC` で `[R9-64, R9)` の 16 ワードを控えて得た:

```
row0 = ( 1.0, -0.0, 0.0, -126.000000)
row1 = ( 0.0, -1.0, 0.0,   -4.999957)
row2 = ( 0.0, -0.0, 1.0,   -1.000000)
```

- `matrix[3]`  = **-126.0** 平行移動 X
- `matrix[7]`  = **-5.0**   平行移動 Y
- `matrix[11]` = **-1.0**   平行移動 Z
- 列 1（index 1/5/9）が負 = `sub_73CE64` による **Y 列の反転**

### 2. ★F-158 の訂正 —「1.25 = 400/320」は誤り

F-158 で `matrix[0] = 1.25` を「上画面 400px と nw::lyt 320 の比」と解釈したが、
**本項の対象では `matrix[0] = 1.0`。**

前回の 1.25 は 3 秒走行後に**最後に描かれた別のテキスト**のステージングを読んだもので、
`T_nam_00` の値ではなかった（`drawctx+37` が 7 で、別の呼び出し元由来だった）。

**`matrix[0]` は pane ごとの拡大率であって全体比ではない。**
行内が `(x, y, z, w)` 順であるという結論自体は、
Y 列の反転位置と平行移動の加算位置から独立に裏付けられており、変わらない。

### 3. ★「ずらす」のではなく「絶対位置を設定する」

`matrix[3]` / `matrix[7]` は**上書き**なので、書いた値がそのまま絶対位置になる。
狙った位置に置くには基準行列を知る必要がある。

実機で 3 枚を配置して確認:

| 描画 | `matrix[3]` X | `matrix[7]` Y | 観測された位置 |
|---|---|---|---|
| ゲーム本来（緑） | -126（基準） | -5（基準） | 最も左 |
| 我々・青 | -60 | 40 | 緑の右、赤の左。**緑より少し上** |
| 我々・赤 | 40 | 0 | 最も右 |

左右の並び `-126 < -60 < 40` が観測順と一致。
`matrix[7]` を -5 → 40 にすると上へ動いたので、**`+X` は右、`+Y` は上**。

（`row1` の Y 列が -1 でレイアウト空間の Y 下向きを反転しているため、
ここで書く平行移動はクリップ空間と同じ向き = Y 上向きになる。）

### 4. 単位

`matrix[3] = -126` で画面内に収まっていることから、**クリップ空間ではなくレイアウト単位（ピクセル相当）**。
射影は頂点シェーダ側の別の定数で当たっている。

### 5. これで揃ったもの
