## F-121: ★★TODO-84 第1段 — 積まれたコマンドを自分で解釈・書き換え、描画結果を狙って変えられた

confidence: **HIGH**（実機。数値と目視の双方で確認）

F-120 で「自前ノードから描ける」ところまで来た。次は**描かれる内容を自分で決められるか**。

### 1. やったこと

`PATCHES/cave_own_funcnode.py` の `CB_MODE="scale"`。自前コールバックが:

```
P0 = GpuCmd_GetProperty(0x208)        書き込み位置を記録
BsShadowViewMgr_DrawCallback()        影の描画コマンドを積ませる
P1 = GpuCmd_GetProperty(0x208)        積まれた範囲を確定
for (p = P0; p < P1; p += 4)
    if (*p == 0x00BF02C1)             ← PICA のヘッダ形式を自分で解釈
        *(p + PATCH_OFF) += EXP_ADD   ← float の指数部演算（+0x00800000 = ちょうど 2 倍）
        HITS++ / LASTHDR = p
```

**毎フレーム 73 個の行列がヒットする**（`HITS / COUNTER = 73.0`）。

### 2. ★構造の確定 — メモリから読んで解いた

`LASTHDR` にヒット位置を記録し、停止後にその周辺を読んだ。

| 位置 | 値 | 意味 |
|---|---|---|
| `hdr-16` | `0x78260000` | 影の色（アルファ `0x78` = 120） |
| `hdr-12` | `0x000F00C3` | ヘッダ = `GPUREG_TEXENV0_COLOR` |
| `hdr-8` | `0x80000019` | **uniform 番号 25**、bit31 = f32 モード |
| `hdr-4` | `0x000F02C0` | ヘッダ = `VSH_FLOATUNIFORM_CONFIG` |
| `hdr+0` | `0x00BF02C1` | ヘッダ = `VSH_FLOATUNIFORM_DATA`（extra 11 = 12 ワード） |
| `hdr+4`〜`hdr+44` | 12 float | uniform c25 / c26 / c27 |

**PICA の f32 uniform は `w, z, y, x` の順で送られる。** これを当てはめると 3×4 行列になる:

| | x | y | z | w（平行移動） |
|---|---|---|---|---|
| 行0 (c25) | `100.0` (`hdr+12`) | 0 | 0 | `2643.0` (`hdr-4`) |
| 行1 (c26) | 0 (`hdr+28`) | -0.996 | 6.286 | `-486.92` (`hdr+16`) |
| 行2 (c27) | 0 (`hdr+44`) | -0.090 | -69.71 | `-43.91` (`hdr+32`) |

### 3. ★実験と結果

| `PATCH_OFF` | 対象 | 数値 | 画面 |
|---|---|---|---|
| `-4` | 行0 の w（平行移動） | `2643 → 5286` | 影が消え、**遠くの影が画面内へ寄ってきた**（動く生物の影が出現） |
| `+16` | 行1 の w（平行移動） | `-486.92 → -973.83` | 影が消えた |
| `+12` | **行0 の x（拡大縮小）** | `100.0 → 200.0` | **★影が横に引き伸ばされ、位置は変わらず** |

**3 番目が狙いどおり。任意の要素を狙って変形できることが確定した。**

### 4. ★副産物 — 影はテクスチャ投影で描かれている

`PATCH_OFF=+12` のときユーザーが観察した内容:

- 影が横に引き伸ばされた（位置はそのまま）
- **左に少し傾いた**
- **横に伸びた分、影が上下からループするように描画された**

**ループするということは、単純なジオメトリの拡大ではなくテクスチャ参照であり、
ラップモードが REPEAT になっている。**
つまりこの 3×4 行列は**サンプリング座標に効く投影行列**。
傾きは、1 行だけ変えたことで他の行の交差項（行1 の z = 6.286、行2 の z = -69.71）
との組み合わせが崩れ、剪断が生じたためと考えられる（`MEDIUM`）。

### 5. F-114 の訂正

F-114 で「`0x00BF02C1` は 12 ワード = 3×4 行列」と書いた点は**結論としては正しかった**が、
**要素の並び順を取り違えていた。** `w, z, y, x` の順を知らなかったため、
最初に触った `f0` と `f4` は両方とも**平行移動成分**で、
2 倍にすれば画面外へ飛ぶのが当然だった。

**教訓: PICA の f32 uniform 転送順（w,z,y,x）を知らずに float 列を行列として読むと、
成分の意味を取り違える。**

### 6. 手法上の知見

- **視覚での総当たりは往復が高くつく。** メモリから構造を読んで絞り込むほうが速い
- 置換ではなく**相対変化（指数部 ±1 = ×2 / ÷2）**にすると、
  元の値の大きさを知らなくても安全に試せる
- `LASTHDR` のように**ヒット位置を記録するだけ**の 1 命令を仕込むと、
  停止後にいくらでも周辺を読める。トレース用ケーブの最小形

### 7. 現在の状態

パッチは **uninstall 済み**（フック `0xE92D4010`、ケーブ全ゼロ、bp 0 件）。
`PATCH_OFF` / `EXP_ADD` / `CB_MODE` / `KEEP_ORIGINAL` / `SUBMIT_OWN` の 5 フラグで
本項の全条件を再現できる。
