## F-120: ★★★TODO-81 達成 — 自前の `FuncNode` から実際に画面へ描画できた

confidence: **HIGH**（実機。ユーザーの目視による決定的な A/B）

### 1. ★★決定的な 3 条件の対照実験（陰性対照つき）

`PATCHES/cave_own_funcnode.py` のフラグを切り替えて 3 条件を実機で比較した。
**陰性対照はユーザーの発案。** これがあることで結論が厳密になった。

| 条件 | `KEEP_ORIGINAL` | `SUBMIT_OWN` | 影ノードの登録 | `COUNTER` | **画面** |
|---|---|---|---|---|---|
| ベースライン | — | — | ゲーム本来のみ | — | 影あり |
| **A** | `False` | `True` | **自前ノードのみ** | 451 → 902（毎フレーム） | **影あり** |
| **B（陰性対照）** | `False` | `False` | **なし** | **0** | **影なし** |

- **A**: ゲーム本来の `Scene_SubmitNode` を NOP 化し、自前ノードだけを登録。
  そのコールバックが `BsShadowViewMgr_DrawCallback` を呼ぶ
- **B**: 本来も自前も一切登録しない（ケーブが全 NOP）。
  `HOLDER[1] = 0`（ノード生成すらしていない）、`COUNTER = 0`

**B で影が消えたことにより「影は別経路でも描かれている」可能性が排除された。**
したがって **A で見えていた影は、自分で生成したノードが
自分のコールバックから描いたものであると厳密に確定する。**

これで一連の到達点がすべて繋がった:

| 段階 | 確認 |
|---|---|
| ノードを任意のシーンへ追加できる | F-116（`ctx[1] n=1`） |
| 何個でも追加でき破綻しない | F-117（`ctx[2] n=8`） |
| **自前ノードを生成できる** | F-119（`vptr = vtbl_g3d_FuncNode`） |
| **自前コールバックが毎フレーム呼ばれる** | F-119（`COUNTER = 62 / 2 秒`） |
| **自前コールバックが GPU コマンドを積める** | F-120（`BL` の次に到達） |
| **★その結果が画面に出る** | **F-120（条件 A で影あり、陰性対照 B で影なし）** |

### 2. 自前描画コールバックの構成（実機で動作）

```asm
; 到達時 R0 = g_DrawContext, R1 = userdata
PUSH {R4,LR}
LDR  R2, =COUNTER          ; 診断用
LDR  R3, [R2]
ADD  R3, R3, #1
STR  R3, [R2]
LDR  R1, =&g_BsShadowViewMgr
LDR  R1, [R1]
CMP  R1, #0
POPEQ {R4,PC}
BL   BsShadowViewMgr_DrawCallback   ; ★実際の描画（21360 バイトを積む）
POP  {R4,PC}
```

`0x01E81680`。**この形がそのまま自前描画のひな型になる。**
`BL` の先を自前のコマンド生成に差し替えれば、任意の絵を描ける。

### 3. ★F-118 の深度仮説を否定する

既製ブロック（`*(mgr+0xB4)`、1032 dword）の描画ステートを実測した。
**ブロックは 59 種類のレジスタを触っている。**

| レジスタ | 位置 | 値 | 意味 |
|---|---|---|---|
| `0x111` `FRAMEBUFFER_FLUSH` | `@996` | `1` | — |
| `0x110` `FRAMEBUFFER_INVALIDATE` | `@998` | `1` | — |
| `0x100` `COLOR_OPERATION` | `@1002` | `0x00E40100` | mask 0x3 |
| `0x101` `BLEND_FUNC` | `@1004` | `0x76760000` | **SRC_ALPHA / ONE_MINUS_SRC_ALPHA** |
| `0x104` `FRAGOP_ALPHA_TEST` | `@1010` | `0` | 無効 |
| `0x105` `STENCIL_TEST` | `@1012` | `0xFF00FF10` | 無効 |
| `0x107` `DEPTH_COLOR_MASK` | `@1016` | **`0x00000F40`** | **深度テスト無効・深度書き込み無効**、カラーマスク `0xF` |
| `0x112`/`0x113` colorbuffer R/W | `@1024`/`@1026` | `0xF` | — |
| `0x114`/`0x115` depthbuffer R/W | `@1028`/`@1030` | `0` | — |

**`0x107` の bit0 = 0（深度テスト無効）、bit12 = 0（深度書き込み無効）。**

**F-118 §3 で書いた「重ねがけが濃くならないのは深度テストで落ちるから」は誤り。**
深度テストはそもそも切ってあり、合成は標準のアルファブレンド。
理屈のうえでは 2 回描けば濃くなるはずで、観察との食い違いは**未解決**（TODO-83）。

考えられる説明: A/B を別ターンで見比べたため差が分かりにくかった
（アルファ 120 = 0.47 の 1 回に対し 2 回で 0.72 相当。
`+176` を 255 に上げたときほど劇的ではない）。

### 4. 実務上の知見

- **既製ブロックのステートは全部そこに書いてある。**
  自前描画でパイプラインを組むときは、この 59 レジスタの並びが最良の手本になる
- ブロックはメモリ上の生バッファなので、**値を書き換えれば挙動を変えられる**
  （`0x107` を書き換えれば深度テストを有効化できる、など）
- コールバックから既存の描画関数を `BL` するだけで動く。
  呼び出し規約は `(g_DrawContext, userdata)`

### 5. 現在の状態

パッチは **uninstall 済み**（フック `0xE92D4010`、ケーブ全ゼロ、bp 0 件）。
生成した `FuncNode`（`0x329D8500`）はグラフィクスヒープに残る（340 バイト、再起動で消える）。
