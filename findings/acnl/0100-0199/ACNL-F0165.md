## F-127: ★★`nw::lyt::TextBox` の構造を実機で確定 — 位置・色・サイズを自由に変えられる

confidence: **HIGH**（実機。1 項目ずつ A/B で目視確認）

ユーザーの目標「**好きな位置に好きなテキストを、フォントと装飾を変えて描画する**」に向けた基礎。

### 1. ★確定したフィールド

対象は会話ウィンドウの住民名 TextBox（実機 `0x32D20220`、ペイン名 `"T_nam_00"`）。

| offset | 型 | 内容 | 実機の値 | 検証 |
|---|---|---|---|---|
| `+0` | ptr | vtable | `0x8FC07C` | — |
| **`+40` / `+44` / `+48`** | float×3 | **位置（translate x, y, z）** | `-0.0, -0.0, 0` | **✔ X を 10.0 にしたら右にずれた** |
| `+52`〜`+60` | float×3 | 回転 | 0, 0, 0 | 未検証 |
| `+64` / `+68` | float×2 | 拡大率 | 1.0, 1.0 | 未検証 |
| `+72` / `+76` | float×2 | ペインの大きさ | 96.0, 24.0 | 未検証 |
| `+184`〜 | char×8 | **ペイン名** | `"T_nam_00"` | ✔ |
| `+212` | ptr | **文字列バッファ** `wchar_t*` | — | ✔（F-126） |
| **`+216` / `+220`** | RGBA | **文字色（上 / 下のグラデーション）** | 白 / `0xFF919191` 灰 | **✔ 青にしたら青くなった** |
| `+224` | ptr | **フォントオブジェクト** | `0x3302ABE0` | 非 0 でないと `SetString` が即 return |
| `+228` / `+232` | float×2 | フォントサイズ（幅・高さ） | 18.0, 24.0 | 未検証 |
| `+236` / `+240` | float×2 | 文字間隔・行間隔（推定） | 0, 0 | 未検証 |
| `+248` | u16 | バッファ長（バイト）。`/2-1` が最大文字数 | 20 | ✔ |
| `+250` | u16 | 現在の文字数 | 3 | ✔ |
| **`+254`** | u8 | **bit0 = 更新フラグ** | — | **✔ これを立てないと反映されない** |
| `+256` | ptr | **マテリアル** | `0x32D2033C` | ✔ |

**色は RGBA のバイト順**（`0xFF919191` = `91 91 91 FF` = R,G,B,A の灰）。

### 2. ★★色は乗算される

マテリアル（`+256`）の **`+20`** に乗算色がある。

```
最終的な色 = 文字色（+216 / +220） × マテリアル +20
```

| 実験 | 結果 |
|---|---|
| 文字色 = 青、マテリアル +20 = `96 00 32 ff`（暗いピンク） | **紺色のような暗い青**に見えた |
| 文字色 = 白、マテリアル +20 = `96 00 32 ff` | **ピンク**に見えた |
| 文字色 = 白、**マテリアル +20 = 白** | **完全に白くなった** ✔ |

**この 3 つで乗算が確定した。** 名前欄がピンク色なのはマテリアル側の色による。

### 3. ★★★更新フラグを立てないと反映されない

**値を書くだけでは見た目が変わらない。** `+254` の bit0 を立てる必要がある。

これに気づくまで「効いていない」と誤判断していた。
`SetString` は内部でこのフラグを立てるので、文字列変更だけは素直に反映されていた。

**ただし値そのものは上書きされない**（2 秒走らせても書いた値が残る）。
文字列の場合（ゲームが毎フレーム `SetString` で書き戻す）とは事情が違う。

### 4. ★踏んだ誤り

**4 項目（位置・サイズ・色×2）を同時に変えて表示が消え、原因を特定できなかった。**
CLAUDE.md「最小構成で検証してから広げる」に反していた。

さらに悪いことに、その失敗を引きずって
**「位置も色も効かない」と誤結論しかけた。**
実際にはユーザーの報告「位置が右にずれました」で位置は効いていたと判明。

**1 項目ずつ変えていれば 1 手で分かった。**

表示が消えた原因は未確定だが、位置 (60, -40) かサイズ 36×48 が
ペインの矩形 (96×24) からはみ出してクリップされたと考えられる（`MEDIUM`）。

### 5. 色の見分けについて

赤にしたとき「変化なし」と報告されたが、**名前欄がもともとピンク系**で
赤との差が付かなかっただけだった。**背景と明確に異なる色（青）を選ぶべき。**

### 6. 残る課題

- **ドロップシャドウ**の出どころ。名前欄には元々影が無いので、
  影がはっきり出ている TextBox（会話本文 `0x32D20788`、
  アイテム名 `0x32CFEC60`）で調べ直す必要がある
- フォント差し替え（`+224`）
- フォントサイズ（`+228` / `+232`）
- 表示が消えたときの限界値（クリップの条件）
