## F-122: ★★★TODO-84 達成 — 完全自己完結の自前描画。あわせて TODO-83 も解決

confidence: **HIGH**（実機。ユーザーの目視で単一インスタンスの同定まで一致）

### 1. ★到達点

自前ノードのコールバックが、**ゲームの描画関数を一切呼ばず**、
自分が持つデータを積むだけで画面に絵を出した。

```asm
p = GpuCmd_GetProperty(0x208)
Mem_CopyBytes(p,        *(mgr+0xB4), 4128)   既製ブロック（シェーダ＋パイプライン）
Mem_CopyBytes(p + 4128, TEMPLATE,     432)   カテゴリ設定＋インスタンス描画
GpuCmd_Advance(4560)
```

`KEEP_ORIGINAL=False` でゲーム本来の影の登録を NOP 化した状態で実行:

- **ゲームの影は 1 つも出ない**
- **自前が積んだ 1 個だけが黒く描かれる**
- ユーザーの報告: 「出ていた影は、私の家（テントの見た目）の柵です」
  → テンプレートに選んだのは**最大スケールのインスタンス**（行0.x = 100.0、w = 2637.0）。
  手前の大きい影に対応しており、**選んだインスタンスと見えたものが一致した。**

`delta = 4560` も毎フレーム実測しており、機構・内容・見た目の三つが揃った。

### 3. ★TODO-83 解決 — 重ねがけが効かなかった本当の理由

`KEEP_ORIGINAL=True`（ゲーム本来の影が先に走る）状態で自前ノードの出力を捕捉すると、
**`DRAWELEMENTS` が 1 回も無い**（11280 バイト積むが描画ゼロ）。
`KEEP_ORIGINAL=False` なら 68 回ある。

**影インスタンスのリストは最初の呼び出しで消費され、2 回目は 1 個も描かない。**

これが F-117 の「8 回重ねても見た目も速度も変わらない」の正体だった。
F-118 で「深度テストで落ちている」と考え、F-120 でそれを否定したものの
理由は未解決のままだったが、**深度でもブレンドでもなく、
単に 2 回目以降が何も描いていなかった。**

**推測を 2 度立てて 2 度外し、3 度目に測定で決着した。**
最初から「2 回目の出力を捕捉して数える」をやっていれば 1 手で分かった。

### 4. ★自分の実装バグ（ARM 即値エンコーダ）

`MOV R2, #432` を生成したつもりが **`MOV R2, #27`** になっていた。
自作の即値エンコーダで回転方向を逆にしていた。

ARM のイミディエイトは **`imm8 ROR (2*r)`**。
したがって `imm8 = v ROL (2*r)` を探さねばならないのに、
`v ROR (2*r)` を探していた。

```
誤: rot = (32 - r*2) % 32 ;  cand = v ROL rot
正: sh  = (r*2) % 32      ;  cand = v ROL sh
```

**この間ずっと 432 バイトのつもりで 27 バイトしかコピーしていなかった。**
描画が出なかった直接の原因はこれ。

**気づけたのは IDA の逆アセンブル出力（`MOV R2, #0x1B`）を毎回表示していたから。**
CLAUDE.md「命令デコードのマスクで方向ビットを落とさない」は、
**自分で書くエンコーダにも同じだけ当てはまる。**
修正後は `288 → 0xE12` / `432 → 0xE1B` の往復を自己検証してから使った。

### 5. 途中で潰した誤解

- 「テンプレートが古くて画面外」— 一因ではあったが主因ではなかった

- 実際の主因は §4 のエンコーダバグ
