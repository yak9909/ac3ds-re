## F-166: ★★★GPU 可視性を証明した。ゲームのアロケータから GPU が読めるメモリを得られる — `HIGH`（実機で視認）

### 1. 結果

`g_GfxAllocator` から確保したバッファを **GPU が実際に読んだ。**

上画面の時計 UI で **時と分の 4 文字が塗りつぶされた四角**になった。
我々のバッファを `0xFF` で埋めてフォントアトラスとして差し向けた結果である。

これで F-165 の「linear の窓の中にある」が
**「GPU が読める」に昇格した。TODO-117 は解決。**

| | |
|---|---|
| バッファ VA | `0x329D9600` |
| バッファ PA | `0x229D9600` |
| reg `0x085` に入れた値 | `0x0453B2C0`（= PA >> 3） |
| 確保 | `g_GfxAllocator->Alloc(0x4000, 0x80)`（F-164 の vtable +8） |

### 2. 手法 — コマンド注入もコードケーブも不要だった

`nw::font::ResFont` のテクスチャ記述子が

```
table + 0x14*i + 0x08  =  物理アドレス >> 3
```

を持っており、**これがそのまま PICA の reg `0x085` に入る**。
この永続フィールドを書き換えるだけでよい。

`scratchpad/dump_glyph_atlas.py` で読める。
適用/復元は `PATCHES/font_atlas_redirect.py`。

**★【F-167 で訂正】記述子は「毎フレーム」ではなく「batch 構築時」に読まれる。**
書き換えた記述子がゲームに書き戻されないのは事実だが、
`reg 0x085` は **batch を組み立てるときに焼き込まれる**。

根拠: 記述子を復元したあとに `T_minute` の batch を読むと、
`reg 0x085` が **我々のバッファ `0x0453B2C0` のまま**だった。
その batch は向け替え中に組み立てられ、以後まだ再構築されていない。

効果が 3 秒で出たのは、時計のテキストが頻繁に再構築されるため。
**「効かない」ときは batch が再構築されていないだけかもしれない。**

### 3. ★`VA - PA = 0x10000000` が独立に再確認された

主フォント `DESC[0]`: `phys>>3 = 0x0430F950` → `<<3 = 0x2187CA80`。
TGLP のアトラス VA は `0x3187CA80`。差は **`0x10000000`**。

F-124 は影テクスチャ（VA `0x33076480` / PA `0x23076480`）で同じ差を出していた。
**まったく別のオブジェクト（フォントアトラス、`0x31xxxxxx`）で一致した**ので、
`0x30000000`-`0x40000000` の窓全体でこの差が成り立つとみてよい。

### 4. ★思い込みの訂正 —「UI テキストは常時画面に出ている」は誤り

上画面の時計 UI は **一定時間操作しないときにだけ出現する**。
プレイヤーが動いている間は上画面に UI 系が何も描画されていない
（ユーザーの指摘。本項の検証中に判明）。

**「常に見えているはず」を前提に検証を組まないこと。**
今回は 20 シートを一括で向け替えたので、たまたま出ていた時計で捕まえられた。
