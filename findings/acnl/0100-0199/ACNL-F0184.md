## F-158: ★★自前の変換行列でテキストを任意位置に描けた — `HIGH`（静的導出＋実機で視認）

### 1. 結果

住民名 `T_nam_00` の **赤い複製が、元の緑の名前から右へずれた位置に描かれた。**
元の緑の名前はそのまま残っている。

**ゲームは TextBox を 1 つしか持っていないのに、描画は 2 回起きている。**
片方は我々が発行したもので、独自の色と独自の変換行列を持つ。

適用スクリプト: `PATCHES/cave_text_emit.py`

### 2. F-127 との違い（重要）

見た目の現象（色が変わる・位置がずれる）は F-127 で既に取れていた。
**違うのは描画の主体である。**

| | F-127 | F-158 |
|---|---|---|
| 手段 | TextBox のフィールドを書き換える | GPU コマンド投入を自分で呼ぶ |
| 主体 | ゲーム | 我々 |
| 画面上の文字 | 1 個（元が変化） | 2 個（元は無傷、増える） |
| 位置指定 | pane のレイアウト座標 +40/+44 | 変換行列を直接（画面座標） |
| pane が存在しない場面 | 使えない | 使える |

### 3. プリフィックスの構造（実測）

`TextDraw_EmitStatePrefix`(0x4D5CB0) は `drawctx+568` のステージング 16 ワードを
`Mem_Copy` で流すだけ。長さは `16*(drawctx+37)+16` バイトで、
`TextBox_EmitBatchToGpuCommands` は直前に `drawctx+37 = 3` を書くので **常に 64 バイト**。

```
[ 0] 0x80000020        param0（uniform index）
[ 1] 0x000F02C0        header  reg 0x2C0
[ 2] matrix[0]         param0
[ 3] 0x00BF02C1        header  reg 0x2C1 + 11 params
[ 4..14] matrix[1..11]
[15] 0
```

`v5[2] = 旧 v5[3]` の退避と `v5[3] = header` の差し込みで、
ステージング上は matrix[0..11] が `v5[3..14]` に置かれている。

**`*(drawctx + 0x66C)` == `drawctx + 580` == `&v5[3]`**（実測、差 12）。
つまり `sub_73CE64` が書き込む float[12] はステージングそのもの。

### 4. 行列の形

実測値:

```
row0 = (1.25, 0, 0,  0)
row1 = (0,    1, 0,  0)
row2 = (0,    0, 1, -1)
```

**★【F-160 で訂正】この行の「1.25 = 400/320」は誤り。**
この行列は 3 秒走行後に**最後に描かれた別のテキスト**のもので、
`T_nam_00` の値ではなかった（対象自身は `matrix[0] = 1.0`）。
**`matrix[0]` は pane ごとの拡大率であって全体比ではない。**
行内が `(x, y, z, w)` 順である結論自体は、Y 列の反転位置と
平行移動の加算位置から独立に裏付けられており、変わらない。
これが行内 `(x, y, z, w)` 順である決定的な根拠になる
（`sub_73CE64` が index 1 を負号反転＝Y 列の反転、index 3 に平行移動を加算、とも整合）。

ストリーム上の位置:

| 要素 | ストリーム index | cursor 基準 |
|---|---|---|
| `matrix[3]` 平行移動 X | `[6]` | `(R0+64) - 40` |
| `matrix[7]` 平行移動 Y | `[10]` | `(R0+64) - 24` |
| `matrix[11]` 平行移動 Z | `[14]` | `(R0+64) - 8` |

`matrix[3]` に `40.0f` を入れて、赤い複製が右へずれることを実機で確認した。

### 5. ★`R9` が使える

`0x4B7DCC` の時点で **`R9` にプリフィックス直後の cursor が生きている**
（0x4B7D44 で `MOV R9, R0`、以後書き換えられない）。
したがって 1 枚目のプリフィックスは `[R9-64, R9)` にある。

**これを複製して平行移動だけ差し替えれば、1 枚目には一切触れずに 2 枚目を動かせる。**

### 6. ケーブ（実機で検証済み）

```
+00  LDR   R12, =TARGET_TB
+04  CMP   R6, R12
+08  BNE   skip
+0C  PUSH  {LR}
+10  SUB   R3, R9, #64        1 枚目のプリフィックス先頭
+14  MOV   R12, #16
+18  loop: LDR R1, [R3],#4
+1C        STR R1, [R0],#4
+20        SUBS R12, R12, #1
+24        BNE loop
+28  LDR   R1, =40.0f
+2C  STR   R1, [R0,#-40]      複製した matrix[3] のみ差し替え
+30  MOV   R1, R0
+34  MOV   R0, R4
+38  LDR   R2, =COLOR
+3C  STR   R2, [R0,#4]
+40  MOV   R2, #0
+44  BL    TextBatch_CopyToCommandBuffer
+48  POP   {LR}
+4C  skip: MOV R2, #0
+50  B     0x4B7DD0
```

R1/R2/R3/R12 は 0x4B7DCC 以降すべて再代入されるので保存不要。
`CopyToCommandBuffer` は AAPCS 準拠で R4-R11 を保存する。

### 7. まだ足りていないこと

**字形はゲームが作った batch のまま。**
今できるのは「ゲームが作った文字列を、好きな色・好きな位置に、好きな枚数だけ複製する」まで。
**任意の文字列を自前で組むには自前 batch の構築が要る。** → TODO-114
