## F-125: ★★★テキストを画面に描画した。タイル内 Morton スウィズル順も確定

confidence: **HIGH**（実機。文字が読めた＝スウィズル順が正しいことの証明）

### 1. 結果

8×8 のビットマップグリフで `"ACNL"` を作り、L4 テクスチャに書いて表示させた。

ユーザーの報告（wrap 変更前）:

> ACNLと読めましたが、その左側に鏡文字のACNLが描画されていて、
> LNCAACNLのような見え方になっています

**文字が読めた = 仮定したスウィズル順が正しい。**

### 2. ★確定したテクスチャの並び

```python
# タイル内 Morton 順（x を偶数ビット、y を奇数ビットへ交互配置）
i = x0 | (y0<<1) | (x1<<2) | (y1<<3) | (x2<<4) | (y2<<5)

# タイルは行優先          tile = ty * (W/8) + tx
# L4 は 1 バイト 2 ピクセル  byte = tile*32 + (i>>1)、下位ニブルが先
```

**8×8 グリフはちょうど 1 タイルに収まる**ので、32 幅 = 4 文字。

### 3. ★鏡文字の正体と解消

wrap が **MIRRORED_REPEAT**（`0x083` bits 8-9 / 12-13 = 3）だったため、
UV が [0,1] を外れた領域に鏡像タイルが出ていた。

**`0x083` を `0x00003306` → `0x00000006`（wrap S/T = CLAMP_TO_EDGE）にしたら鏡文字が消えた。**

これで **F-121 の「横に伸びた分、上下からループする」も完全に説明がついた。**
同じ MIRRORED_REPEAT が原因。

### 4. ★UV の範囲が分かった

wrap を CLAMP にしたあとのユーザーの報告:

> 中心点はACNLというテキストの左端になっているのか、真ん中から右に描画されており、
> 左半分の影は何もない状態です

CLAMP_TO_EDGE では UV < 0 の領域が左端の列に固定される。
`'A'` のグリフは左端列が 0（黒）なので、そこが引き伸ばされて左半分が空白になる。

**つまりこの四角形の UV は 0〜1 ではなく -1〜1 相当で、テクスチャは中心から右半分に貼られる。**
絵を作るときはこれを見込んで配置すること（または UV を作る側＝頂点データを触る）。

### 6. 2D にならない理由（ユーザーの質問への答え）

影の描画パイプラインを丸ごと借りているため、
**影と同じ頂点シェーダ・同じ行列・同じブレンド**で処理される。
必然的に「地面に貼られた影」として出る。意図的ではなく手法の帰結。

2D 化の選択肢は 3 つ:

| 案 | 内容 | 難度 |
|---|---|---|
| A | uniform 25 の行列を、画面いっぱいの板になるよう組む | 低〜中 |
| B | 頂点シェーダを自前に差し替えクリップ空間へ直接置く | 中〜高 |
| **C** | **`nw::lyt` / `nw::font` の 2D 描画経路に乗る** | 高 |

**ユーザーの選択は C。** → TODO-94 として着手する。
