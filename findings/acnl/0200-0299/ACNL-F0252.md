## F-227: ★★★観測用の領域を、動いている描画の領域と重ねてクラッシュさせた — `HIGH`（実機）

フェードの調査のために `probe_replay_last.py` を仕掛けたらクラッシュした。
**観測が原因**で、調べたかった現象とは無関係だった。

```
観測用 LOG   0x009B0F00  リングは +0x40..+0x140 = 0x009B0F40 〜 0x009B1040
下画面の表   0x009B0E00  280 語 = 0x009B0E00 〜 0x009B1260   ← ★重なる
```

スプライト表を毎フレーム踏むので、GPU に壊れた頂点が渡って落ちる。

### なぜ今まで平気だったか

同じ `0x009B0F00` を使う観測スクリプトは前にもあったが、
**そのときは描画ケーブを入れていなかった**（表が使われていなかった）。
「前に使えたから安全」ではない。**同時に何が生きているかで変わる。**

### 使用中の .bss（重ねないこと）

```
0x009B0010 確保スロット
0x009B0D00 LOG（48 語 = 〜0x009B0DC0）
0x009B0E00 下画面 スプライト表（〜0x009B1260）
0x009B1400 上画面 スプライト表（〜0x009B1860）
0x009B1C00 下画面 色配列        0x009B1E00 上画面 色配列
0x009B2000 〜  観測用に空けてある
```

### 教訓

**観測は「素の挙動を変えない」が原則だが、領域の衝突はその原則を破る。**
仕掛ける前に、**そのとき生きている領域の一覧と機械的に突き合わせる**こと。
ケーブの番地については同じ検査をしていた（`CLAUDE.md`）のに、
**.bss については同じ検査をしていなかった。**
