## F-175: ★★★Picture は毎フレーム必ず描かれる。TextBox ではなく Picture に相乗りすべきだった — `HIGH`（実機で計測）

適用: `PATCHES/measure_picture_draws.py`

### 1. 経緯 — 過去の記録を先に読んだことで探索を省けた

TODO-115 の次の一手は「79〜82 回の描画がどの関数から出ているかを
`GpuCmd_Advance` の呼び出し元から辿る」だった。

**しかし `RE/TODO.md` と `RE/FINDINGS.md` を先に読んだところ、答えが既にあった。**

- `TODO-112` に **`nwlyt_Picture_DrawToCommandList` (`0x73CB58`)**
- **F-147** に `nwlyt_Pane_DrawRecursive` (`0x73B524`) が cursor を `R1` で渡し
  戻り `R0` を次 Pane へ渡すこと、**Picture 経路と TextBox 経路が
  `TextBox_UpdateDrawState` / `sub_4B8360` を共有する**こと
- **F-149** では自前 Picture を 6 枚追加して実機で表示に成功していた

**辿る作業は不要だった。**

### 2. 仮説

F-171 で「歩行中は TextBox 描画ゼロ」と分かっていたが、
ユーザーの指摘は **「上画面には UI が無い」** であって下画面は別。
**下画面の常時 UI は TextBox ではなく Picture ではないか。**

### 3. 計測結果（25 秒。前半は会話・時計あり、後半は UI 無しで歩行）

```
Picture 描画の総数 = 20231
Pane 走査の総数    = 60038
総フレーム数       = 1043
★Picture ゼロのフレーム = 0 / 1043  (0.0%)
1 フレームあたり平均 19.40 枚、最大 80 枚
直近 256 フレーム（UI 無しで歩行中）: 全部 10 枚以上、ゼロは 0/256
```

**Picture は 1 フレームも欠かさず描かれている。**

| 経路 | 描画ゼロのフレーム |
|---|---|
| TextBox（F-171） | **83.8%** |
| **Picture（本項）** | **0.0%** |

### 3b. 60 秒・操作を変えての再計測（ロード遷移とメニュー開閉を含む）

「ロード中に描画されないのでは」というユーザーの指摘を受けて測り直した。
建物の出入りとメニュー開閉を複数回行った 60 秒:

```
Picture 描画の総数 = 65315
Pane 走査の総数    = 161251
総フレーム数       = 1792（29.9 fps）
★Picture ゼロのフレーム = 20 / 1792  (1.1%)
1 フレームあたり平均 36.45 枚、最大 118 枚
```

**指摘どおり穴はあった。** ただし 20 フレーム = 約 0.67 秒で、
ロード遷移 1 回につき数フレームという規模。

| 経路 | 描画ゼロのフレーム | 穴の性質 |
|---|---|---|
| TextBox（F-171） | 83.8% | **8.5 秒連続で空く** |
| Picture（本項） | **1.1%** | ロード遷移で数フレームだけ |

**実用上は問題にならない。** 途切れるのは画面が暗転・フェードしている場面で、
そこでオーバーレイが数フレーム出ないのはむしろ自然である。

**ただし「常に描ける」と書いてはいけない。** 1.1% は穴である。
フレーム跨ぎの状態を持つ実装にするなら、
描画が飛ぶフレームがあることを前提にすること。

### 4. 結論

**TODO-115 の「常時使える相乗り点」は `nw::lyt::Picture` の描画経路である。**

F-147 より Picture 経路は TextBox 経路と `sub_4B8360` /
`TextBox_UpdateDrawState` を共有するので、**同じ UI の状態が整っている。**
F-174 で断念した「GPU 状態を一から再現する」必要がない。

**F-169 で確立した「テクスチャと矩形の差し替え」がそのまま適用できるはず。**

### 5. 教訓 — 相乗りが悪かったのではない

F-171 の時点で私は「相乗り方式は自前 GUI として成立しない」と結論したが、
**それは言い過ぎだった。悪かったのは「TextBox を選んだこと」であって
「相乗り」そのものではない。**

同じ計測器を対象だけ変えて回せば済む話で、
F-171 の直後に Picture を測っていれば F-172〜F-174 の遠回り
（GPU 状態の再現に挑んで 1 度フリーズ）を避けられた。

**「この経路がダメ」と分かったら、
結論を一般化する前に隣の経路を同じ道具で測ること。**
