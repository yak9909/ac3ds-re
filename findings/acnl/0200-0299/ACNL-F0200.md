## F-174: 発行点への注入は確立したが、GPU 状態の再現は現実的でない。方針を変えるべき — `HIGH`（実機で反復検証）

適用: `PATCHES/cave_replay_draw.py`、`scratchpad/dump_frame_cmdlist.py`、
`scratchpad/load_draw_unit.py`

### 1. 確立できたこと

**`GpuCmd_SplitAndSubmit`(`0x1280CC`) の入口で `g_GpuCmdPtr` へコマンドを積む方式は確実に動く。**

live のコマンドリストを吸い出して照合したところ、
**我々の 928 バイトが完全一致で 3 箇所**見つかり、
書き換えた値（96.0）も各 +203 ワードの位置にあった。
**「積めているか」は解決済み。**

### 2. しかし絵にならない。原因は GPU 状態の依存

段階的に足していったが、最後まで描画されなかった。

| 試したこと | 結果 |
|---|---|
| TextBox 1 枚分 `[R9-64, R0)` を再生 | **GPU が固まる**（F-173。頂点配列の設定欠落） |
| 実フレームから `0x200` バーストで始まる完結単位（232 ワード）を再生 | 落ちないが絵にならない |
| 大きさを 16→96 に変えて重なりを排除 | 変化なし |
| 描画先・寸法・ビューポート・シザーの設定（30 ワード）を前置 | 変化なし |
| 中身が `0x10000` バイト以上たまったリストにだけ積むゲート | 変化なし |

### 3. ★足りないものを数え上げた

フレーム全体（7002 コマンド）と我々の単位（60 レジスタ）を突き合わせた結果、
**不足しているレジスタは 57 種。** 中でも致命的なのは:

| reg | 内容 | フレーム内の回数 |
|---|---|---|
| `0x2CB` / `0x2CC` | **頂点シェーダのコード転送** | 29 / 32 |
| `0x2D5` / `0x2D6` | **オペランド記述子の転送** | 29 / 29 |
| `0x107` | DEPTH_COLOR_MASK | 5 |
| `0x244` / `0x2BF` / `0x232` | ジオメトリ段・その他 | 29 / 29 / 52 |

**ゲームはフレーム中に 29 回もシェーダを切り替えている。**
我々の描画は「たまたま最後に載っていたシェーダ」で実行されるので、
頂点の解釈が合わず何も出ない（あるいは画面外へ飛ぶ）。

### 4. ★もう 1 つの落とし穴 — コマンドリストは 2 つを交互に使う

`g_GpuCmdListMgr`(`0xAD995C`) が **`0x3229D06C` と `0x323B20D0` の間で切り替わる**。
どちらも 100KB 超まで育つ。ダブルバッファとみられる。

さらに、**中身がほとんど無い補助リスト**にも `SplitAndSubmit` は呼ばれる。
実測で、長さ 1,072 バイト = **我々の 1,048 バイト + 終端 24 バイト**だけの
リストが観測された。**そこに積んでも画面には出ない。**

### 5. 結論 — 方針を変える

**「任意の地点で GPU 状態を一から再現する」のは費用対効果が悪い。**
シェーダ本体まで含めて 57 種のレジスタを正しい順序で積む必要があり、
1 つ間違えると無反応か GPU の停止になる。

**代わりに「状態が既に正しい地点」に相乗りするべき。**

F-171 の計測が根拠になる。**UI が何も出ていない歩行中でも、
1 フレームあたり 79〜82 回の描画が行われている。**
TextBox がゼロでも描画自体は常に大量にある。

つまり **TextBox 以外の描画経路にフックすれば、
状態が整った場所で、UI の有無に関わらず毎フレーム描ける。**
F-171 で「TextBox 相乗りには穴がある」と分かったが、
**「相乗り」そのものが悪いのではなく「TextBox を選んだこと」が悪かった。**

→ TODO-115 を「常時走る描画経路を特定して、その直後に積む」へ書き換える。

### 6. 手法上の教訓

**変更のたびに「注入されているか」を確認し直すこと。**
928 バイト版で一致を確認したあと、前置きを足した 1048 バイト版では
確認せずに画面だけを見ていた。最後の走行では**そもそも注入されていなかった**
（ゲートとリスト切り替えの噛み合わせ）。

**「見えない」の原因が「描画されない」なのか「積まれていない」なのかを、
毎回メモリで確かめてから次の仮説へ進むこと。**
