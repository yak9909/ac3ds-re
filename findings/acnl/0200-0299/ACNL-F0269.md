## F-246: ポルタメントの2つの誤り — `HIGH`（実機との聴き比べで確定）

`SOUND/synth.py` / `SOUND/render.py`。**命令表の一致率 100%・検証 20/20 を通っても
残っていた誤り。数値上はどこにも異常が出ない。**

### 1. `porta_key` は「次の 1 音」の起点だけ

持続させると毎音そこへ跳ね上がってから滑るため、下降する音符列で終盤が高いまま残る。
正しくは次の 1 音だけで、以降は**前の音から滑る**（レガート）。

`SE_SYS_ERASE`（`tie 1` / `porta_key 43` / キー 47→39→43→35→39→31→35→27）で発覚。

### 2. 音程の更新は 1 tick ごと（階段状）

`porta_time = 0` ならスイープは音符の長さ全体を使うが、**更新は 1 tick 単位**。
`SE_ACT_ITEM_CMN_PICK_UP` は音符長 7 tick なので**最初の 1 tick（10.4ms）は
開始キーのまま保たれる**。滑らかに補間すると最初から上がり、全体が高く聞こえる。

実機録音とゼロ交差率で比較（前半平均 / 後半平均）:
実機 117 / 861、滑らか補間 336 / 1648、**階段状 109 / 930**。

### あわせて直したもの

- `0xB4` / `0xB5` / `0xB6` も引数 1 バイト（3 バイトで読むと直後の note の
  キーと velocity を食い潰し、`velocity=255` `key=0` の幽霊 note が生まれる。
  利用者の言う「末尾に鳴る低いノイズ」の正体）。
  これでラベル境界一致は **33,319/33,319（完全一致）**、不正 velocity は 0 件
- `time` 接頭辞つき `volume`（416 箇所）/ `pitch_bend`（62 箇所）は
  **時間をかけて変化させる**命令。即座に適用すると末尾のフェードが再現されない
- `lpf_cutoff`（172 件）を無視していた。高域が残って「高く」聞こえる

### 進め方の教訓

- **全件を書き出す前に、指摘された数音だけで回す**（`SOUND/test_set.py`）。
  1 回 25 分のバッチでは検証の往復が遅すぎる
- **耳でしか分からない誤りがある。** 実機の録音 1 本が決定打になった
- **利用者の言葉の範囲を確かめる。**「末尾」は「最後の 1 音」ではなく
  「最後から手前にかけての範囲」だった。取り違えると別の場所を掘り続ける
