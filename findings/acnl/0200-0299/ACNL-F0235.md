## F-210: ★★★★★狙う相手をリスト id で固定してはいけない。実行時に追いかける — `HIGH`（実機）

START のセーブ確認メッセージウィンドウを出すと、自前スプライトが消えた。

### 切り分け（1 つずつ潰した）

| 疑い | 観測 | 結果 |
|---|---|---|
| 記録されていない | ケーブの発火回数 | ✗ 4 秒で 123 回 = 毎フレーム発火していた |
| 再生されていない | `*(layout+264)`（記録長） | ✗ `0x7A0`。`if (*(a1+264) > 0)` を満たす |
| scissor で切られた | `*(layout+312)` | ✗ 無効 |
| 描画順が変わった | `GpuCmd_ReplayRecordedListRange` を直接観測 | ✗ ダイアログ中も id 15 がフレーム最後 |
| マテリアル | 通常 `0x32C96428` / ダイアログ中 `0x32D1E0C8` | **○ 原因はこちら（F-211）** |

**「フックが発火している」と「描かれている」は別。** 発火だけを見て安心しない。

### それでも id 固定はやめた

id 15 がたまたま生きていただけで、**場面によっては再生されなくなる**。
「いついかなる時も描画されない事態を起こさない」ためには、
**そのフレームで下画面パスの最後に再生されたレイアウトを実行時に追いかける**のが正しい。

```
Frame_DrawPass1040（下画面・再生のみ）
    入口で「前フレームに集めた値」を確定させ（LOG+0x34）、集め直しを始める
    Layout_ReplayRecordedList のたびに R0 を LOG+0x2C へ
Frame_DrawPass1024（上画面・記録してから再生）
    記録のときに LOG+0x34 と突き合わせる
```

### ★集めている途中の値を狙ってはいけない

最初は「集め中の値（LOG+0x2C）」をそのまま狙ったが **発火 0 回**になった。
記録と再生はフレーム内で入り混じるため、記録時点ではまだ目的のレイアウトが
集まっていないことがある。**1 フレーム分まるごと保持した値**を狙えば必ず一致する。

### ★控えた値は比較にしか使わない

解放済みのポインタを掴んでも安全なように、**参照はしない**。
フラグを書き込むのは「ゲームがいま処理しているレイアウト」（`R0`）だけ。
