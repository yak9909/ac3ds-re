## F-256: ★★★★★ゲームがそのパスで 1 枚も描いていないと、描画コマンドを積んだ瞬間に GPU が止まる — `HIGH`（実機で二分により確定）

自前ノード方式にしてから、**「上画面のタイトルロゴが消えた瞬間」に必ず GPU が停止**した。
画面だけ止まり音は続く。`PC` は `SVC 0x24`（WaitSynchronization1、タイムアウト -1）＝
GPU 完了イベントの無限待ち。Resume では戻らず、ゲーム再起動が必要。

### 二分（1 回の実機試行につき 1 点だけ変える）

| 版 | 描画コマンド | マテリアル | テクスチャ復元 | 結果 |
|---|---|---|---|---|
| 1 | **積まない**（vtable +0x08 は空スタブ） | — | — | **落ちない**（A ボタンも通過） |
| 2 | 積む | ○ | ○ | 落ちる |
| 3 | 積む | ○ | **×** | 落ちる |
| 4 | 積む | **×** | × | 落ちる（**上画面に何も描画されていない状態で**） |
| 5 | 積む（ゲートあり） | ○ | ○ | **落ちない** |

版 1 で **F-254 のノード方式そのものは無罪**と確定した。
版 2〜4 でブロックを外しても落ちたので、**原因はブロックの中身ではない**。

### 原因

**そのパスでゲームが 1 枚も描いていないと、テクスチャの結び付き・頂点配列・TEV といった
GPU 状態がそのフレームに対して確立されていない。** そこへ描画コマンドを積むと、
解放済みまたは前フレームのアドレスを参照して GPU が停止する。

利用者の観察「上画面に何も描画されていない状態でフリーズする」が決め手だった。
マテリアルを外してもテクスチャ復元を外しても落ちたのは、
**描画コマンド自体が未確立の状態の上に乗る**からである。

### 対策（実機で確認済み）

**そのパスでゲームが 1 度もバッチを流していなければ描かない。**

- `DrawCtx_FlushBatch`（`0x4B8360`）のフックで**ゲーム自身が流した回数**を数える。
  自前の描画はトランポリン（`CAVE_T`）経由なのでこのフックを通らない＝
  **ゲームの回数だけ**が数えられる
- 自前ノードはリストの最後なので、そこで読めば「このパスの合計」になる
- 0 なら描画を見送り、カウンタを 0 に戻して次のパスに備える

実測: 3 回/フレーム → **2 回/フレーム**になった。
見送られるのは上画面の右目パス（`0x410`）で、あのパスは記録を行わない（replay のみ）ため。
3D スライダを切っていれば右目は表示されないので見た目に影響しない。

### 途中で潰した「原因ではなかったもの」（再訪しないこと）

- 主リストの記帳ずれ … `mgr[3] = mgr[5]` を実測で確認。**無関係**
- 自前ノードがリストの先頭になる … 先頭で見送った回数は**常に 0**。**起きていない**
- 借りたマテリアルのポインタが古い … 複製＋内部ポインタ張り替えまでやっても落ちた。**無関係**
  （ただし複製方式自体は「マテリアルが捕まらないフレームでも描ける」ので有用）
- ケーブの構造 … `PATCHES/audit_node_cave.py` で全 LDR リテラル・全分岐・領域・重なりを
  機械監査して**異常 0 件**

### ★手順上の教訓（同じ事故を繰り返さないため）

1. **`cave_draw_topmost.py` 系は install 時に逆アセンブルを表示しない。**
   そのため 318 語のケーブを一度も検証せずに実機で走らせていた。
   `PATCHES/audit_node_cave.py`（実機不要）を必ず通すこと。
2. **`R7` はスプライトループとテクスチャ復元ループでカウンタに再利用される。**
   ケーブ末尾で `[R7,#..]` を触るなら読み直す。これで実機をクラッシュさせた。
3. **撤去は「登録フックを戻す → ノードをリストから外す → 0 で消す」の順。**
   繋がったまま vtable を 0 にすると、次フレームに
   `LDR R0,[R4]` → 0 → `LDR R1,[R0,#8]` → `BLX R1` で描画スレッドが死ぬ。
   これも「画面だけ止まり音は続く」症状になるので、GPU ハングと紛らわしい。
4. **「生きているか」は `g_GpuCmdPtr` の**変化**で判定する。** 1 回読むだけでは分からない。
5. **1 回の実機試行で変える点は 1 つだけ。** 一度、ガード追加とケーブ再配置を同時に行い、
   「操作しなくても落ちる」という別現象を生んで切り分けを濁らせた。
6. ケーブ内で落ちても**再起動せずに復帰できる**。スタックから `R4-R8` と `LR` を戻し、
   `SP` を戻して `PC` を呼び出し元へ設定すればよい（今回それで復旧した）。

### 残っている課題

**未確立のパスでは描けない**ので、上画面が空のフレームでは自前 GUI が消える。
最終形は「未確立なら自前で GPU 状態を作る」＝ gokiro 氏の方式
（`REFERENCES/TEXTS/render.txt`）。必要なのは
テクスチャ結び付き・頂点属性の構成・TEV の 3 つで、
材料は F-191 / F-206 / F-207 / F-216 に揃っている。
