## F-215: ★★★★★借りたマテリアルは 9 語まとめて中立化する。ただし描画後に積み直してはいけない — `HIGH`（実機）

F-214 の対策（`+0x10`/`+0x14`/`+0x18` の 3 語を中立化）では**しずえ会話の切り替わりで
一瞬描画が消えた**。会話が終わって遊べるようになると以後は正常（優先枠が埋まるため）。

### 3 語では足りなかった

そのとき使われていた予備は `P_soft_B`。動作実績のある `P_base_00` と比べる。

| offset | `P_base_00`（良） | `P_soft_B`（不可視） |
|---|---|---|
| `+0x10` | `00000000` | `0087C3EB` |
| `+0x14` | `FFFFFFFF` | `FFE1FFFF` |
| `+0x18` 〜 `+0x24` | `FFFFFFFF` | `FFFFFFFF` |
| **`+0x28`** | **`FFFFFFFF`** | **`80FFFFFF`**（アルファ 0x80） |
| **`+0x2C` / `+0x30`** | **`00000015`** | **`000006AA`** |

**半透明かつ合成モードが別**なので、白を描いても背景が変わらない＝見えない。
中立化を **`+0x10` 〜 `+0x30` の 9 語**へ広げ、`P_base_00` と同じ並びに揃えて解決した。

```
+0x10        = 0
+0x14..+0x28 = 0xFFFFFFFF   （定数色。+0x28 はアルファを含む）
+0x2C/+0x30  = 0x15         （合成モードらしき値）
```

### ★★描画の後に `Material_EmitState` を呼んではいけない

「中立化した状態が残らないように積み直す」つもりで、描画後にもう一度呼んだところ、
**自前スプライトの位置にモザイク状の乱れ**が出た（文字をモザイク化した見た目ではなく、
無関係な四角が撒かれたような見た目）。

`Material_EmitState` は内部で `DrawCtx_FlushBatch` を **12 箇所**から呼ぶ。
こちらが描き終えた直後は配列の中身が確定していないので、そこで流されると
**中身の定まらないバッチがそのまま描かれる**。

積み直しは不要だった。マテリアルの中身は既に素へ戻してあり、
ゲームは毎フレーム、ペインごとに `Material_EmitState` を呼び直す。

**★「状態を戻す」つもりの後始末が、別の壊し方をすることがある。**
F-198 で `unk_97B74C` を戻したのは正しかったが、同じ発想を関数呼び出しに広げたのが誤り。
**副作用のある関数を「後始末」に使わない。**

### ★`.text` の空き領域は `0x839000` まで（文書が過大だった）

`DOCS/ctrpf_plugin.md` は「`0x00838080` から `0xFE8` バイト」と書いていたが、
実機では **`0x839000` から実データ**が入っている（`"K---"` の ASCII と生きたポインタ）。
正しくは `0x838080` 〜 `0x839000` の **`0xF80` バイト**。

描画ケーブは 290 ワード（末尾 `0x838F88`）まで伸びたので、
`0x838F80` にあったフレームケーブを `0x838900` へ移した。
