## F-183: ★索引エントリの `w3` は「色」。テクスチャはバッチ単位 — `HIGH`（静的解析）

### 1. F-180 の記述を訂正する

F-180 で索引エントリの `w3` を「マテリアル関連」と書いたが、**誤り。**
`sub_4B8090`(`0x4B8090`) を読むと **頂点カラー**である。

```c
sub_4B8090(drawctx, colors /* picture+320 */, alpha /* picture+181 */)
```

- `colors` は **4 隅の色**（RGBA 各 1 バイト x 4 個）
- 4 隅がすべて `0xFFFFFFFF`（既定の白）なら
  `*(float*)(drawctx+1636) = alpha/255`（＝索引ではなくアルファ値そのもの）
- そうでなければ **4 色 x RGBA = 16 float を `+1644` 配列へ積み**、
  `*(float*)(drawctx+1636) = その索引`、そして **`drawctx+37 += 4`**

`drawctx+1636` が索引エントリの `w3` になる（F-178）。

**つまり `+1644` の配列は「行列」専用ではなく、「行列」と「4 隅の色」を共有している。**
1 画像あたり行列 3 エントリ、色を持つ場合はさらに 4 エントリ。

### 2. ★テクスチャはバッチ単位で決まる

`sub_73CB58` にこうある。

```c
v10 = *(picture + 216);                    // sub_73B650 が作るマテリアルの鍵
if (*(drawctx + 1692) != v10) {
    if (*(drawctx + 36)) sub_4B8360(drawctx);   // ★マテリアルが変わるとバッチを流す
    *(drawctx + 1692) = v10;
}
```

そして `sub_4B8360` は `*(cursor) = *(drawctx + 1692)` としてマテリアルのブロックを積む。

**1 バッチ = 1 テクスチャ。** 同じバッチに別テクスチャの画像は混ぜられない。

したがって自前テクスチャを使うには

- **(a)** 自前のマテリアルでバッチを分ける、または
- **(b)** `sub_4B8360` が積んだ後のコマンド列で `reg 0x085` を書き換える
  （**F-169 で実証済みの手法**。ただしバッチ全体のテクスチャが変わる）

のどちらかが要る。

### 3. ★色は今すぐ制御できる

`w3` が色を指すなら、**自前の 4 色ブロックを `+1644` に積んで `w3` をそこへ向ける**だけで、
追加した UI 画像の色とアルファを自由に決められる。

**半透明の色付きパネルは GUI の中核**であり、
テクスチャ差し替えより先にこちらを取るべき。

我々の追加画像は現在 行列 3 エントリ（索引 3..5）を使い `+37 = 6` にしている。
色を足すなら索引 6..9 に 4 エントリ書き、`w3 = 6.0`、`+37 = 10` とする。
上限は `+37` が 0x20 なので余裕がある（F-176）。

色は 4 隅 x (R, G, B, A) の float、いずれも 0..1。
