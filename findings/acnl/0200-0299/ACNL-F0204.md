## F-178: 描画コンテキストの四角形配列を解読。`+1648` は F-167 の `c[0x40]` そのもの — `HIGH`（実機で採取）

適用: `PATCHES/cave_probe_drawctx.py`

### 1. 採取方法

`sub_4B8360`(`0x4B8360`) の**入口**にフックを置いた。
そこは「配列を流す直前」＝**カウンタが最大の瞬間**である。
drawctx・3 つのカウンタ・3 つの配列ポインタを記録し、停止後に配列を読んだ
（`sub_4B8360` はカウンタを 0 にするが配列の内容は消さない）。

**`g_DrawContext`(`0x94CA48`) は別物だった**（配列ポインタが 0）。
実際に使われている drawctx は実測で取るしかない。

### 2. 実測値

```
drawctx = 32FF62EC        （F-147 が記録していた値と一致）
カウンタ  +36=1  +37=3  +38=2
配列      +1640=32FF6380  +1644=32FF6530  +1648=32FF6740
```

```
四角形 (+1640) カウンタ=1
  [0] 003F02C1  1.000  0.000  1.000

行列 (+1644) カウンタ=3
  [0] 00BF02C1  0.000  0.000  60.000
  [1] 0.000  1.000  0.000  -8.000
  [2] 0.000  0.000  1.000  -1.000

幾何 (+1648) カウンタ=2
  [0] 007F02C1  0.500  0.750  0.250
  [1] 16.000  16.000  -8.000  8.000
```

### 3. 解読

各配列の先頭ワードは **PICA のヘッダ**である。

| 配列 | ヘッダ | パラメータ数 | 内容 |
|---|---|---|---|
| `+1640` | `0x003F02C1` | 4 | 他の 2 配列への**索引** |
| `+1644` | `0x00BF02C1` | 12 | **3x4 行列**（1 四角形につき 3 エントリ） |
| `+1648` | `0x007F02C1` | 8 | **UV 4 つ + (幅, 高さ, X, Y)** |

**`+1648` は F-167 で解読した `c[0x40 + 2k]` / `c[0x40 + 2k + 1]` そのもの。**
実測値 `16, 16, -8, 8` は、以前フレームのコマンドリストから切り出した
16x16 スプライト（F-172 の単位 #43）と一致する。

`+1640` の索引は `sub_73CB58` の

```c
*v22     = *(a4+1624);   // = (float)(drawctx+37) 行列の索引
v22[1]   = *(a4+1628);   // = (float)(drawctx+38) 幾何の索引（書いた後）
v22[2]   = *(a4+1632);   // = (float)(drawctx+38) 幾何の索引（書く前）
v22[3]   = *(a4+1636);
```

に対応する。**これでシェーダは「四角形 k がどの行列とどの UV を使うか」を知る。**

### 4. 1 四角形あたりの消費

| 配列 | 増える数 |
|---|---|
| `+1640`（カウンタ `+36`） | 1 |
| `+1644`（カウンタ `+37`） | **3** |
| `+1648`（カウンタ `+38`） | **2** |

上限は `+36` が 0x1A、`+37`/`+38` が 0x20（F-176 の溢れ判定より）。

### 5. これが意味すること

**自前の四角形を足すのに、コマンドを 1 バイトも書く必要がない。**
配列にエントリを足してカウンタを増やすだけで、
`sub_4B8360` が正しいコマンドを生成する。

**次の最小実験**（F-168 の型）: まず**既存の四角形の大きさだけを変える**。
`+1648` の `[1]` の先頭 2 ワード（幅・高さ）を書き換えればよい。
索引の意味を理解しなくても実行でき、Picture 経路を掌握できたかが確認できる。
