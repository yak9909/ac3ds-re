## F-198: ★★★★7 枚超の描画と、ドット絵をきれいに出すための 4 条件 — `HIGH`（実機）

`PATCHES/cave_draw_sprites.py`。**「ACNL GUI OK」11 文字（2 チャンク）を描画し、
線の太さが均一なドット絵として表示**（ユーザー確認）。

### 1. 7 枚を超えるには — チャンク分割

`sub_73CB58` の判定より **1 バッチ 7 枚まで**（`3N+4 <= 25`）。
超えるときはフラッシュを繰り返す。

**★最後のチャンクを「大きさ 0 のダミー」で埋めて全チャンクを 7 枚にそろえる。**
カウンタも色ブロックの索引も定数のままで済み、外側ループを 1 つ足すだけになる。
半端な枚数を特別扱いする分岐が要らない。大きさ 0 の四角形は何も描かない。

表の索引は**チャンク内の位置 `j`** で作る（`3j` / `2j+1` / `2j`、
バイトオフセットは `48j` / `32j` / `16j`）。チャンクごとに配列を先頭から使い直すため。

**★F-192 の「配列 [0].w0 の復元」はチャンクループの中に置く。**
フラッシュのたびに潰れるので、チャンクごとに必要。

### 2. ★見た目を壊していた 4 つの独立した原因

ノイズを追う過程で、**層の違う 4 つ**が順に見つかった。

| # | 症状 | 原因 | 対処 |
|---|---|---|---|
| 1 | メニュー開閉時のフェードが乱れる | テクスチャ状態を書き換えたまま戻していない | `unk_97B74C` の 32 バイトを流して**復元** |
| 2 | ノイズ（一部） | 発火点の予測が外れフレーム途中で配列を破壊 | 発火点を「最初のフラッシュ」に固定 |
| 3 | 点々のノイズ | **拡大率 26/8 = 3.25 が半端** | 整数倍にする |
| 4 | 線が 1px と 2px に割れる | **相乗り先の座標系の縮尺が 0.5** | 単位数を倍にする |

### 3. ★テクスチャ状態は「潰す」のではなく「復元する」

`unk_97B74C` はキャッシュであると同時に、
`Mem_Copy(cursor, &unk_97B74C, 32*n)` で**そのまま流されるコマンド列**。

| ユニット | 中身（`[param][header]` の 4 対 = 32 バイト） |
|---|---|
| 0 | `0x082` 大きさ / `0x085` アドレス / `0x08E` 形式 / `0x083` パラメータ |
| 1 | `0x092` / `0x095` / `0x096` / `0x093` |
| 2 | `0x09A` / `0x09D` / `0x09E` / `0x09B` |

私たちが壊すのはちょうどこの 4 レジスタなので、
**自前バッチの後にユニット 0 の 32 バイトを流せば元に戻り、キャッシュとも整合する。**

キャッシュを 0 にして再発行させる手（`0x97B754` / `0x97B774` / `0x97B794`）もあるが、
**それはフェードの乱れという新しい症状を生んだ。** 状態そのものを直す方が正しい。

### 4. ★ドット絵をきれいに出す条件

```
画面上の倍率 = 描画サイズ（単位） x 相乗り先の縮尺 / グリフのテクセル数
```

**これが整数になること。** 相乗り先の縮尺は batch ごとに違うので、
**乗り換えたら測り直す。**

実測: 「最初のフラッシュ」のバッチは **縮尺 0.5**。
8 テクセルのグリフを 3 倍で出すには **48 単位**（= 画面 24px）。

- 24 単位 -> 画面 12px -> 1.5 倍 -> 線が 1px と 2px に割れる
- 48 単位 -> 画面 24px -> 3 倍 -> **均一**

`reg 0x083 = 0`（ニアレスト）も必須。リニアだと境界がぼやける。
