## F-224: ★★★★★確定した対象を「0 以外のときだけ更新」してはいけない — `HIGH`（実機）

F-223 の対策を入れてもまだ落ちた。ただし条件がはっきりした。

> メニューを開いたまま放置しても落ちませんが、
> **上画面に UI 系が表示されなくなった時**まだ落ちます。

### 原因

追いかけている対象の確定（F-210）を、こう書いていた。

```
LDR R1,[集め中]
CMP R1,#0
STRNE R1,[確定]      ← ★0 のときは更新しない
```

そのパスで 1 つも再生されないフレームでは、**古いレイアウトのポインタが残り続ける**。
上画面に UI が無くなるとまさにその状態になる。

**解放された番地に別のオブジェクトが再確保されると、
描画ケーブがそれを「対象」と誤認して、無関係なレイアウトの記録リストへ書き込む。**
だから `g_GpuCmdListMgr` が壊れる（F-223 の症状と同じ現れ方をする）。

### 対策

**無条件に確定させる。**

```
LDR R1,[集め中]
STR R1,[確定]        ← 0 でも入れる
```

0 が入れば描画ケーブは一致せず、その画面には何も描かないだけで済む。
**失うのは 1 フレームぶんの描画。壊すよりはるかによい。**

### ★教訓

「値が無いときは前の値を保つ」は、**ポインタに対しては危険**。
前の値が指す先はもう別のものかもしれない。
**保持してよいのは『それ自体が意味を持つ値』だけで、
『生きている物への参照』は保持してはいけない。**

なお F-210 で「比較にしか使わない。参照はしない」と決めていたのは正しかったが、
**比較で一致してしまうことまでは防げていなかった。**
参照しなくても、**別物と一致する**なら同じ危険がある。

### 副作用

上画面に UI が無い場面では、自前メニューも描かれない
（Select で開いても見えない。実機の報告と一致する）。
常に描きたいなら、上画面でも素で記録し直されるレイアウトを探すか、
下画面へ出す必要がある。
