## F-196: ★★★★フルカラー画像（RGBA8）の表示を確定 — `HIGH`（実機）

64x64 の RGBA8 テスト画像を自前バッファに置き、120x120 で表示した。
**「赤、青、緑、白が期待どおりの配置で出て、囲むように黒い輪郭線が出ている」**（ユーザー確認）。

### 1. RGBA8 のバイト順

**メモリ上は `A, B, G, R` の順**（リトルエンディアンの u32 で読むと `0xRRGGBBAA`）。

```
data[o+0] = A
data[o+1] = B
data[o+2] = G
data[o+3] = R
```

### 2. タイリングは 8x8 タイル・モートン順、タイルは行優先

```
tile = (y >> 3) * (幅 >> 3) + (x >> 3)
m    = x0 | y0<<1 | x1<<2 | y1<<3 | x2<<4 | y2<<5     （x0 = x & 1 など）
byte = (tile * 64 + m) * バイト数/テクセル
```

**64x64 RGBA8 = 16384 バイト。** `g_GfxAllocator` の `ALLOC_SIZE = 0x4000` にちょうど収まる。

### 3. 検証用の画像の作り方

**1 枚で 3 つを同時に判定できる形にした。**

| 判定したいこと | 手がかり |
|---|---|
| RGBA8 のバイト順 | 赤・緑・青がどの象限に出るか |
| 上下の向き（v の反転） | 赤緑が上か、青白が上か |
| タイリング | 象限の境界と**外周の黒枠がまっすぐか** |

**外周の黒枠が特に有効。** タイリングを間違えると枠が破線状に散らばるので一目で分かる。

### 4. 形式の使い分け

| 形式 | `reg 0x08E` | バイト/テクセル | 用途 |
|---|---|---|---|
| RGBA8 | 0 | 4 | フルカラー画像 |
| LA4 | 9 | 1 | ビットマップフォント（容量 1/4） |
| ETC1 | 12 | 0.5 | ゲーム自身の UI が使用（圧縮） |

### 5. ★残るのはファイル入出力だけ

**SD から読んだ画像も、デコード後はまったく同じ形になる。**
デバッガからは「SD を読む」こと自体に意味がない（読むのは PC 側になる）ので、
**ファイル入出力は CTRPF プラグイン（TODO-130）の領分。**
貼り方は本項で完全に確立した。
