## F-218: ★★★半透明（アルファブレンド）は使える — `HIGH`（実機）

OSD を避けた理由の 1 つが「アルファブレンドが使えない」ことだった（ユーザー指摘）。
自前 GUI の経路でそれが解決していることを実機で確かめた。

64x64 RGBA8 のテスト画像を作って貼った。

- 上半分: 赤を **アルファ 255 / 170 / 85 / 0** の 4 段階に塗った縦帯
- 下半分: 白を **アルファ 0 → 255 へなめらかに変化**

**どちらも指定どおりに出た。** 段階も階調も潰れず、背景が透けて見える。
`0` か `255` の 2 値に丸められる（アルファテストで切り捨てられる）こともない。

つまり:

| | |
|---|---|
| 完全な透明（アルファ 0） | ○ |
| **中間のアルファ** | **○ なめらかに効く** |
| アルファの階調 | ○ 潰れない |

借りるマテリアルの合成設定を `0x15`（`P_base_00` と同じ）へ揃えている（F-215）ので、
**どのマテリアルを借りてもアルファブレンドは同じように効く**。

### その後、プラグイン経由でも実機で確認できた（F-219 の修正後）

- こちらで変換した 128x128 LA4 の `.acgx` → 読み込まれて表示された
- ユーザーが 64x64 へ縮めて `rgba8` で変換したもの → **フルカラー＋アルファで表示された**

これで「PC で変換 → SD に置く → プラグインが読んで描く」が端から端まで通った。
