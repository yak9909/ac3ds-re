## F-226: ★★★★★相乗り先は「素で記録し直される」ものから選ぶ。強制は廃止 — `HIGH`（実機）

F-223 / F-224 の対策を入れても、しばらく遊ぶとまだ落ちた。
**根本は「素では記録し直されないレイアウトを、無理に記録させていた」こと。**

### 上画面パスの中身を測った（`PATCHES/probe_top_natural.py`）

観測したのは 2 つ。**再生の順**と、**記録要求フラグが素で立つか**。
1 だけを見て相乗り先を選んでいたのが今までの誤り。

上画面パス（`Frame_DrawPass1024`）の 1 フレーム:

```
id38 → id37 → id28 → id29 → id16 → id6 → id8
 ○     ○      ×      ×      ○      ×     ×      ← ○ = 素で記録し直される
```

| レイアウト | id | 素で記録 | 記録長 |
|---|---|---|---|
| `0x330BB074` | 38 | ○ | |
| `0x330BAED8` | 37 | ○ | 0x33B0 |
| `0x3309E0C8` | 28 | × | 0 |
| `0x330A28F4` | 29 | × | 0 |
| **`0x3225B070`** | **16** | **○** | |
| `0x32C46EA0` | 6 | × | **0** |
| `0x32C4CBCC` | 8 | × | **0** |

**id 16 が「素で記録し直されるものの中で最後」。**
しかも後ろに来る id 6 / id 8 は **記録長 0（何も再生しない）**ので、
**id 16 に相乗りすれば実質最前面**になる。

下画面の id 15 も素で記録し直される。

### 対策

- 相乗り先を **リスト id で選ぶ**（下 15 / 上 16）。id は .bss（LOG+0xA4 / +0xA8）から読む
- **記録要求フラグの強制フックを廃止**（フックは 8 個 → 7 個）
- 一致しなければ何も描かない。安全側に倒れる

これで F-223 の原因（強制によるコマンドリストの枯渇）が**構造的に消える**。

### ★教訓 — 「最後に再生される」だけでは相乗り先の条件が足りない

必要な条件は 2 つあった。

1. なるべく後に再生される（描画順）
2. **素で記録し直される**（こちらから触らなくてよい）

2 を測らずに 1 だけで選び、足りないぶんを**強制で埋めた**のが誤りだった。
**「足りないから無理に作る」のではなく、「条件を満たすものを探す」。**
探せば id 16 が普通に存在した。
