## F-228: ★★★★フェードは id 8（上）/ id 9（下）が最後に描く。両方に積めば判別が要らない — `HIGH`（実機）

ロード時のフェードで自前 GUI も一緒に暗くなる、という報告から。

### フェード中の再生順（実測）

`PATCHES/probe_replay_last.py` を仕掛け、画面が暗い間に Suspend して読んだ。

```
id15 → id16 → id8 → id16 → id8 → id9      （1 フレーム）
```

| リスト id | 記録長（フェード中） | 記録長（通常） |
|---|---|---|
| 15 / 16 | 0x7A0 | 0x7A0 |
| **8 / 9** | **0x180** | **0** |

**フェード中だけ id 8（上）/ id 9（下）が記録され、id 16 / id 15 の後に再生される。**
これがフェードの実体で、我々の上に被さっていた。

### ★「記録長が 0 でないか」では判別できない

最初は「id 8 の記録長が 0 でなければフェード中」と判定しようとしたが、
**記録長はフェードが終わっても残る**ので、常にフェード用が選ばれてしまい、
しかもそれは記録し直されないので**一度も描かれなくなった**（発火 0 回）。

### 対策 — 判別しない

**通常用とフェード用の両方を対象にする。**

- フェードが無ければフェード用のレイアウトは記録し直されないので、フックも走らない
- フェード中は両方に積まれ、後から再生されるフェード用のぶんが上に出る

同じ絵を 2 回描くだけで、**「フェード中か」を知る必要がなくなる**。
状態を判別しようとして失敗したら、**判別が要らない形にできないかを考える。**
