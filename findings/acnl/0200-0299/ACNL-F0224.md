## F-199: ★★★★★UI の座標系を確定。**縦横で縮尺が違う（非等方）** — `HIGH`（実機で段階的に測定）

### 1. 確定した座標系

| 項目 | 値 |
|---|---|
| 原点 | **画面中央** |
| UI 空間 | **400 x 240 単位** |
| 下画面 | 320 x 240 px |
| **縮尺** | **横 0.8 / 縦 1.0** |

**3DS の UI は上画面の 400x240 で作られ、下画面（320x240）では横だけ 0.8 倍に潰される。**
F-158 に出てくる `400/320 = 1.25` という比と一致する。

```
横の単位 = 欲しい px / 0.8   （= px * 1.25）
縦の単位 = 欲しい px / 1.0
```

### 2. ★正方形の単位で指定してはいけない

8 テクセルのグリフを 3 倍（画面 24x24 px）で出すには **30 x 24 単位**。

**正方形（48x48 など）で指定すると横だけ非整数倍になり、列によって 1px 狭くなる。**
これが「一部だけ 1px 狭い」「縦に 1px 長いのかもしれない」の正体だった。

| 指定 | 画面 px | 倍率 | 見え方 |
|---|---|---|---|
| 48 x 48 単位 | 38.4 x 48 | 横 4.8 / 縦 6.0 | 横だけ不均一 |
| **30 x 24 単位** | **24 x 24** | **3.0 / 3.0** | **完全に均一** |

位置も `X * 0.8` が整数になるようにする（X は 5 の倍数にすれば `X*0.8` が 4 の倍数）。

### 3. ★どう測ったか — 独立した 2 つの制約を突き合わせる

| 段階 | 手法 | 結果 |
|---|---|---|
| 1 | 幅 160/320/480/640 の帯を縦に並べる | 480 からはみ出す -> 画面幅は 320〜480 単位 |
| 2 | 幅 320/360/400/440 | 360 が収まる最大 -> **半幅 < 200** |
| 3 | X = -180/-90/0/+90 の四角 | 原点は中央。**X=-180（左端 -200）が見える -> 半幅 >= 200** |
| 4 | 横 400 単位・縦 240 単位の帯 | **どちらも端にぴったり** |

**段階 2 と 3 は単独ではどちらも「400 前後」までしか絞れないが、
両立するのは半幅 = 200 のみ。** 独立した 2 つの制約を突き合わせて 1 点に確定できた。

**★判定しやすい形にすること。**
「640 の帯 1 本」では「はみ出している」ことしか分からなかった。
**幅を変えた複数本を同時に出す**と目盛りとして使え、1 回で絞れる。

### 4. 私の誤りの経緯

「24 単位で 1.5 倍・48 単位で 3 倍に見える」から **縮尺 0.5 と推定し、検算しなかった。**
実際は横 0.8 / 縦 1.0 で、48 単位は横 38.4px（4.8 倍）だった。
偶然「48 単位で線が均一に見えた」ため誤った確信を持った。

**推定値は必ず絶対基準（画面幅・画面高さ）と突き合わせる。**
