## F-204: ★★★レイアウトの記録は「記録要求フラグ」が立っているときだけ走る — `HIGH`（静的＋実機）

`0x568770` の NOP に相乗りしたのに **発火 0 回**だった。原因は入口の門番。

```
005686D4  PUSH {R3-R5,LR}
005686D8  MOV  R4, R0            R4 = レイアウト
005686DC  ADD  R5, R0, #0x100
00568704  LDRB R0, [R5,#0x1D]    ★= レイアウト+0x11D「記録要求」フラグ
00568708  CMP  R0, #0
0056870C  BEQ  locret_5687B4     ★立っていなければ何もせず帰る
...
005687B0  STRB R0, [R4,#0x11D]   記録し終えたら降ろす（R0 = 0）
```

**独立した 2 つの結果が一致した。**

| 経路 | 観測 |
|---|---|
| 静的 | 上記の門番と、末尾でのフラグ降ろし |
| 実機 | リスト id 8 は 4 秒で 123 回呼ばれるが、入口のフラグは毎回 0（＝素通り） |

つまり**変化したレイアウトだけが記録し直され、静的なものは初回の記録を再生し続ける。**

### 対策と裏付け

入口 `0x5686D4` をフックし、対象のリスト id のときだけ `*(layout+0x11D) = 1` を書く。

- 素の状態でも 4 秒に 738 個のレイアウトが記録し直されている（＝正規の経路）
- 強制後、記録本体の通過数が **738 → 861（＝+123、毎フレーム）** になった
- 数が一致するので「強制したぶんだけ増えた」と言い切れる

### ★記録済みリストに書いたものは消えない

一度追記すると、そのレイアウトが**記録し直されるまで残り続ける**。
フックを外しても画面に残る（実機で上画面に残像が出た）。
掃除するには `*(layout+0x11D) = 1` を 1 回書いて記録させ直す。
