## F-225: ★★★★「開いている間だけ描く」にすると、閉じても最後の絵が残り続ける — `HIGH`（実機）

ユーザー報告:

> メニューを閉じても、メニューの横にあったテキストなどが描画され続けています。
> つまり描画実装の変更を行っておかしくなった可能性が残っています。

**そのとおりで、こちらの実装ミスだった。**

### 何が起きていたか

描画スレッドをこう書いていた。

```cpp
if (g_closing && 時間切れ) { g_closing = false; g_open = false; }
if (g_open || g_closing)      // ★閉じ終わると呼ばれなくなる
    Render(now);
```

`Render()` は毎回 `Begin` -> 積む -> `Flush` で **.bss のチャンク数を書き換える**。
閉じ終わった瞬間に呼ばれなくなるので、**最後に流したチャンク数が残ったまま**になり、
ケーブは同じ絵を描き続ける。

### ★クラッシュにも寄与していた

チャンク数が 0 に戻らないので、**F-223 の「描くものが無いときは記録を強制しない」
という条件から抜けられない**。閉じているのに上画面のレイアウトを毎フレーム
強制し続け、コマンドリストを食い潰す。

**1 つの実装ミスが、見た目の不具合とクラッシュの両方を起こしていた。**

### 対策

**毎回必ず流す。** 閉じているときは `Begin` と `Flush` だけが走り、0 チャンクになる。
費用は 16ms ごとに数語書くだけ。

```cpp
Render(now);   // 条件を付けない
```

### 教訓

**「状態を外へ出す処理」を条件つきで呼んではいけない。**
呼ばなかったフレームは「前の状態が続く」ことを意味する。
出力が持続する仕組み（.bss を読み続けるケーブ、二重バッファ、GPU の状態）では、
**「何もしない」は「前のままにする」と同義**になる。
止めたいなら**明示的に「空」を出す**こと。

### ユーザーの指摘が正しかった

「修正前は問題なく動いていた」「描画実装の変更でおかしくなった可能性がある」という
指摘から入ったことで、クラッシュの原因調査より先にこちらへ辿り着けた。
**症状が増えたときは、直前に何を変えたかを疑う。**
