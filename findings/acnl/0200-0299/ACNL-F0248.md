## F-223: ★★★★描くものが無いのに記録を強制すると、しばらくして GPU コマンドリストが枯れる — `HIGH`（実機）

自前 GUI を ON にして**しばらく遊ぶと**クラッシュした。

```
PC  001216DC   Layout_RecordPaneTree が 0x568724 で呼ぶ関数の中
LR  00568727   呼び出し元は Layout_RecordPaneTree
R12 00AD995C   ★g_GpuCmdListMgr
R4  3F6BEBEC   linear の窓の外。壊れたポインタに見える
R6  00AD98C0   R7 00AD98E4   R2 = 7   R5 = 0x29
```

**コマンドリストの管理側が壊れている。** 我々の描画そのものではなく、
**記録の強制**が原因だった。

### なぜ溜まるのか

段 B で上画面にも描けるようにしたとき、上画面のレイアウト（リスト id 8）にも
「記録要求」フラグを毎フレーム立てるようにした（F-204 の仕組み）。

**下画面のレイアウト（id 15）は素でも毎フレーム記録し直されるが、
id 8 はほとんど記録し直されない。** それを毎フレーム強制すると、
リストの領域が少しずつ食われ、**数分後に枯れる**。

デバッガから 4 秒だけ走らせた検証では表に出なかった。
**「短く動いた」は「長く動く」の証明にならない。**

### 対策

**チャンク数が 0 のとき（＝描くものが無いとき）は強制しない。**
メニューを閉じている間は素の挙動のままになる。

```
R0 == 下画面の確定対象 かつ 下画面のチャンク数 != 0 -> フラグを立てる
R0 == 上画面の確定対象 かつ 上画面のチャンク数 != 0 -> フラグを立てる
それ以外                                          -> 何もしない
```

### 残っている懸念

**メニューを開いている間は id 8 を強制し続ける。** 長く開いたままだと
同じ形で枯れる可能性がある。次に確かめること:

- メニューを数分開いたままで再現するか
- するなら、上画面は「素で記録し直されるレイアウト」を選ぶか、
  リストの残量を見て強制を止める仕組みが要る
