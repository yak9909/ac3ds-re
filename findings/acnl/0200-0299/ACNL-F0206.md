## F-180: ★★★UI 画像を「足す」ことに成功。TODO-122 の主要部達成 — `HIGH`（実機で視認）

適用: `PATCHES/cave_add_quad.py`

### 0. 用語（ユーザーからの指摘を受けて統一する）

内部的には「テクスチャを貼った四角形（quad）」だが、
**画面上ではそれが 1 枚の UI 画像・アイコンそのものである。**

**以後「四角形」ではなく「UI 画像（スプライト）」と書く。**
抽象的な幾何の話ではなく、見えるものの話として書いたほうが誤解が少ない。

### 1. 結果

**ゲームの UI 画像が複製され、大きさを変えて追加表示された。**
コマンドは 1 バイトも書いていない。

やったこと（`sub_4B8360` の入口、カウンタが `(36,37,38) = (1,3,2)` のときだけ）:

1. 行列 3 エントリ（48 バイト）を `[0..3)` から `[3..6)` へ複製
2. 幾何 2 エントリ（32 バイト）を `[0..2)` から `[2..4)` へ複製
3. 複製した幾何の**幅・高さだけ**を 64x64 に差し替え（位置は据え置き。F-168 の教訓）
4. 索引エントリ `[1]` を作る = `(3.0, 3.0, 2.0, [0].w3 の複製)`
5. カウンタを `(2, 6, 4)` にする

3 秒で **2860 回発火**、フォルトなし。

### 2. 索引エントリの意味が裏付けられた

```
w0 = 行列の索引        （複製先 = 3.0）
w1 = 幾何の索引 + 1    （= 3.0）
w2 = 幾何の索引        （= 2.0）
w3 = マテリアル関連    （複製元からコピー）
```

**`w3` を複製元からコピーしているので、テクスチャも複製元のものを引き継ぐ。**
だから「同じ絵が大きさだけ変わって増える」という見え方になる。

### 3. 残っている制御（TODO-123 へ）

- **発火が多すぎる。** 条件に合うバッチすべてで足すので、
  いろいろな UI 画像が複製される。**1 フレームに 1 回だけにする**必要がある
- **テクスチャが複製元のもの。** 自前の絵にするには
  `w3`（マテリアル）を自前のものに向ける必要がある。
  `sub_4B8090(drawctx, picture+320, picture+181)` が `drawctx+1636` を作り、
  それが `w3` になる経路を解く
- 位置の指定（幾何の `X` / `Y`、または行列の平行移動）

### 4. 一度フォルトさせた — リテラルプールの参照ミス

`LDR R3, =VALS` のリテラルが **「VALS のアドレス」ではなく
「VALS の中身（64.0 = `0x42800000`）」を指していた。**
`R3 = 0x42800000` で未マップ領域を読んで停止した。

**再起動は不要だった。**`DOCS/crash_recovery.md` の手順どおり、
フックを素に戻し、`PUSH` に対応する `POP` へ `PC` を進めて復帰、
修正版は I-cache を避けて未実行の番地へ置き直した。

**教訓: `LDR Rn, =X` を自前で組むときは、
逆アセンブラでリテラルの位置と中身を実際に辿って確認すること。**
今回は修正後にそれを行い、ワード 55 の中身が VALS のアドレスであることを
確かめてから走らせた。
