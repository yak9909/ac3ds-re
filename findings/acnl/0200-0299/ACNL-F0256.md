## F-231: ★★★★★リスト id 0 を「未設定」として弾かないと、id 0 のレイアウトと誤って一致する — `HIGH`（実機）

デバッガから入れたケーブでは正しく動くのに、**プラグインでは**

- フェードに隠れる
- 特定のロード画面でクラッシュ（`1216DC` = `g_GpuCmdListMgr` を触る関数）

の 2 つが同時に起きた。

### 原因は 1 つ

**プラグインがフェード候補の id（下 9 / 上 8）を .bss へ書いていなかった。**
`GuiRender::Init` は id 15 / 16 しか書かず、しかも LOG を 0 で埋めるので、
フェード候補は **0 のまま**だった。

```
候補 id が 0  →  フェード用が一致しない        → フェードに隠れる
候補 id が 0  →  **リスト id 0 のレイアウトと一致** → 無関係なリストへ書き込み → 落ちる
```

**1 つの「書き忘れ」が、見た目の不具合とクラッシュの両方を起こしていた。**

### 対策 2 つ（両方入れる）

1. プラグインが `LOG+0xBC` = 9、`LOG+0xC0` = 8 を書く
2. **ケーブ側で「候補 id が 0 なら必ず飛ばす」**（未設定として扱う）

2 が本質。**「設定されていない」と「0 という値」を区別できない設計は危険。**
0 が有効な値として通ってしまう場所では、必ず番兵の検査を入れる。

### ★デバッガ版とプラグイン版で挙動が違ったら、まず「設定の書き漏れ」を疑う

ケーブは同じバイト列（export で一致を確認済み）なのに挙動が違うなら、
**差は .bss の初期化にしかない。**
デバッガ版の install が書いている値を一覧にして、プラグイン側と突き合わせること。
