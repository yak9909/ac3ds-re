## F-185: ★★★フック地点で **`R1` がコマンドカーソル**。任意の GPU コマンドを発行できる — `HIGH`（実機のコマンド列で確認）

### 1. `sub_4B8360` は引数が 2 つ

```
sub_4B8360:  PUSH {R4-R8,LR}     ← ここをフックしている
             MOV  R4, R0         ; drawctx
             MOV  R6, R1         ; ★cursor = コマンドカーソル
```

**decompiler は第 2 引数を落とす**（`ssys::ma::Allocator` F-164、`sub_4B8360` F-170 と同じ罠）。

したがって **`0x4B8360` のフックに入った時点で `R1` がコマンドカーソルそのもの**。
**バッチが流される直前に、自前の GPU コマンドを好きなだけ書ける。**

### 2. 書き方

ケーブ冒頭が `PUSH {R0-R3,R12,LR}` なので `[SP,#4]` が元の `R1`。

```
LDR R2,[SP,#4]        ; カーソル
STR Rx,[R2],#4        ; パラメータ
STR Rh,[R2],#4        ; ヘッダ
...
STR R2,[SP,#4]        ; 進めたカーソルを書き戻す → POP で反映
```

**実機のコマンド列で確認済み。** 書いた 6 組がそのまま並び、
直後にバッチ本体（`80000006 / 000F02C0` = 頂点シェーダ float uniform 転送）が続いていた。

### 3. マテリアルが色を出す経路（`sub_4B7864` = `0x4B7864`）

```c
v20 = *(material + 48) & 3;
v20 == 0:  reg 0x0DB = *(material + 20);
v20 == 1:  reg 0x0DB = *(material + 16);  reg 0x0F3 = *(material + 20);
v20 == 2:  sub_4B84C0(...)     // 別形式
v20 == 3:  sub_4B85D8(...)     // 別形式
```

- **マテリアル `+16` → reg `0x0DB`、`+20` → reg `0x0F3`** — F-157 でテキストの色を変えたのと同一
- Picture のマテリアルは **`*(picture + 316)`**
- **マテリアルが変わるたび `sub_4B8360` を呼んで流す** ← F-183「1 バッチ = 1 マテリアル」の正体
- 状態キャッシュ: `0x97B6FC`（モード0 の 0x0DB）/ `0x97B714`（モード1 の 0x0DB）/ `0x97B72C`（0x0F3）

### 4. ★TexEnv 定数色は、この素材には効かなかった（負の結果）

6 段すべての定数色（`0x0C3` `0x0CB` `0x0D3` `0x0DB` `0x0F3` `0x0FB`）に
緑 `0xFF00FF00` を出したが**見た目は変化なし**。
コマンド列には正しく載っていたので、**発行は成功していて、この素材が定数色を参照していない**。

### 5. ★相乗り先（地図の影）のテクスチャ設定

私たちの挿入位置の直前に、マテリアルのテクスチャ設定がそのまま並んでいた。

| reg | 値 | 意味 |
|---|---|---|
| `0x080` | `0x00011001` | テクスチャ有効化（mask B と mask 4 の 2 回） |
| **`0x082`** | `0x00080008` | **テクスチャ 0 の大きさ = 8 x 8** |
| **`0x085`** | `0x03037AE0` | **テクスチャ 0 のアドレス（PA >> 3）→ PA = `0x181BD700`** |
| **`0x08E`** | `9` | **形式 = LA4（輝度 4 + アルファ 4、色を持たない）** |
| `0x083` | `6` | ラップ / LOD |

**たった 8x8 の LA4。** 色を持たないテクスチャなので、
見えている紫は TexEnv かシェーダ側から来ている。

### 6. ★`VA = PA + 0x10000000` は **VRAM には効かない**

`PA 0x181BD700` は **VRAM**（PA `0x18000000`-`0x18600000`）。
F-124 / F-166 の `VA = PA + 0x10000000` は**リニア FCRAM 専用**の規則だった。
`PA+0x10000000` / `PA` / `PA-0x18000000+0x1F000000` の 3 つとも
768 バイト全部 `0xFF` で読めなかった。**UI のテクスチャは VRAM に置かれている。**

### 7. 次にやること

**reg `0x082` / `0x085` / `0x08E` を自前の値で上書きする**（F-169 で実証済みの手法）。
私たちの発行位置はマテリアル設定の**直後**なので、上書きが効く。
自前バッファは `g_GfxAllocator`（F-165 / F-166）から取る。リニア FCRAM なので
`PA = VA - 0x10000000` が使える。
