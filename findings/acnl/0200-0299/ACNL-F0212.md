## F-186: ★索引エントリの意味を静的に確定。色は複製先ではなく**複製元**に出る — `HIGH`（静的＋実機 A/B 多数）

### 1. 索引エントリの意味（`sub_73CB58` 末尾、静的に確定）

```c
v22 = *(drawctx+1640) + 16 * (drawctx+36);
v22[0] = *(drawctx+1624);   // 行列の索引
v22[1] = *(drawctx+1628);   // 自分の幾何の索引
v22[2] = *(drawctx+1632);   // 追加幾何の索引
v22[3] = *(drawctx+1636);   // ★色
drawctx+36 += 1;
```

**F-180 / F-183 の「w1 = 幾何+1、w2 = 幾何」は誤り。**
正しくは **`w1` = 自分の幾何、`w2` = 追加幾何**（結果的に入れていた値は偶然合っていた）。

### 2. 色を作るのは `sub_4B8090`。2 つの経路がある

```c
if (4 隅がすべて 0xFFFFFFFF)   *(float*)(drawctx+1636) = alpha/255;      // 値そのもの
else                           *(float*)(drawctx+1636) = (float)(+37);   // 索引
                               16 float を *(drawctx+1644)+16*(+37) へ
                               (+37) += 4;
```

**同じフィールドに「アルファ」と「索引」という別の意味が入る。**
実機の複製元は `w3 = 0.275`、触る前の `*(drawctx+1636)` も `0.275` で完全一致（＝アルファ経路）。

### 3. ★`w3` は自前スプライトに効く（決定的観測）

`w3 = 0.1` を入れると**自前の板がほぼ見えなくなった**。`1.0` で不透明。
**したがって索引エントリは確かに自前スプライトのもの。**

### 4. ★しかし色は複製元に出る（未解決）

`sub_4B8090` をケーブから呼び、呼んだ直後に検証した値は**すべて正しい**:

| 確認項目 | 値 |
|---|---|
| `*(drawctx+1636)` | `6.0`（索引経路） |
| 行列配列[6] | `(0,1,0,1)` = 積んだ色そのもの |
| `+37` | `10`（関数が 4 進めた） |
| 自前の索引エントリ `w3` | `6.0` |

`TextDraw_EmitStatePrefix` は `16*(+37)+16` バイト＝**索引 0〜9 全部を転送**（静的に確定）。
**データも転送も正しいのに、色は複製元のスプライトに出る。**

4 隅のアルファを 255/191/127/31 にしたときの実機の見え方:

| | 見え方 |
|---|---|
| 自前の複製先 | **一様に半透明**。色は暗い紫のまま |
| 複製元（地図の影） | **緑＋アルファのグラデーション。しかも REPEAT のようにループ** |

### 5. 試して否定されたもの

| 試したこと | 結果 |
|---|---|
| 索引エントリ `w3` = 6.0（配列索引） | 色は複製元に出る |
| 索引エントリ `w3` = 12.0（uniform 番号 = 索引+6） | 自前はグラデーション状になるが色は変わらず |
| 索引エントリ [0] と [1] を入れ替える | **変化なし。並び順ではない** |
| TexEnv 定数色 6 段（`0x0C3`〜`0x0FB`） | **無反応**（F-185） |
| テクスチャ差し替え（`0x082`/`0x085`/`0x08E`） | **無反応**（F-185） |
| 幾何エントリ `v14[2]` に自前の行列索引 3.0 | **板が消えた** |

### 6. 幾何エントリは S0 / S1 から書かれる

```
0073CCD8  LDM  R3, {R3,R12}     ; picture+72, +76 = 幅・高さ
0073CCE0  VSTM R2, {S0-S1}      ; 幾何エントリ +8 / +12
0073CCE4  STM  R0, {R3,R12}     ; 幾何エントリ +0 / +4
```

`v14[2]` = S0、`v14[3]` = S1。decompiler は S1 を追えていない。
**`v14[2]` に行列索引を入れると板が消えるので、シェーダ側の用途は行列索引ではない。**

### 7. 配列ポインタは実体の 12 バイト先

`*(drawctx+1640)` = `drawctx+148`、ステージング実体は `drawctx+136`（差 12）。
`*(drawctx+1644)` = `drawctx+580`、実体は `drawctx+568`。
フラッシュは**実体の先頭から** `16*個数+16` バイトを流す。
先頭 12 バイトは PICA のバースト用ヘッダ領域。
`TextDraw_EmitStatePrefix` はここで `v5[3] = ヘッダ; v5[2] = 旧 v5[3]` の入れ替えを行う。
**フラッシュ後に配列を読むと「書いた値」ではないので、検証は書いた直後に行うこと。**

### 8. 次にやること

**シェーダが `w3` をどう使うかが唯一の未知。** 取りうる道:

1. **頂点シェーダのバイトコードを読む**（`reg 0x2CB`/`0x2CC` でアップロードされる）。確実だが重い
2. **色を使っている既存スプライトを探し、その索引エントリと色配列を実測で突き合わせる。**
   ゲーム自身が索引経路を使う瞬間を `sub_4B8090` にフックを置いて捕まえる
3. **相乗り先を変える。** 地図の影の素材は 8x8 LA4（色を持たない）。
   頂点カラーを使う素材に乗り換えれば素直に色が出る可能性が高い

**2 が最も安く、確実。** ゲーム自身の正しい組み合わせを 1 例観測すれば、
`w3` に入れるべき値が確定する。
