## F-191: ★★★★自前テクスチャの適用に成功。欠けていたのは `reg 0x083` — `HIGH`（実機）

`PATCHES/cave_add_sprite2.py`（`EMIT_TEX = True`）。

### 1. 結果

**背景が真っ白、自前の板が真っ赤の単色**になった（ユーザー確認）。
**自前バッファに詰めたテクスチャが GPU に読まれている。**

### 2. ★原因は `reg 0x083` を上書きしていなかったこと

`0x082`（大きさ）/ `0x085`（アドレス）/ `0x08E`（形式）の 3 つだけ上書きしていたが、
**`reg 0x083`（ラップ・フィルタ・テクスチャ種別）が相乗り先の値のまま**だった。

| | `0x082` | `0x083` | `0x08E` |
|---|---|---|---|
| 背景（元） | `0x00400040` = 64x64 | **`0x00002226`** | `0x0C` = ETC1 |
| 地図の影（元） | `0x00080008` = 8x8 | **`6`** | `9` = LA4 |
| 自前（成功時） | `0x00080008` = 8x8 | **`6`** | `9` = LA4 |

64x64 ETC1 用のパラメータを 8x8 の非圧縮テクスチャに当てていたので縞模様になっていた。

**動作実績のある構成（地図の影）をそっくり真似て、変える変数をアドレスだけに絞ったら通った。**

### 3. `PA = VA - 0x10000000` は正しかった

`g_GfxAllocator` が返した `VA 0x329D8500` に対し `PA 0x229D8500`（`reg 0x085 = 0x0453B0A0`）で
GPU が読めている。**リニア FCRAM の規則は成立している**（F-124 / F-166 の裏付け）。

### 4. キャッシュフラッシュは不要だった（が害もない）

`svcFlushProcessDataCache(0xFFFF8001, addr, size)` = **SVC 0x54** を毎フレーム呼んでおり
戻り値 `0`（成功）だが、**これを入れても縞模様は直らなかった**ので原因ではなかった。
デバッガ経由の書き込みでも GPU から見えている。

### 5. ゲームの UI テクスチャは全部 VRAM

コマンド列 64KB を走査して `reg 0x085` の異なる値 14 件を集めたところ、
**13 件が VRAM（`0x18086780`〜`0x18091200`）、FCRAM は自前の 1 件だけ**。
GDB スタブは VRAM を読めない（全部 `0xFF` に見える）ので、
**ゲームのテクスチャの中身は覗けない。** 自前テクスチャは FCRAM に置くこと。

### 6. これで揃ったもの

| 要素 | 状態 |
|---|---|
| UI 画像の追加 | 済 |
| 毎フレーム確実に描画（ゼロフレーム 0.00%） | 済 |
| 位置・大きさ | 済 |
| 色（RGB）・アルファ | 済 |
| **テクスチャ（絵）** | **済** |

**★テクスチャはバッチ全体に効く。** 自前スプライトだけ別の絵にしたいなら
マテリアルを分けてバッチを分割する必要がある（未着手）。

### 7. タイリング

3DS のテクスチャは 8x8 タイル・モートン順:
`i = x0 | y0<<1 | x1<<2 | y1<<3 | x2<<4 | y2<<5`
LA4 は 1 バイト/テクセル、上位ニブル = 輝度、下位 = アルファ。

### 8. `reg 0x083` のフィルタビット

`0x083` の bit1 = 拡大フィルタ、bit2 = 縮小フィルタ（1 = リニア）。

| 値 | 見え方 |
|---|---|
| `6` = `110` | 両方リニア。**拡大すると切り替わりがぼやける** |
| `0` | ニアレストネイバー。**くっきり。ドット絵・ビットマップフォント向き** |

wrap（bit 8-15）は両方 0 のままなので変わらない。

### 9. タイリングも含めて絵が出せることを確認

8x8 LA4 にモートン順で 4x4 ブロックの市松模様を書いたところ、
**板は赤と黒、背景は白と黒の市松模様**として正しく表示された（ユーザー確認）。
色（頂点カラー）とテクスチャが掛け算されているのも見て取れる。
