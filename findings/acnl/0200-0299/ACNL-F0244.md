## F-219: ★★★CTRPF のファイルパスはプラグインのフォルダ基準。ON が早すぎると落ちる — `HIGH`（実機）

### 1. SD の画像が読まれず、黙って埋め込みへ落ちていた

`.acgx` を SD に置いてプラグインを ON にしても「ACNL GUI OK」のままだった。
変換したファイルは検査条件を**すべて**通ることを手で確かめてあったので、
問題は読み込み側。

**手がかりは前に得ていた。** ユーザーの報告に
「`CTRPF_OwnGui.txt` は `.3gx` の場所に出来た」とあった。
`File::Open(f, "/CTRPF_OwnGui.txt")` と書いたのに SD の根ではなく
プラグインのフォルダに出来る＝**パスがプラグインのフォルダ基準で解決されている**。

したがって `/luma/plugins/00086200/gui_image.acgx` は
`.../00086200/luma/plugins/00086200/gui_image.acgx` を探しに行っていた。

**★この手がかりは 2 往復前に自分で受け取っていたのに使っていなかった。**
「ログがどこに出来たか」は、パスの解決規則についての観測結果でもある。

対策: **候補を順に試し、どれで開けたかを必ずログに残す。**

```
gui_image.acgx                          （プラグインのフォルダ基準）
/luma/plugins/00086200/gui_image.acgx   （SD の根が基準の場合）
/gui_image.acgx
```

### 2. プラグインが ready になった瞬間に ON にすると落ちる

```
PC 0551C928   （どこにも属さない番地）
LR 061CFCEC   （プラグイン内）
SP 0FFFFE00   （ゲームのメインスレッドのスタック）
R0 32FF62EC   （drawctx）  R4/R9 3225B070（レイアウト）
```

ゲームがまだ描画を始めていない段階で組み込むと、無効な番地へ飛ぶ。
2 回目（ゲームが動いてから ON）は正常だった。

### ★対策は効かなかった。コードは外して保留にした（TODO-133）

試したのは 2 つ。

- `g_GfxAllocator`（`0x0094CA30`）が 0 なら中止する
- 払い出しが linear の窓（`0x30000000` 台。F-124 / F-165）に無ければ使わない

**実機では防げなかった。** ユーザーの判断で保留とし、**修正コードは外した**。
当面の回避策は「ゲームが動き出してから ON にする」こと（2 回目は正常に動く）。

**★効かなかった対策をコードに残さない。**
残すと「対策済み」と誤解し、次に調べるときの出発点がずれる。
観測（レジスタの値）は残し、対策は外す。

### 次に調べるなら

- レジスタから分かるのは「プラグインのコードから無効な番地へ飛んだ」ことだけ。
  **我々のケーブは 1 つも入っていない段階**（確保フックを置く前）でも落ちるのかを
  切り分ける。落ちるならプラグイン/CTRPF 側の初期化の問題で、こちらの領分ではない
- `PatchProcess` / `main` のどちらで組み込むかによる違いも未確認
