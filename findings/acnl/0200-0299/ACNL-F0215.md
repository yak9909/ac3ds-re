## F-190: ★★★★色・位置・大きさの完全制御を達成。詰まっていた原因は**アンカー** — `HIGH`（実機）

`PATCHES/cave_add_sprite2.py`（色つきバッチに相乗り）。

### 1. 原因はアンカー（基準点）だった

幾何エントリの後ろ 2 ワードは**アンカーのオフセット**で、中央揃えなら
**`(-幅/2, +高さ/2)`**。実測が規約をはっきり示している。

| 幾何エントリ | 幅 | 高さ | アンカー X | アンカー Y |
|---|---|---|---|---|
| `(16, 16, -8, 8)` | 16 | 16 | -8 = -幅/2 | 8 = 高さ/2 |
| `(36, 9, -18, 4.5)` | 36 | 9 | -18 = -幅/2 | 4.5 = 高さ/2 |

**幅・高さだけ書き換えてアンカーを複製元のまま残すと、釣り合いが崩れて画面外へ飛ぶ。**
複製元が全画面の背景（アンカー -160/+120 相当）だったため大きくずれていた。

これが F-186 以降ずっと「自前スプライトが見えない」原因だった。
旧バッチ（地図の影）はアンカーが小さかったので、そのままでも画面内に残っていた。

### 2. 切り分けの経過（1 変数ずつ）

| 段階 | 行列 | 幾何 | 色 | アンカー | 結果 |
|---|---|---|---|---|---|
| 全部自前 | 3 | 3/2 | 7 | 複製元のまま | 消えた |
| 行列だけ | 3 | 1/0 | 3 | — | **左上へ移動** |
| ＋幾何 | 3 | 3/2 | 3 | 複製元のまま | 消えた |
| ＋アンカー修正 | 3 | 3/2 | 3 | -64/+48 | **小さくなって左上に** |
| ＋色 | 3 | 3/2 | **7** | -64/+48 | **真っ赤になった** |

**複数の値を同時に動かして誤診を繰り返したのが遠回りの原因。**
「最小構成で検証してから広げる」を守っていれば早く着いた。

### 3. 1 枚のスプライトを完全に決めるのに必要なもの

```
索引エントリ（*(drawctx+1640) + 16*n）
  w0 = 行列の索引          -> 位置（行列の平行移動を書き換える）
  w1 = 自分の幾何の索引    -> 大きさ・アンカー
  w2 = 追加幾何の索引      -> UV
  w3 = 色ブロックの索引    -> 4 隅の色（左上→右上→左下→右下、各 (R,G,B,A)）

行列（*(drawctx+1644) + 16*w0）  3 エントリ。行 0 の w が X、行 1 の w が Y
色  （*(drawctx+1644) + 16*w3）  4 エントリ
幾何（*(drawctx+1648) + 16*w1）  (幅, 高さ, -幅/2, +高さ/2)
```

カウンタ `+36`（索引の数）/ `+37`（行列＋色の数）/ `+38`（幾何の数）を合わせる。

### 4. 相乗り先は `+37` で見分ける

| `+37` | 中身 |
|---|---|
| 3 | 行列 3 エントリだけ = **色を持たない**（w3 はアルファとして解釈される） |
| 7 | 行列 0..2 ＋ **色 3..6** |

**色を使いたいなら `+37 = 7` のバッチに乗る。**

### 5. 色はテクスチャへの掛け算

真っ赤にしても模様がうっすら残る。鮮やかな色や自前の絵が要るなら
テクスチャの差し替え（F-185 の reg 0x082/0x085/0x08E）が引き続き必要。

### 6. ★実機で最終確認（追加モード）

```
ゲームのエントリ [0] = 0.0 / 1.0 / 0.0 / 3.0   （無傷）
自前のエントリ   [1] = 7.0 / 3.0 / 2.0 / 10.0  （追加）
```

**「背景は元通りで、左上に赤い板が 1 枚増えました」**（ユーザー確認）。

配置:

| 索引 | 用途 |
|---|---|
| 0..2 | ゲームの行列 |
| 3..6 | ゲームの色ブロック |
| 7..9 | **自前の行列** |
| 10..13 | **自前の色ブロック** |

カウンタ: `+36 = 2` / `+37 = 14` / `+38 = 4`

**GPU コマンドは 1 バイトも書いていない。** 配列にエントリを足してカウンタを増やすだけ。
