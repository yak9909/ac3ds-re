## F-195: ★★★★★自前ビットマップフォントで文字列を描画。描画順も制御 — `HIGH`（実機）

`PATCHES/cave_draw_sprites.py`。**「ACNL が地図の上に表示され、読めました」**（ユーザー確認）。

### 1. 複数枚をまとめて描く

スプライトの表を `.bss` に置き、ケーブ側はループにした。**枚数を変えても同じコード。**

```
1 枚 = 20 ワード（80 バイト）
  +00 X    +10 幅      +20 u0   +30 行列の索引(float)
  +04 Y    +14 高さ    +24 v0   +34 自分の幾何の索引(float)
  +08 Z    +18 -幅/2   +28 u1   +38 追加幾何の索引(float)
  +0C -    +1C +高さ/2 +2C v1   +3C 色の索引(float)
  +40 行列配列のバイトオフセット  +44 幾何配列  +48 索引配列
```

**★索引もバイトオフセットも全部 Python 側で計算して表に入れる。**
そうすればケーブ側に整数→float 変換（VFP）が要らず、命令数と失敗の余地が減る。

配置:

| 領域 | 割り当て |
|---|---|
| 行列 | `3k`..`3k+2` |
| 幾何 | `2k` = UV / `2k+1` = 幅・高さ・アンカー |
| 色 | `3N`..`3N+3`（全スプライト共有） |
| カウンタ | `+36 = N` / `+37 = 3N+4` / `+38 = 2N` |

**上限は `+37 + 7 > 32` より N <= 7。** それ以上はフラッシュを繰り返せば伸ばせる。

### 2. ★★描画順は「フレーム内で何回目のフラッシュか」で決まる

**1 フレームに `DrawCtx_FlushBatch` は約 42 回呼ばれる**（実測）。
最初の方に相乗りすると、あとから描かれる UI（地図など）に覆われる。

**そのフレームの最後のフラッシュで描けば最前面になる。**

やり方: 前フレームの総フラッシュ回数を覚えておき、
今フレームでその回数目に達したときだけ描く。

```
cnt++;  if (cnt != total) skip;      ← 描画ケーブ
total = cnt;  cnt = 0;               ← Render_FrameEnd のケーブ
```

1 フレーム遅れで追従するが、実測では毎フレーム 42 回で安定していた。

**★相乗り先が「色つきバッチ」である必要はもう無い。**
行列・色・幾何・カウンタ・テクスチャを全部自分で組むので、条件は外せる。

| | 相乗り先 | フレーム内の位置 | 結果 |
|---|---|---|---|
| 条件 `(1,7,2)` の最初 | 42 回中 1 回目 | 地図に覆われる |
| 条件 `(1,7,2)` の最後 | 42 回中 3 回目 | まだ覆われる |
| **条件なしで最後** | **42 回中 42 回目** | **最前面。読める** |

### 3. フォントアトラスの作り方

64x64 の LA4（4096 バイト）に 8x8 のグリフを並べる（8x8 = 64 文字ぶん）。

- **文字部分 = `0xFF`（L15/A15）、背景 = `0x00`（L0/A0）**。
  背景のアルファが 0 なので、文字の形だけが浮かぶ
- タイリングは 8x8 タイル・モートン順、タイルは行優先
  `byte = tile*64 + (x0|y0<<1|x1<<2|y1<<3|x2<<4|y2<<5)`
  `tile = (y>>3)*(幅>>3) + (x>>3)`
- 列 `k` のグリフの UV = `(k/8, 1.0, (k+1)/8, 1-1/8)`

**インクの色は頂点カラーで変えられる。**
ドロップシャドウは、同じ文字を少しずらして暗い色でもう 1 枚描けばよい。
