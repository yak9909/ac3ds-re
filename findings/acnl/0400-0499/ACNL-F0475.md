## IDA-opus-5.5-F058: 村の物体の描画の仕組み — 1 体ずつ色を変える入口と、カーソルが消えた原因（2026-09-28、MEDIUM: 静的＋停止中の実機の読み取り。赤の割り込みは実機未確認）

解析ソフト: IDA（主 IDB を idalib-mcp で静的、停止中の実機を ida-pro-mcp で読み取りのみ）/ 解析モデル: opus-5.5。
利用者の指示（2026-09-28）: 赤はモデルそのものに、選択範囲内の同じモデルは共有して。範囲を引いている途中も出す。大きな範囲でカーソルが出なくなる → ヒープの扱いを再設計。

- **カーソルが消えた原因（実機、読み取りのみ。3gx は d3438f5）**: GridCursor は stage 8 Failed / 理由 4 kInstanceHeap、heapCursors 24。
  親ヒープ `*0x94CC48` = sead::ExpHeap 0x301668EC（vtable 0x8FFEF8、総量 0xEB8000）の空き 503,480 B（3 塊、最大 482,732）。24 体の組み直しに要る量は 245,760 B
  （0x8000 + 24 × 6144 + 0x4000 + 0xC000）。マップエディターの複製のヒープ 0x40000 = 262,144 B を借りている間は 241,336 B しか無く足りない。
  **失敗すると Failed のまま二度と組み直さない**ので、借りている物が返っても出なかった。GridCursor はカーソル 1 個に体 1 つ（6 KB）でヒープが数に比例する。
- **村の物体の描画**: fgobj::Proc の FuncNode（fgobj_Proc_Setup 0x59CDD0 → g3d_FuncNode_Create 0x4EFFB4 / SetCallbacks 0x4EFF58、cb = sub_59BFEC / sub_59A900）→
  `sub_59A918(proc, ctx, 描画リスト)`: 視点 = `sub_711A8C(&unk_ABD380, 1024)` の 48 B、リストの物体ごとに **`off_948F90`[obj+0x11D]**（{関数, adj} のメンバ関数ポインタ）を (obj, ctx, &視点) で呼ぶ。
  表は `0x948E5C + 0x134`（0x59A92C `LDR R8,=0x948E5C` / 0x59A968 `ADDNE R10,R8,#0x134`。定数 0x948E5C の全 67 か所のうち +0x134 を作るのはここだけ）、.data の初期値 {0x58F6B8, 0}, {0x58FA78, 0}。
- **種類 0 `sub_58F6B8`**: `sub_58F984(obj, 視点)`（体 +444 = 視点 × 体の行列）→ 材質 `sub_494B1C`（材質番号 obj+116 が前回 `dword_948E98` と同じなら省く。旗 0x10000000 なら proc+4458×4 の共有体の材質）→
  形状 `sub_4957BC`（`dword_948E94/9C`）→ **obj+120 の関数を (obj, ctx) で呼ぶ（0x58F864）** → obj+104 & 0x800 なら `sub_58F0D0` → 描く `sub_48D4DC` →
  0x800 なら `E94 = E98 = -1, E9C = 0, sub_4EF898(0x1FFF)`（0x58F8A8〜0x58F8C4）。
- **種類 1 `sub_58FA78`**: `sub_58F984` → キャッシュを捨てる → メッシュ（体 +0x170..+0x174 の自己相対、空なら資源 +0xB8 の +0xB4 個）ごとに `sub_48D26C(ctx, mesh, node)` =
  `ctx[2]+0x20 = node+0x164[mesh+0x1C]` → `gfx_RenderContext_BindMaterial(ctx[2], 0)` → `sub_4957C4(ctx[2], mesh)` → `sub_48D51C(ctx, node, 資源+0xC8[mesh+0x18], mesh+0x28)` → `Mem_CopyBytes(g_GpuCmdPtr, mesh+0x68, mesh+0x6C)`。
- **フェード `sub_58F0D0`**: TEV 段 5 を `sub_34A178(buf, 5)` で初期化し、α = obj+288 で上書き、`sub_72721C(buf, p)` で 6 語（ヘッダ 0x804F00F8）を積む。
  → **段 5 は村の物体でゲーム自身が上書きする段**。TEV 段の 24 B: [0] RGB 合成 [1..3] 演算子 [4..6] 入力 [7] 倍率 [9] α 合成 [10..12] [13..15] [16] [18..20] 定数 RGB [21] 定数 α [22] u16 レジスタ。
- **材質の深度**: 季節資源の材質 +284 = 0x41（+288 ヘッダ 0x00010107）= 深度テスト有効・LESS。同じ形を同じ深さで重ねると負ける（1.04 倍に広げて重ねていた理由）。
- **gohan 0e1082d の赤**: 表の 2 語を包み関数へ差し替え、選んだマスの物体だけ材質を結んだ直後に段 5 = 定数色（赤）×定数α + 前段 ×(1−α) を積み、描いたあと 0x800 と同じ手順でキャッシュを捨てる。
  種類 0 は呼んでいる間だけ obj+120 を自前にして元の関数を先に呼ぶ、種類 1 は `sub_58FA78` / `sub_48D26C` と同じ手順を写す。体・ヒープ・材質の書き換えは無い。
- **F056 の訂正**: 「材質の物体は同じモデルの実体で共有」（1 体を書き換えたら同じモデルが全部赤くなった）は、種類 0 の材質キャッシュ（`dword_948E98` が同じなら結び直さない）でも同じ見え方になる。**共有とは断定できないので取り下げて未確定に戻す**。
- 反証条件: 実機で赤が選んだ物体に乗らない、同じモデルのほかの物体にも赤が漏れる、フェード中以外で見た目が崩れる。段 5 を材質が使っている物（ゲームのフェードも上書きするので無いと見ている）。
