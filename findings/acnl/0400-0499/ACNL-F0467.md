## IDA-opus-5.5-F066: マイデザインは村の物体の「層 1 の一覧」で描かれる — F064 の訂正と、カーソルを「マイデザインより上・それ以外より下」にする設計（2026-09-28、MEDIUM: 静的＋実機の結果と整合。設計は未実装）

解析ソフト: IDA（主 IDB を idalib-mcp で静的）＋ romfs の Fg.bin / FgShape.bin / 解析モデル: opus-5.5。
利用者指示: UnitCursor もマスの色と同じく「地面に張り付いた物（当面マイデザインだけ）より上・それ以外より下」。マイデザインの上だけ透明度を下げる。建物の入口などの Z-Fighting を避ける。
- **マイデザインの判定**: 0x7683E4 = (item & 0x7FFF) == 0x9D（**Item_IsMyDesign** と命名）。0x9D = Pattern（ID 一覧）、Fg.bin[0x9D]+12 = 形 76 = fg_mydesign（形 76 を使うのは 0x9D だけ。FgShape.bin 22 B/件、+5 = 名前）。
  物体の +100 にアイテムが写される（fgobj_Object_BuildForItem 0x58FB40 の Item_Copy）ので、物体からは (*(u16 *)(obj+100) & 0x7FFF) == 0x9D で判定できる。
- **マイデザインは層 1 の一覧**: fgobj_Object_CreateModel（0x58F044）だけが呼ぶ **fgobj_Object_SetupDrawKind 0x58F3B4** が、マイデザインなら
  描く前の関数 obj+120 = **fgobj_MyDesign_PreDraw 0x58F5FC**（PICA 0x085 = テクスチャ 0 の番地を *(dword_948E68 + 11048 + 4·obj[286]) >> 3 に。図案ごとのテクスチャ）、
  砂 / 土で拡大率、obj+286 = 図案の番号（< 0x28）、**obj+104 |= 0x20000（0x58F540）** → sub_59C778 で proc+13752（層 1）へ入り、cb1 0x59BFEC で描かれる。
  0x20000 を立てる所は全部で 4 か所（code.bin の ORR 即値の総当たり、fgobj 付近）: 0x58F540（マイデザイン）・0x58F590（区分 140）・0x58FCDC（穴 0x9E）・0x59474C（消える途中 0x20800）。
  ★**F064 の「0x20000 を立てるのは 0x594748 だけ → マイデザインは層 0」は誤り**（走査の範囲が狭かった）。
- **実機の結果と整合**: マスの色を 段 0 = 層 0 の後・段 1 = 層 1 の前 に描くと、どちらもマイデザイン（層 1 の一覧・不透明）より前なので上から塗られて下に出た。
  段 2 = 自前の描画ノード（村の物体の描画ノードより後）ではマイデザインの後なので、深度テスト（LESS）でマイデザインに勝って上、手前の物には深度で負けて下。利用者の見立て（深度テストでマイデザインが負ける）と一致。
- **一覧の形**（sub_13F84C 追加 / sead_List_UnlinkAll 0x133B20）: 一覧 = {+0 ?, +4 先頭, +8 末尾}、ノード = obj+12 {+4 前, +8 次, +12 = 物体}。fgobj_DrawList 0x59A918 は先頭から辿り、
  off_948F90[obj+285] で描き、最後に一覧を空にする。前後でキャッシュ（0x948E94 / 98 / 9C）と sub_4EF898(0x1FFF) を戻すので、一覧を分けて 2 回呼んでも状態は漏れない。
- **設計（未実装・利用者の承認待ち）**: 村の物体の描画ノードの cb0 を包む（既存の InstancedDraw::UnderCb0）:
  1. 層 1 の一覧（proc+13752）からマイデザインのノードだけを自分の一覧へ移し、fgobj_DrawList(proc, ctx, 自分の一覧) で描く（ゲームの関数で描く。描く中身は変えない）。
  2. UnitCursor とマスの色を描く（深度を書かない・深度テストは今のまま = マイデザインに勝つ高さ）。
  3. ゲームの 0x59A900（層 0 の残り = 建物・入口・木など）。後から描くので、カーソルは深度で競わずに上から覆われる → **Z-Fighting が起きない**。
  マイデザインの上に出すカーソルだけ別の体（透明度を下げる）にする。
  懸念: マイデザインを層 0 の前へ移すので、層 0 で描かれる半透明の物（影など）がマイデザインの上に重なるようになるかもしれない（元は層 1 で後から上書き）。実機で確かめる。
- 反証条件: 設計どおりにしてもマイデザインがカーソルの上に出る、マイデザインが消える・ちらつく、入口でカーソルがちらつく。
- **実装（gohan d5d468b、実機未確認）**: InstancedDraw の cb0 の包みで、登録（SubmitUnder）があるフレームだけ DrawGroundFirst → マスの色（underFirst）→ カーソル → 0x59A900。
  マスの色も SubmitUnder へ（村の物体の描画ノードが無い場面だけ自前ノード）。成果物の逆アセンブル: 一覧 = proc+13752（先頭 +13756 / 末尾 +13760）、比較 = ldrh [obj,#100] & 0x7FFF == 157、
  呼び出し = 0x59A918(r0 = proc, r1 = ctx, r2 = s_groundList 0x071F85C8)、userdata と比べるのは s_underProc（0x071F85B4、nm）。cb0 0x59A900 は最後が NOP で 0x59A918 へ落ちる（BL ではない）、
  cb1 は B。ADD 即値から 13740 / 13752 を検査で確認（verify_map_editor 群 15）。
- **未実装: マイデザインの上だけカーソルを薄く**。いまの色付け（PlanBlock の段 5 = 定数アルファで補間）は定数アルファが色の強さなので、アルファだけ下げられない。
  MakeAlphaScaled（色 = 前乗算のスクリーン、アルファ = 元 × 定数）にすると削除（赤）・スポイト（青）の見え方が変わる。UnitCursor の TEV の空き段の解析が要り、
  第 2 段の「真ん中以外を薄く」と同じ仕組みなので一緒に行う。
