## IDA-opus-5.5-F033: 複製の光＝BsLightMgr の組のフラグメント方向光・アンビエント・半球。向きはゲームのカメラの view で変換されるので専用カメラと食い違う。描く間だけ自前の組に差し替える（2026-09-24、MEDIUM（静的＋実機の読み取り）。gohan の直しは実機未確認）

- **利用者の実機確認（gohan 8908f5d）**: ズボンは付いてくる、髪 -1 で戻る（F032 の 2 点は確認済み）。傾きは 45 度ぐらいが良い。傾けるとポリゴンがおかしい／影が変な所に出来る気がする。
  髪を変えても同じライティングになったが「左下から小さいポイントライトを当てているような見え方で、当たらない所は暗い」。全体的に明るく（白飛びしない範囲で）、周りの光に左右されないこと。
- **F032 の訂正**: `Render_DrawSceneIndexed 0x4EEDD8` は `dword_94959C`（BsLightMgr、`BsLightMgr_Create 0x190D28`）があるとき `sub_1902D0` で **`dword_98529C[4]`** を詰めて描画の文脈へ渡す。
  `dword_9C3088` は無いときの経路で、F032 はこちらを読んで「空」と判断した。
- **実機（`tools/models3d/probe_bs_lights.py` → `work/evidence/models3d/bs_lights.json`）**: 管理役の +28 から方向光 2（g3d::DirectionalFragmentLight。組ビット 0x9 / 0x2）、+76 にアンビエント 1、+92 に半球 1。
  組 0 = アンビエント・半球・方向光 0、組 1 = 同・方向光 1、組 2 = アンビエントだけ、組 3 = 組 0 と同じ。資源の欄: +0xB4 有効、+0xB8 種類（0 = 方向）、+0xFC..+0x108 色（0xAABBGGRR）、
  アンビエントは +0xC8、半球は +0xB8 地面色・+0xC8 空色（float4）・+0xD8 向き・+0xE4 補間。
- **静的（逆アセンブル）**: 描画の文脈（`*(0x94CA44)`）+64 がライトの状態。`gfx_RenderContext_BindMaterial 0x494B4C` → `sub_49586C` → `sub_49AD20(ctx+64, 材質の組番号 ResMaterial+664)` が
  組の表（ctx+64+144 の先 4 本）から +12 アンビエント・+16 半球・+68..+72 フラグメントを写す（番号が前と同じ +156 なら何もしない）。
  フラグメントの向きは `sub_494E20` が **ctx+164 のカメラ（ゲームのカメラ）の view（+328）** で `-(V*dir)`（dir = ライト +380）にして送る。半球の向きも `sub_495624` が同じ view で変換（頂点シェーダ c22〜c24）。
  色は `sub_4AFA0C`（材質の適用から）が材質の色と掛けて 0x140+16n と大域アンビエント 0x1C0 へ送る。
  **Render_DrawSceneIndexed の頭 `sub_4EFA00` → `sub_49489C` → `sub_49AE18`** がライトの状態を毎回初期化する（番号 -1・変更印）→ 記録・再生のたびにライトは送り直される。
- **食い違いの理由**: 複製は専用カメラ（回転なし）の view で法線を出すのに、光の向きはゲームのカメラの view で送られる → 光が別の向きから当たる。環境（時間・部屋）で色も変わる。
- **直し（gohan、実機未確認）**: late pass の間だけ組の表 4 本を自前の組へ差し替え、`sub_49AE18` で初期化してから描き、戻して再び初期化する。自前のライトは今の組のライトを写したもの
  （vtable などはそのまま）で、色（アンビエント 0.35・方向光のアンビエント 0.15・ディフューズ 0.5・スペキュラ 0.15・半球は空と地面を同じ 0.2）と向き（`dir = -V^T L`、L は専用カメラから見て正面やや左上）だけ変える。
  メニュー「複製の明るさ」（百分率、既定 100）。傾きの既定は 45。検査 `tools/models3d/verify_player_clone.py` 群 7。
- **★実機 SIGSEGV（gohan 18e4130、画面に固定を ON）**: PC 0x495998（`sub_495994` のベクトル変換）、LR 0x494FF4（`RenderContext_SendFragmentLight`）、行列の番地 R2 = 0x148。
  その時点の描画の文脈: +164 = 0、+160 = 0、+184 = -1、+64/+68 = 自前のライト。**`LightState_Reset 0x49AE18` はライトの状態の後ろ（state+96 / +100 / +120 = 文脈 +160 霧 / +164 カメラ / +184）も消す**
  （`str ip,[r0,#96]` / `str ip,[r0,#100]!` / `str r5,[r0,#20]`）。ゲームは直後の `sub_4EFA00` でカメラを入れ直すが、gohan は入れ直していなかった（F033 の読み落とし）。
  直し gohan 45d66af: `ResetLights` が初期化の前に 3 語を読み、後で戻す（ELF の逆アセンブルでも確認）。検査 verify_player_clone に照合を追加（0 failed）。実機未確認。
- **利用者の実機確認（gohan 45d66af）**: 落ちずに表示、全体的に明るい（明るさ 130 がちょうど良い）、傾けてもポリゴンの乱れ・影は出ない、世界側の光は変わらない。
  ただし**屋外では光が左下から、屋内では左上から**見えた（狙いは左上）。屋内では差し替えが効いて狙いどおり → 向きの計算は正しい。
  屋外は写し元のライトが無く `BuildLights` が false を返し、ゲームのライトのまま描いていたと推定（F032 で空の組 `dword_9C3088` を読んだのはおそらく屋外）。**仮説・実機未確認**。
  直し gohan（次の commit）: 写し元が無いときは RTTI の vtable（nw::gfx::AmbientLight 0x8FB6B4 / FragmentLight 0x8FB7A4 / HemiSphereLight 0x8FB8FC）を持つ 0 埋めのライトを一から作る。
  組の表はゲームの配列に書かず、文脈 +64+144 のポインタを自前の 4 本へ向けて戻す。向きは利用者の希望で左下（L = (-0.3, -0.4, 1)）、明るさの既定 130。
  状態の通知に「光 回数/写し元ビット」を出す（屋外で /0 なら上の推定どおり）。
- **★利用者の実機確認（gohan 41b7aaa、2026-09-25）**: 屋内外を問わず同じ見え方、光は左下から。明るさ 100・他は既定で良い（gohan dff9bf5 で既定 100）。
  **プレイヤーモデルの UI オーバーレイ（2D UI が複製より手前に出る）は利用者の想定どおり**（直さない）。光の設定項目は今後も使うので残す。F033 は HIGH（静的＋実機＋利用者確認）。
- **★屋外で暗い・光の向きが場面で変わる本当の原因（2026-09-25、HIGH: 静的＋実機の命令捕獲）**: キャラクターのシェーダは法線を頂点シェーダの **c3〜c5** で回す。
  c3〜c5 は描画ごとに `RenderContext_SendModelMatrices 0x495A10` / `RenderContext_SendModelViewOnly 0x495538` が **ノード +444**（Scene の更新が**ゲームのカメラ**で
  計算した model-view）から送る（c0〜c2 = ノード +140 か単位行列、送った後 ctx+28 = ノード）。位置は専用カメラ（c86〜c92、CameraBind）で決まるが、法線はゲームの
  カメラ基準のまま → 専用カメラ基準で送る光と食い違い、屋外（カメラの上下が逆）で暗く平らになった。
  根拠: late pass の命令捕獲（`tools/models3d/probe_cmd_range.py` → `cmd_range_clone_indoor/outdoor.json`）で、複製の描画の GPU 状態は屋内・屋外で
  c3〜c5（= それぞれのゲームのカメラの view）・c24 以外同一。ブレンドは不透明（0x101 = 0x01010000）、影・霧・位置・半球の補間・Fader・レイアウトは実験で否定
  （画像 `work/evidence/screens/clone_light_20260924/`）。ゲームの view は屋内・屋外とも正規直交。
  直し gohan 41b7aaa（実機未確認）: 描く間だけ体と部品のノード +444 を V_専用 * V_ゲーム^-1 * (+444) に置き換え、描いた後に戻して ctx+28 を 0 にする。
- **傾けたときの「影」**: 45d66af で出なくなった（利用者）。光の向きの食い違いが原因だったと見る（影マップ説は不要になった）。
- **（旧）未確認**: 傾けたときの「影」。複製は y=-5000 にいるので、影マップ（`off_94A44C` BsShadowMapMgr）の投影が関わる可能性がある（仮説・LOW）。光を直した版で利用者に見てもらってから調べる。
