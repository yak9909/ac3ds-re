## IDA-opus-5.5-F056: 村の実体の材質は同じモデルで共有、書き換えるとゲームの書き出しが落ちる／参照表の安全条件（2026-09-28、HIGH: 実機のクラッシュと静的）

解析ソフト: IDA（ida-pro-mcp で停止中の実機を読み取りのみ、主 IDB）/ 解析モデル: opus-5.5。gohan 165b571 の実機確認で「触っていない同じモデルも赤い」「しばらく使うと落ちる」。
- **実機のクラッシュ**: PC = LR = 0x4B0C54（MaterialActivator_SendFragmentLuts）、R0 = 0。戻り先 0x4A1F34 = SimpleMaterialActivator_Activate 0x4A1F30 から。
  参照表 R4 = 0x30CB73CC（季節資源 proc+0x34 = 0x30C91E00 の中）の 4 番目の項目の参照が `0x40000000` 型で +12 = 0 → `sub_4A583C` が NULL → +8 を読んで落ちた。
  このとき gohan は実体 1 体の材質（M+48 / M+72）を自前の写しへ向けていた（s_hiCount 1）。
- **材質の物体は同じモデルの実体で共有**（bufferOption 0）: 1 体の材質を書き換えると同じモデルの全部が赤くなった（利用者の目視）。→ 実体の材質は書き換えない。
- **書き出しの参照表**: 簡易版（0x4A17B8）は M+8（資源）の +0x288 → +0x28 の表（0x4A1EEC / 0x4A1F00）、汎用（0x49C08C）は TEV の部分の +0x288 → +0x28 の表（0x49C7F0 / 0x49C800）を
  前回と違えば必ず `SendFragmentLuts` へ渡す（0 なら NULL を渡す）。表の 6 項目は相対（0 は飛ばす）、項目 +8 の相対の先を `sub_4A583C` が解く: `0x80000000` = そのもの、
  `0x40000000` = +12 の相対の先（0 なら NULL）、ほかは NULL。→ 自前の体は「全部解ける表」か「全部 0 の表」だけを指させる。
- **体の欄**: `nwgfx_TransformNode` ctor 0x497F4C が +8 = ResModel（STMIA R4,{R0,R1,R5}）、+0x4C = 行列、+124〜+132 = 拡大率 1.0。
- 対処（gohan ca85896、実機未確認）: 赤は実体の体 +8 の資源から自前の体（0x834）を作って赤を混ぜ、実体の行列・拡大率を写して 4% 大きく重ねる。
- **追記（2 回目の実機クラッシュ）**: 自前の体でも 0x4B0C54 で落ちた（戻り先 0x49C818 = 汎用）。汎用は参照表を**ライティングの部分 M+0x44** から読む
  （0x49C53C `LDR R0,[R8,#0x44]` → SP+0x60 → 0x49C7EC で +0x288 → +0x28）。M+0x48 だけ写しへ向け、M+0x44 は資源のままだった
  （停止中の実機で材質 0x30FD9038: M+0x48 = 写し 0x30FD90BC、M+0x44 = 資源 0x30C9FBDC）。+0x288 を辿る部分は M+0x40/0x44/0x48/0x4C、表まで読むのは 0x44 だけ。
  bufferOption 0x834 で体ごとに写されるのは M+0x30 / 0x38 / 0x3C / 0x50。
- 反証条件: M+0x44 も写しへ向けたあとでも同じ位置（0x4B0C54）で落ちる、重ねた赤が実体とずれる。
