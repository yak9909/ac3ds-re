## IDA-opus-5-F028: 模様替えカーソルは大きさを変えていない。V2-F019 の「範囲の形」は誤り（2026-09-21、HIGH、静的）

解析ソフト: IDA / 解析モデル: opus-5。**既存記録 V2-F019 の訂正**（`work/evidence/unit_cursor/README.md` §5.3〜5.4、
`0x00690B68` の IDB コメント）。利用者から「模様替えの UnitCursor と同じやり方で大きさを変えたい」と
依頼を受けて中身を確かめたところ、土台にしようとした記述が二重に誤っていた。

### 誤り1: `0x00690B68` の引数はアイテムIDではなく**16bit 角度**

`ModuleIndoor.cro 0x00B1A0C4` は `ModuleFtr:seg0+0x1ECE0(家具)` が返すポインタを
**そのまま** `0x00690B68` へ渡し、同じポインタの u16 を毎フレーム更新（`0x00B1A15C`）で
`0x005669A0` の第2引数にも渡している。そして **`0x005669A0` は Y 軸回転（16bit 角）**
（`[cos 0 sin; 0 1 0; -sin 0 cos]` を `sub_14F4C0` で合成）。
同じ u16 が角度として使われている以上、`0x690B68` が読むのも角度である。

`0x690B68` は `v = (角度 >> 12) & 0xF` から `(v + 2) >> 2` を返す。0/1→0、2〜5→1、6〜9→2、
10〜13→3、**14,15→0**。この 14,15 の巻き戻りが「大きさ」では説明できず、
**0°・90°・180°・270° を中心とする象限**そのもの。

### 誤り2: `UnitCursorRotate` は「範囲の形」を選んでいない

`UnitCursor.bcres` を直接読むと:

- **可視性アニメは1本も無い**（辞書スロット11が存在しない。スロットは 0=モデル / 1=テクスチャ / 10=マテリアルアニメ）。
  よって「アニメの `IsBranchVisible` で枝を出し入れして形を選ぶ」は**できない**。
  文字列表に `IsBranchVisible` や `UnitCursorLine` があるのは、資源の文字列表が
  「ありうる対象名」を持っているだけ。
- `UnitCursorRotate` のメンバは **`Materials["m_UnitCursor"].TextureCoordinators[1].Rotate` の1つだけ**。
  曲線の値は **0.7854（π/4）と 2.3562（3π/4）** ＝ 斜線テクスチャの向きを 45° / 135° に振るもの。
  テクスチャは `UnitCursor` 128×128 と **`UnitCursorLine` 32×32** の2枚で、回転が掛かるのは後者。

### 実際のところ

毎フレーム更新 `0x00B1A15C` が組む行列は **対角が 1.0（リテラル `0x00B1A2E8` = `3F800000`）、
他が 0.0** の単位尺で、位置は家具の座標、そこへ Y 軸回転を合成するだけ。
**枠1つ＝家具1つで、カーソルの面積は一切変わらない。**
`UnitCursorRotate` のフレーム 0〜3 は家具の向きに斜線を合わせるためのもの。

### 利用者の推測との関係

利用者の「1マスごとに一つの UnitCursor を生成していそう」は**ゲームの実装とは違う**
（ゲームは家具1つにカーソル1つ）。ただし**任意の大きさ（1x1 / 2x1 / 3x3）を出したいなら
1マス1体が正しい道**で、IDA-opus-5-F017 が**12体でもフレーム落ちが測れない**ことを実測済み。
3x3 なら9体で足りる。ゲームの方式は 4 種類の斜線向きしか選べず、面積を変える手段を持たない。

### 未解明

- 枠が64ある以上「家具64個までカーソルを出す」入れ物だが、`0x00B19FFC` の呼び出し元が
  見つからない（V2-F019 §5.5 のまま）ので、**1つの家具に複数枠を割り当てているかは不明**。
  ただし更新は枠ごとに**同じ家具の位置**を読むので、複数枠を同じ家具に割り当てても重なるだけ。
- モデルの1枚が世界座標で何単位か（＝1マスの実寸）。CMDL ヘッダには寸法が無く、頂点データにある。
  **実機で並べて較正するのが速い**（次の作業で行う）。
