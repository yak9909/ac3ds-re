## IDA-opus-5.5-HHD-F014: 模様替え画面の状態とゴミ箱への落とし（2026-10-06、MEDIUM: 静的のみ。途中）

- 模様替え画面（家具を置く画面）の本体は 0x3EA990〜0x3F2xxx のクラス。vtable は 0x6EF998〜0x6EFAB4（手前 2 語 0,0。直後に offset-to-top −8 の第 2 vtable）。
  状態機械は this+4712（`StateMachine_GetCurrentState` / `StateMachine_ChangeState` 0x441534）。状態は `sub_5A5E90` が静的に作る 12 個:
  Idle_, In_, Wait_, PutError_, Remake_, **TrashBox_（0x793B10）**, Dress_, NfcError_, Nfc_, SwitchDialog_, End_, Out_（`sub_613EB8(状態, 基底, 名前, PMF x4)`。PMF は (vtable の位置, 1)。
  Idle_ = 120..132 … Out_ = 296..308）。
  **訂正（同日）: vtable の先頭は 0x6EF980**（コードのリテラル 0x3F2BC8 / 0x3F305C が指す。先頭近くの 0 の欄は 0 のままの仮想関数で、offset-to-top ではなかった）。この先頭で 12 状態 x 4 欄がすべて関数を指す（work/evidence/hhd_decorate/main_screen_states.json）。
  Wait_ = [0x3F0710, **0x3EE01C（毎フレームの入力・ドラッグ）**, 0x3F05D8, 0x3F08CC]。TrashBox_ = [**0x3F0968**, 空, 空, 0 を返す]: 0x3F0968 は `sub_49CBEC(1)` なら `sub_49C8DC(1,0)`（進行の記録）→ `sub_3F2814(this, 0)` = 画面の部品の入力の旗（部品 +236）をまとめて落とすだけ。家具を消す処理は別（ゴミ箱の部品クラスかドラッグ側。未読）。
  同じ静的初期化で 0.7854（π/4）・28・部品名 N_Drug_00 / N_SoundW_00 / N_Sound_00 を置く。
- 状態の並びを積む `sub_3EBE28`、TrashBox_ か調べる `sub_3ED0F8`。
- ゴミ箱へ入る条件（`sub_3EE01C` 0x3EF3A8〜0x3EF414）: 落とし先の部品 [this + 4*[R8+0x1E0] + 0xE54] が「重なっている」（`sub_56AC8C`: 部品+270 が立ち +412 が 0）かつ `sub_49CBEC(1)`（進行の条件。チュートリアル等でゴミ箱を使えない場面を除く）→ 落とし先の部品の +0x48 のレイアウトで "open" を再生 → `TrashBox_` へ。
- ゴミ箱の部品: レイアウトの部品 `L_Trash_00` を見つけると 392 B のクラス（ctor `sub_3DE0D4`、vtable 0x6EE5D0 / +8 0x6EE6BC、+352 に状態機械 0x6FAB08）を作る（部品の作り分け `sub_354F44`。`L_Drag_%02d` は 452 B のクラス `sub_37C650`）。
- 未読: ゴミ箱のクラスの状態（重なり・開閉・捨てる）、TrashBox_ 状態の処理、"open" の持ち主のレイアウト。
