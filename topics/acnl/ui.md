# ACNL / UI

## 今わかっていること

日本版の対象記録（build: `acnl_jpn_v15`）を話題別に整理した。実行時の番地・リスト ID・観測回数は、その記録の標本に限る。確度と記録の格付けは別であり、格付け C・? の記録だけに依存する結論には「要確認」を付けた。静的解析だけで HIGH とされた記録は、ここでは MEDIUM 以下として扱う。訂正前の説は「矛盾」の比較用に限り残し、訂正後の内容を採用する。`superseded` の記録は使用していない。

### 会話本文・ルビと会話枠

- 確度: MEDIUM／要確認。`script::TalkSeq` は二つの `TalkRuby` を持ち、文字送りから制御コードを処理する。文字送り呼出しを飛ばすと完了扱いになり、漢字とルビを生成する処理も飛ぶ。一括表示フラグを使う経路では文字ストリーム自体は処理される。根拠: [ACNL-F0087]（静的のみ）。
- 確度: HIGH／要確認。会話本文枠は背景・四辺の計六つの Picture と本文 TextBox で構成される。元の相対配置を保った非所有コピーは別位置でも整列して描画された。話者名の背景・文字は別部品で、この試験には含まれない。根拠: [ACNL-F0035] [ACNL-F0036]。

### メニュー要求・日付変更画面

- 確度: MEDIUM／要確認。`Menu_RequestOpen` はアイドル状態で要求を積み、`Menu_PollOpen` が MenuID を画面 ID に変換し、画面ファクトリを呼ぶ。要求受付と画面生成成功は異なる。MenuID `0x2E` は `BsMenuSetupTime`（画面 ID 557）で、`0x2F`〜`0x31` も同じ画面を使う。根拠: [ACNL-F0095]、生成成功判定は [ACNL-F0117]。
- 確度: HIGH／要確認。屋外で通常の X 入力が通った要求呼出しは `sub_6D62AC` 内の `0x6D6338`。MenuID は状態から表引きされ、観測値は `(0, 1)` だった。この時点では持ち物 UI の準備が既に進んでいる。根拠: [ACNL-F0109]。
- 矛盾（訂正済み）: [ACNL-F0095] の「日付変更画面を開く経路が外部コード側に無い」という旧説明に対し、訂正先 [ACNL-F0096] は、埋める動作が要求する MenuID `0x4A` を `0x2E` に替えるとゲーム本来の同画面に至る経路を示す。採用するのは画面と MenuID の対応であり、外部製品の実装は対象外。確度: MEDIUM／要確認。

### 持ち物とカタログの開始・終了の契約

- 確度: MEDIUM／要確認。持ち物 `BsMenuItem` は開始時に `MENU_FLAGS` の `0x08`、入場完了時に `0x10` を立て、終了時に消す。`BsMenuCatalog` はこの set/clear を実装せず、終了要求 `0x20` を読む。カタログが隠すのは手カーソルで、タブを隠す命令は出さない。根拠: [ACNL-F0118]。
- 矛盾（訂正済み）: [ACNL-F0116] はカタログも生成後に `0x08` を立てるとの前提で待機し、[ACNL-F0117] は生成関数の非ゼロ戻りを同期点とした。しかし [ACNL-F0118] は共通の handshake という前提を否定する。生成成功の判定と、持ち物用タブ・プレイヤー状態が復帰することは同一ではない。確度: MEDIUM／要確認。

### アニメの最終フレームと HHD との違い

- 確度: HIGH。ACNL の非ループ `UiAnim_Step` は `frameSize − 1` で止まり、終了判定も同じ境界を使う。ループ時の巻戻し境界は `frameSize`。非ループ資源の最終キーは ACNL では `frameSize − 1`、HHD では `frameSize` に置く例が多数であり、数値をそのまま移すと最終キーに届かない。HHD の実行コードの終端判定まで確定した話ではない。根拠: [ACNL-F0628]、一覧の最終フレーム適用は [ACNL-F0492]。

- 確度: HIGH／要確認。Layout は記録要求 `+0x11D` が立つ場合だけ Pane 木を記録し、記録後に旗を落とす。静的な Layout は既存の記録を再生し続ける。`0x568770` は木の記録後・記録長確定前に当たるが、要求がなければ通らない。根拠: [ACNL-F0228] [ACNL-F0229]。
- 確度: HIGH／要確認。通常の観測では自然に記録し直す Layout と、再生だけする Layout が混在した。何も再生されないフレームや Layout の解放・再確保もあり、過去のポインタやリスト ID だけでは現在の表示物を特定できない。ID 0 の Layout も実在し、外部の未設定値と同一視できない。根拠: [ACNL-F0249] [ACNL-F0251] [ACNL-F0256] [ACNL-F0261]。
- 確度: MEDIUM／要確認。記録 manager の base・capacity・offset と現在の書込 cursor は別の値で、記録途中の offset は未確定の場合がある。未知 ID の選択は manager header を作るだけで描画バッファ本体は割り当てない。バッファ置換の実験はゼロ長経路までで、非ゼロのコピーと再生の成立は未確認。根拠: [ACNL-F0264]。
- 確度: HIGH／要確認。記録リストと主リストには別々の容量・提出状態がある。記録リストへの大量追記で cursor が壊れた例があり、主リストへの直接追記が提出に畳み込まれる観測もある。容量・残量は標本依存であり、主リストも無制限ではない。根拠: [ACNL-F0257] [ACNL-F0259]、訂正先 [ACNL-F0276]、提出の確認 [ACNL-F0278]。

### TextBox と文字バッチ

- 確度: HIGH／要確認。TextBox は `DrawInfo+0x80` に作業体 `LayoutMgr+0x1C` を使う。UTF-16LE の文字列、ゲームのフォント、Material、バッチを与えた試験で日本語と上下の文字色を描けた。文字列容量欄 `+0xF8` は文字数ではなくバイト数で、`+0xFA` が実文字数。TextBox の Material は色を供給し、テクスチャはグリフ側から出る。根拠: [ACNL-F0326]。
- 確度: MEDIUM／要確認。dirty がなくバッチ構築済みなら再構築を省き、普通メモリ経路は既存コマンドをコピーする。最大文字数への予約容量、実送出量、CPU 時間は別であり、保持バイト数から速度の優劣は決められない。根拠: [ACNL-F0326] の静的追記。TextWriter 直呼びの新方式は未実証。

### Window の枠・メモリ上のアーカイブ

- 確度: MEDIUM。`nw::lyt::Window` は枠数 1 でも枠材質を四隅へ反転して使い、中身も描く。ACNL 自身にも一枠の資源があるが、その実機表示は未観測。根拠: [ACNL-F0588]。

### HHD のペイン基準投影と文字配置の対応

- 確度: MEDIUM。HHD の一部資源の pane based projection は、ペイン中心基準で `u = x / textureWidth + 0.5`、`v = −y / textureHeight + 0.5` を作ってから材質 SRT を掛ける規則で、水玉と小円の見た目に対応した。投影の拡大 1・平行移動 0 の対象に限り、HHD の座標生成コードは未読。文字の x/y alignment は基準点に対応するが、HHD の shadow enabled に相当する欄は ACNL TextBox には無いと記録される。根拠: [ACNL-F0594]。

### 3D オブジェクトの画面固定とアニメ適用

- 確度: HIGH／要確認。専用 view/projection で描いた 3D オブジェクトは、上画面の屋外試験でゲームのカメラ移動中も画面位置を保ち、位置・倍率・不透明度を変えられた。場面切替、他材質、下画面、左右目別の結果は未確認。根拠: [ACNL-F0551]（by: gpt-6）。

- 確度: HIGH／要確認。観測した影は ETC1、LINEAR フィルタ、MIRRORED_REPEAT で、カテゴリによってテクスチャと寸法が異なる。データ変更による縞模様と、L4 へ切り替えた市松模様の表示が観測された。これは影の描画経路の結果であり、2D UI の投影・寿命の保証には使わない。根拠: [ACNL-F0161] [ACNL-F0162]。
