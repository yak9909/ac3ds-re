# ACNL / UI

## 今わかっていること

日本版の対象記録（build: `acnl_jpn_v15`）を話題別に整理した。実行時の番地・リスト ID・観測回数は、その記録の標本に限る。確度と記録の格付けは別であり、格付け C・? の記録だけに依存する結論には「要確認」を付けた。静的解析だけで HIGH とされた記録は、ここでは MEDIUM 以下として扱う。訂正前の説は「矛盾」の比較用に限り残し、訂正後の内容を採用する。`superseded` の記録は使用していない。

### 会話本文・ルビと会話枠

- 確度: MEDIUM／要確認。`script::TalkSeq` は二つの `TalkRuby` を持ち、文字送りから制御コードを処理する。文字送り呼出しを飛ばすと完了扱いになり、漢字とルビを生成する処理も飛ぶ。一括表示フラグを使う経路では文字ストリーム自体は処理される。根拠: [ACNL-F0087]（静的のみ）。
- 確度: HIGH／要確認。会話本文枠は背景・四辺の計六つの Picture と本文 TextBox で構成される。元の相対配置を保った非所有コピーは別位置でも整列して描画された。話者名の背景・文字は別部品で、この試験には含まれない。根拠: [ACNL-F0035] [ACNL-F0036]。

### メニュー要求・日付変更画面

- 確度: MEDIUM／要確認。`Menu_RequestOpen` はアイドル状態で要求を積み、`Menu_PollOpen` が MenuID を画面 ID に変換し、画面ファクトリを呼ぶ。要求受付と画面生成成功は異なる。MenuID `0x2E` は `BsMenuSetupTime`（画面 ID 557）で、`0x2F`〜`0x31` も同じ画面を使う。根拠: [ACNL-F0095]、生成成功判定は [ACNL-F0117]。
- 確度: HIGH／要確認。屋外で通常の X 入力が通った要求呼出しは `sub_6D62AC` 内の `0x6D6338`。MenuID は状態から表引きされ、観測値は `(0, 1)` だった。この時点では持ち物 UI の準備が既に進んでいる。根拠: [ACNL-F0109]。
- 矛盾（訂正済み）: [ACNL-F0095] の「FOXXY に日付変更画面を開く経路が無い」という旧説明に対し、訂正先 [ACNL-F0096] は、埋める動作が要求する MenuID `0x4A` を `0x2E` に替えるとゲーム本来の同画面に至る経路を示す。旧説明と訂正の対象は FOXXY に限り、Vapecord の経路は [ACNL-F0095] に明記されている。採用するのは画面と MenuID の対応であり、外部製品の実装は対象外。確度: MEDIUM／要確認。

### 持ち物とカタログの開始・終了の契約

- 確度: MEDIUM／要確認。持ち物 `BsMenuItem` は開始時に `MENU_FLAGS` の `0x08`、入場完了時に `0x10` を立て、終了時に消す。`BsMenuCatalog` はこの set/clear を実装せず、終了要求 `0x20` を読む。カタログが隠すのは手カーソルで、タブを隠す命令は出さない。根拠: [ACNL-F0118]。
- 矛盾（訂正済み）: [ACNL-F0116] はカタログも生成後に `0x08` を立てるとの前提で待機し、[ACNL-F0117] は生成関数の非ゼロ戻りを同期点とした。しかし [ACNL-F0118] は共通の handshake という前提を否定する。生成成功の判定と、持ち物用タブ・プレイヤー状態が復帰することは同一ではない。確度: MEDIUM／要確認。

### 家具プレビュー管理と子画面の生成

- 確度: MEDIUM／要確認。`BsFtrMgr` は資源生成段で大域変数へ公開されるが、共通資源の非同期待ちと部屋家具の初期化はその後。生成完了の条件は object `+19` の下位二ビットが両方立つこと。通常の屋外ではこの管理体を生成しない。根拠: [ACNL-F0121]。

- 確度: HIGH。カタログの入退場は `BsMenuBg` の種類変更と画面自身の in/out アニメを使う。下画面の背景変更は二つの背景ペインの不透明度を上げるクロスフェードで、change アニメは 5 フレーム。背景にはテクスチャ SRT の loop もある。Fade/Wipe/Fader の開始処理は、カタログを開いた実機観測では発火しなかった。根拠: [ACNL-F0593]。

### アニメの最終フレームと HHD との違い

- 確度: HIGH。ACNL の非ループ `UiAnim_Step` は `frameSize − 1` で止まり、終了判定も同じ境界を使う。ループ時の巻戻し境界は `frameSize`。非ループ資源の最終キーは ACNL では `frameSize − 1`、HHD では `frameSize` に置く例が多数であり、数値をそのまま移すと最終キーに届かない。HHD の実行コードの終端判定まで確定した話ではない。根拠: [ACNL-F0628]、一覧の最終フレーム適用は [ACNL-F0492]。

### 時計・日付・ベルの箱

### Layout の記録・再生・容量

- 確度: MEDIUM。基底 Layout は記録要求 `+0x11D != 0` のときだけ専用リストをクリアして Pane 木を再記録し、`+0x104..+0x110` に範囲を保存して要求を落とす。要求がゼロでも保存長 `+0x108 > 0` なら既存範囲を再生する。要求の生産例は通常の計算処理 `0x568030` にあり、可視変化を比較した場合だけ立つとは限らない。`0x568770` は木の記録後だが Drawer end・Commit前で、ここでの書込長は最終保存長ではない。投影更新は要求検査より前。根拠: [ACNL-F0699]。
- 確度: MEDIUM。Layout の寿命、ID、manager、記録領域は別。ctor はID欄を0にし、BuildがIDと領域を作り、破棄は非ゼロIDと内部資源を解放する。削除IDは生成候補へ戻るため再利用可能で、過去のID・ポインタだけでは現在の表示物を同定できない。パス末尾のリンク解除は破棄とは異なる。根拠: [ACNL-F0700]。
- 確度: MEDIUM。ID欄0のLayoutは初期状態として存在する。ID生成は0を飛ばさず、選択は既存ID0も検索するが、未知の0にはheaderを生成せず、削除は0を無視する。旧F0256の表示中のID0・衝突・クラッシュの因果は未確認であり、「0は一律有効/無効」としない。根拠: [ACNL-F0700]。
- 確度: MEDIUM。記録managerの `+4=base`、`+8=バイト容量`、`+0x0C=保存offset` と global cursor/end は別。切替時は旧offsetを保存し、新cursorをbase+offset、endをbase+capacityから復元する。保存offsetは記録途中だけでなくCommitのpadding直後もlive位置と異なり得る。正しく整合した瞬間の既書込長はcursor−base。未知の非ゼロIDの選択はheaderだけを作り、バッファ本体はstorage処理が別途確保する。根拠: [ACNL-F0701]。
- 確度: MEDIUM。記録リストと主リストはそれぞれ有限のコマンド領域とGXエントリ容量を持つ。Layoutの記録容量はBuildの第4引数、GX容量は1。主リストも同じstorage処理を使い、確認した初期化では2本それぞれコマンド容量 `0x96000`・GX容量10。残量は実行時状態に依存する。書込時に終端を検査しない経路もあり、安全な枚数を一般化できない。旧F0257の停止時レジスタ標本はMem_Copy内の更新を含めると命令列と整合するが、「容量超過でcursorがゼロになった」という因果は未証明。旧実験の安全量・長時間安定・バッファ置換の表示成立も未確認。根拠: [ACNL-F0701]。
- 確度: MEDIUM。主リスト再生は現在位置と提出済み位置の差を条件に応じて分割提出または結合し、未提出で残す経路もある。第7引数が非ゼロで記録エントリ数がゼロなら両方を省略する。分割エントリはbase+提出済み位置と現在位置−提出済み位置を使い、現在位置には終端コマンド分も含む。直接追記の提出・表示を無条件には保証しない。根拠: [ACNL-F0695]。
- 未確認: 再記録する個体と再生だけの個体の実行時混在、何も記録範囲を再生しないフレーム、同一番地への再確保、実際のID0所有者、容量超過と旧クラッシュの因果、非ゼロ記録のバッファ置換。旧実機の回数・ポインタ・ID固有の順序を今回の再実測根拠には使わない。主張ごとの判定は [ACNL-F0699] [ACNL-F0700] [ACNL-F0701]。
