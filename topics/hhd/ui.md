# HHD / UI

## 今わかっていること

日本版 v1.1（`hhd_jpn_v11`）の画面・部品・仕組みを整理した。対象の ui 記録はすべて格付け S、`state: active`。静的のみの結論は MEDIUM とし、他作品上での再現の成功を HHD 実機での確認には数えない。`superseded` の記録は使用していない。

### キャラクター作成画面の構成と更新順

- 確度: MEDIUM。画面は三つのアーカイブと五つの専用レイアウトから構成される。汎用の `LayoutObj_BaseCtor` を基底に持ち、部品名だけが入った箇所にはコードが目・髪等の部品を割り当てる。根拠: [HHD-F0008] [HHD-F0009]。
- 確度: MEDIUM。毎フレームは切替、目の色、髪の色、肌の色、目、髪・ページ・決定の順で処理する。外見データは髪型・肌・髪色・目形・目色の順。選択グループは色三組と目・髪の一覧に分かれる。根拠: [HHD-F0005] [HHD-F0008]。
- 未確認: 目の形の取得関数の上限は 13 と読めるが、資源と画像の一覧は 12 個。両者が同じ個数を表すかは不明で、十三番目の選択肢があるとは結論しない。シーン `+8` の意味と決定後の状態も未確定。根拠: [HHD-F0005] [HHD-F0009]。

### 目・髪・肌の色とアイコン

- 確度: HIGH（個数・配置と資源の対応）、MEDIUM（実行時の反映経路）。色番号は色アニメのフレームに対応し、目色 6・肌色 8・髪色 16 の資源がある。コードの色設定もアニメ枠のフレームを色番号へ変える。目は男女別のテクスチャ表を使い、髪は 32 個で前半・後半が男女の組に分かれる。根拠: [HHD-F0008] [HHD-F0009]、髪の配置は [HHD-F0006]。

### 髪のページ構成

- 確度: MEDIUM。髪は一ページ八個を三つのページ枠へ回して貼り、性別で 16 個へ絞る状態を持つ。髪色・肌色はページ内へ一括反映する。三つの表示枠と髪の総ページ数は区別する。根拠: [HHD-F0006]。
- 確度: MEDIUM。髪一覧は `PageSlider` とドラッグ当たり用 `DragArea` を使い、ページの回り込みを切る。[HHD-F0006] [HHD-F0008] に残ったページ入力の未確定点は、[HHD-F0002] が L/R とドラッグの経路を具体化している。

### ページのドラッグ・弾き・滑り

- 確度: MEDIUM。入力は中心原点の画素座標と正規化座標を持つ。横移動累計が正規化 0.05（記録の換算で 8 画素）以上でドラッグに入り、ページは指の横移動量と同じだけ動く。回り込み無しでは端で止まり、伸びて戻る動きはない。根拠: [HHD-F0002]。
- 確度: MEDIUM。速度を平滑化し、離した時の速度を上限 25 に抑える。速度 8 以上で弾き量を加え、移動目標を一ページ以内に丸めて範囲内へ収める。L/R は待機中だけ一ページの移動を要求する。滑りは残距離に比例した刻みを速度で制限し、終端へ近づくと最小刻みを使って止まる。HHD 実機での体感・操作音は未確認。根拠: [HHD-F0002]。

### 共通ボタンの状態機械

- 確度: MEDIUM。`ButtonBaseActor` の実名を含む状態名が残り、静的初期化が 17 状態を登録する。タッチ決定処理とアニメ名表が対応する。キャラ作成だけでなく、カタログのタブ・小分類等も同じボタン機構を使う。実機での全状態遷移は未観測。根拠: [HHD-F0007] [HHD-F0013]。

### 繰り返しアニメと背景

- 確度: MEDIUM。汎用のレイアウト組み立て経路は、`G_Loop` グループと `loop` アニメが両方あると結合して再生する。キャラ作成の背景では水玉の材質 SRT が流れ、上画面では吹き出しと小円の拡大率も変わる。HHD 実機の動的確認は未実施で、他作品上の再現結果と区別する。根拠: [HHD-F0011]。

### 家具・壁紙・床のカタログ

- 確度: MEDIUM。カタログはモード別の地、三ページ分の一ページ 15 個の格子、条件付きの一覧の地、名前の吹き出しから段階的に組み立てる。家具は緑の `ctl_Base_01`、壁紙・床等はピンクの `ctl_Base_04` を使う。上段タブ、小分類、戻るボタンは選択グループへ登録される。根拠: [HHD-F0013]。
- 確度: HIGH。家具リストの地ではタブ・小分類・戻る等が参照する子部品のレイアウト名と配置を資源から特定し、画像と照合している。部品ペインの参照名は展開 JSON に落ちる場合があり、生の資源を読んだ結果が根拠である。根拠: [HHD-F0018]。

### 模様替え画面の上段タブ

- 確度: HIGH。画面上段のタブは `MainTop.arc` の `mit_RoomTop_00`。左からドア、家具、壁紙、床、マイデザイン、検索の部品位置があり、観測画像ではマイデザインは出ていない。家具は緑の葉、壁紙は黄、床は青で、家具に焦点がある画像では地が橙になる。根拠: [HHD-F0018]。
- 注意: [HHD-F0013] のカタログ内部の上段タブと、[HHD-F0018] の模様替え画面全体の上段タブは別レイアウトであり、同じ部品列とは扱わない。

### 模様替え画面の状態とゴミ箱

- 確度: MEDIUM。画面本体は `this+4712` に状態機械を持ち、Wait、TrashBox 等の 12 状態を使う。Wait の更新で入力・ドラッグを処理し、落とし先との重なりと進行条件が成立すると open アニメを再生して TrashBox へ移る。TrashBox の開始処理は入力の旗を落とすが、それだけで家具の削除本体とは断定できない。根拠: [HHD-F0014]。
- 矛盾（同一記録内で訂正済み）: [HHD-F0014] の冒頭は本体 vtable を `0x6EF998` 起点としたが、後半ではコードのリテラルと全状態の関数対応から `0x6EF980` 起点へ訂正した。採用するのは後者。確度: MEDIUM。
- 確度: MEDIUM。ゴミ箱部品は落とし先が Select 状態かを見て OnTarget へ進む。落とし先は Wait/Select/UnSelect を持ち、タッチ中は指の点、それ以外は投影した点で矩形内を判定する。当たりペインは `B_Base_00`、資源上の大きさは 47×53。家具削除の最終処理、開閉状態の全体、進行制限の詳細は未読部分が残る。根拠: [HHD-F0017]、遷移条件との対応は [HHD-F0014]。

### 要確認の結論と再解析候補

格付け C・? のみで支えられた結論は、この対象には無い。未確定点は上記各話題に残した。再解析の候補は、目形の上限と実選択肢の対応、ゴミ箱の家具削除・開閉全体、HHD 実機でのページ送りと loop の確認。優先度の案はワーカー報告にまとめる。
