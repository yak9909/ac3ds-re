## 結論と根拠の要約

- 索引は address / build / key / file / line の TSV。本文・書き込み値・チート名・ID 表は保存しない。Gateway は通常書き込みの 0/1/2 型から番地を取り、制御コードと E 型の後続データを除外する。CTRPF・TEXTS と CHEATS の C++ メモは 0x 表記を候補として抽出する。
- ビルドは台帳の任意の build またはパス中の既知ビルドキーで特定し、その他は unknown（表示は「不明」）。addr は対象ビルドと不明の資料のみを「参考資料（LOW、一次証拠ではない）」として表示する。索引なしでも動作する。
- 対象試験は tools/tests/test_refindex.py と tools/tests/test_kb.py の合計34件通過。通常書き込み・制御コード・データ列・0x 表記・行番号・BOM/CP932・バイナリと IDS の除外・ビルド別表示・索引なしを確認。追加試験は0x表記の上下境界、Gateway の幅指定除去後の下限、表示20件・21件・25件、上限の変更・0指定・負数拒否を含む。実資料では既存の記録と参考資料の併記も確認した。
- 実資料の試し生成先: A:/Disassemble/ac3ds-workspace/_local/evidence/94/refindex/addresses.tsv。修正後は9,002件（CHEATS 1,373件、CTRPF_PROJECTS 7,620件、TEXTS 9件）。_local/refs/ には書き込んでいない。
- 追加修正: 抽出する全ての番地を `0x00100000 <= address < 0x40000000` に制限した。Gateway も幅指定を除去してから同じ条件で絞る。参考資料は既定20件まで表示し、残りを「ほか N 件」とする。`--ref-limit` で変更できる（0以上）。
